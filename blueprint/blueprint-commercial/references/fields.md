# 商业段字段清单

本文件为 `blueprint-commercial` 段提供本段的待闭环字段、闭环判据、追问句式、空洞回答的追加问法、必核字段、上游锚点与档位子集。候选生成规则、处置分类、来源等级、发散手法与单轮输出格式以 [co-create.md](references/co-create.md)为唯一来源，本文件**严禁**复述。

本段字段总数为 8，`scope=screen` 时为 6，单轮输出的完整度分母**必须**按当前 `scope` 取对应数，**严禁**另取。

---

## 一、本段字段清单

| 字段 | 要拿到的东西 | 闭环判据 | 追问句式 |
|------|------------|---------|---------|
| `COM1` | 价值主张 | 取值型：一句「谁付出什么、换回什么」 | 用户为了得到什么，愿意付出钱、时间还是注意力？付出的那一份具体是多少？ |
| `COM2` | 目标客群与使用场景 | 取值型：一个可点名的人群 + 一个具体场景 | 第一批会用的是哪一类人？他们是在什么场景下打开它的？ |
| `COM3` | 收入模式与定价 | 枚举型：选定的计费方式 + 计数型单价 | 钱从哪来：一次性买断、订阅、内购、广告、接单还是不收钱？单价打算定多少？ |
| `COM4` | 成本结构与单位经济性 | 计数型：单个用户或单次交付的收入减成本 | 服务一个用户你要花掉多少（服务器、素材、人工、渠道分成）？减完之后剩多少？ |
| `COM5` | 竞争与替代 | 取值型：用户当前的替代做法 + 切换成本 | 没有你这个东西之前，他们靠什么解决？换到你这边要放弃什么？ |
| `COM6` | 留存与复购周期 | 计数型：一个用户会付几次、隔多久付一次 | 一个用户平均会付几次钱？多久之后就不再回来了？ |
| `COM7` | 机会成本基准 | 计数型：同样工时投在次优选择上的月收益 | 这些时间如果投在你眼下第二想做的事上，一个月能挣多少？ |
| `COM8` | 时机证据 | 取值型：近 24 个月内发生的一个可取证变化 | 这件事为什么是现在才成立？两年前做不了、现在能做了，变的是哪一件事？ |

- 本表为**封闭清单**，**必须**逐字取用，**严禁**在本段追问本表之外的字段编号
- `COM4` 的取值**必须**写成「单用户收入 − 单用户可变成本 = 结果」三段形态，**严禁**只写成本总额
- `COM4` 的结果为负时**必须**当场把结果与两个输入摆给用户，**严禁**只写入分册而不告知
- `COM3`、`COM4`、`COM6`、`COM7` 的取值**必须**带单位写入字段台账，**严禁**只写在分册正文 —— 裁决段的算式读的是台账

## 二、空洞回答与追加问法

| 空洞回答 | 追加问法 |
|---------|---------|
| 「先做用户量，以后再想变现」 | 到多少用户量才开始变现？这个量级下你打算收谁的钱、收多少？ |
| 「成本很低，几乎没有成本」 | 把服务器、素材、平台分成、你自己的时间按小时折算，加起来一个月多少？ |
| 「市场上还没有人做」 | 用户现在是怎么凑合解决的？完全没人做与完全没人要，怎么区分？ |
| 「定价看竞品定就行」 | 竞品哪几家、各自公示价多少？你比他们多给了什么，凭这一点你定高还是定低？ |
| 「用户肯定会一直用下去」 | 一个用户用到第几周会停？停之前他付过几次钱？ |

- 用户的回答命中本表任一行时**必须**发出对应的追加问法，**严禁**把空洞回答记为【已确认】

## 三、本段必核字段

下列字段**必须**联网取证，**严禁**以模型记忆中的数据代替。

| 字段 | 要核的事实 | 检索方向 |
|------|----------|---------|
| `COM3` | 同类产品的公开定价区间 | 同类产品官网定价页 |
| `COM4` | 所用服务的公开价目 | 服务商定价页 |
| `COM5` | 是否已有在做同类产品的团队，以及是否有已停运的同类及其公开死因 | 品类名 + 关键功能词检索；品类名 + 停运、关停、复盘 |
| `COM8` | 使这件事现在才成立的那个变化是否真的发生过 | 该变化的官方公告、政策文件或平台更新日志 |

- 取证记录的形态与取不到时的处置以 [co-create.md 第六节](references/co-create.md#六取证记录与取不到时的处置)为唯一来源
- `COM5` 取到已停运的同类时**必须**把其公开死因逐条写入分册，**严禁**只记「存在同类」

## 四、上游锚点与档位子集

追问本段字段之前**必须**先读字段台账的下列上游取值，**严禁**在未读台账时开始追问。

| 台账字段 | 本段用它做什么 |
|---------|-------------|
| `RQ4` | 成功判据不含收入项时把 `COM7` 标为【不适用】并附理由 |
| `RQ5` | 逐条比对本段取值有无与硬约束直接冲突 |
| `PRD1` | `COM1` 的价值主张由核心体验那句话改写而来 |
| `PRD5` | `COM3` 的计费规则、`COM4` 的成本项取自规则与数值 |
| `PRD4` | `COM4` 的单次交付成本引用内容工时合计 |
| `PRD6` | `COM2` 的目标客群落在角色清单中的某一角色上 |
| `PRD7` | `COM6` 的留存周期读状态或阶段序列中的某一节点 |
| `PRD10` | `COM6` 的复购周期与内容可支撑时长比对 |

- 字段台账不存在时**必须**先新建台账、追问 `RQ2` 与 `RQ4` 两项并写入，**严禁**在成功判据未确定时开始本段追问
- 台账缺 `PRD` 分区时**必须**把本表所列上游 `PRD` 字段全部标为【缺口】，并在分册首行下方写出「本册未经产品方案锚定」一行，**严禁**凭模型代填的产品方案往下算
- 上游取值标为【缺口】时其下游字段的取值**必须**同步标注依赖该缺口，**严禁**当作已确认事实入算
- 用户在本段改写了上游 `PRD` 字段取值时**必须**把该改写回读并交回编排段，**严禁**在本段就地改写产品分册

`scope=screen` 时本段字段子集固定为下列六项，**必须**逐字取用，**严禁**增删条目。

| 字段 | 本档为什么要它 |
|------|-------------|
| `COM1` | 价值主张不成立时后面的定价无对象 |
| `COM3` | 收入模式是本档全部收入类算式的输入 |
| `COM4` | 单位经济性是本档最主要的判死依据 |
| `COM5` | 同类已存在且无差异化时本档即可判死 |
| `COM6` | 留存周期决定单用户收入能重复几次 |
| `COM7` | 机会成本基准是本档「值不值得做」的对照 |

- 子集外的字段在本档**必须**记为【不适用】并附「本档不问」一句，**严禁**标为【缺口】
- 本档**必须**照常执行第三节的取证要求，**严禁**以「只是快筛」为由跳过
