# 推广段字段清单

本文件为 `blueprint-growth` 段提供本段的待闭环字段、闭环判据、追问句式、空洞回答的追加问法、必核字段、上游锚点与档位处置。候选生成规则、处置分类、来源等级、发散手法与单轮输出格式以 [co-create.md](references/co-create.md)为唯一来源，本文件**严禁**复述。

本段字段总数为 5，单轮输出的完整度分母**必须**取该数，**严禁**另取。

本段管的是「把东西送到人面前」—— 渠道、种子用户、增长回路、获客成本、分发合作。客观判据：某字段的产出物是一个可以被计数的触达位置或触达机制时归本段；是一句可以被读出来的话时归营销段，**严禁**在本段追问定位、痛点语言、卖点与素材主线。

---

## 一、本段字段清单

| 字段 | 要拿到的东西 | 闭环判据 | 追问句式 |
|------|------------|---------|---------|
| `GRW1` | 冷启动渠道与种子用户来源 | 取值型：第一批用户的具体来处 | 头一百个用户从哪来？这个来处你现在就能触达吗？ |
| `GRW2` | 渠道清单与优先级 | 枚举型：候选渠道排序 + 每个渠道的进入门槛 | 可用的渠道有哪些？各自要交什么门票（审核、费用、内容量、资质）？ |
| `GRW3` | 增长回路 | 取值型：一句「一个用户如何带来下一个」的机制描述 | 用户用完之后，什么动作会自然把新用户带进来？这个动作对他有什么好处？ |
| `GRW4` | 获客成本与预算上限 | 计数型：单用户获客成本 + 总预算 | 你能接受为一个用户花多少钱？总共能投多少？ |
| `GRW5` | 合作与分发 | 枚举型：候选合作方 + 各自的利益点 | 谁手上已经有你要的人？跟他合作，他能拿到什么？ |

- 本表为**封闭清单**，**必须**逐字取用，**严禁**在本段追问本表之外的字段编号
- `GRW2` 的每个渠道**必须**各写出进入门槛，**严禁**只列渠道名
- `GRW4` 的单用户获客成本与总预算**必须**各自带单位写入字段台账，**严禁**合并成一个数 —— 裁决段的可达用户量算式要分别读它们
- 用户答「没预算，全靠免费流量」时 `GRW4` **必须**按其可投工时折算出时间成本，**严禁**记为零

## 二、空洞回答与追加问法

| 空洞回答 | 追加问法 |
|---------|---------|
| 「发到各大平台」 | 挑一个先做。挑它的理由是那里的人更对，还是你在那里已经有账号和内容？ |
| 「靠口碑传播」 | 触发口碑的那个动作是什么？现在产品里有没有让用户能一键分享的位置？ |
| 「没预算，全靠免费流量」 | 那投入的是你的时间。一周能投多少小时？按你的时薪折算，一个用户的成本是多少？ |
| 「先攒一批种子用户」 | 这一批人现在在哪个具体的群、榜、社区里？你现在能不能直接给他们发消息？ |
| 「找博主合作推一下」 | 找哪一类博主、量级多少？他为什么要接这一单，你能给他什么？ |

- 用户的回答命中本表任一行时**必须**发出对应的追加问法，**严禁**把空洞回答记为【已确认】

## 三、本段必核字段

下列字段**必须**联网取证，**严禁**以模型记忆中的数据代替。

| 字段 | 要核的事实 | 检索方向 |
|------|----------|---------|
| `GRW2` | 目标渠道的准入规则与门槛 | 平台官方规则文档 |
| `GRW4` | 渠道公开报价或该品类获客成本区间 | 渠道广告后台公示页、公开行研 |

- 取证记录的形态与取不到时的处置以 [co-create.md 第六节](references/co-create.md#六取证记录与取不到时的处置)为唯一来源
- 取证结果显示可用渠道只剩一条且其门槛不可满足时**必须**在分册中原样记录并交由裁决段判定，**严禁**在本段给出否决结论
- 用户给的获客成本与取到的 `E1` 或 `E2` 报价差异达到 2 倍时**必须**把两个数并列摆出请用户确认，**严禁**默默采用用户那一个

## 四、上游锚点与档位处置

追问本段字段之前**必须**先读字段台账的下列上游取值，**严禁**在未读台账时开始追问。

| 台账字段 | 本段用它做什么 |
|---------|-------------|
| `RQ5` | 逐条比对本段取值有无与硬约束直接冲突 |
| `RQ6` | `GRW1` 与 `GRW5` 优先落在用户已有的账号、人脉与素材上 |
| `PRD6` | `GRW1` 的种子用户落在角色清单中的某一角色上 |
| `COM2` | `GRW1` 与 `GRW2` 的触达对象以商业段目标客群为准 |
| `COM3` | `GRW4` 的可接受获客成本以单用户收入为上限参照 |
| `MKT4` | `GRW2` 的渠道选择与素材形态匹配 |

- 字段台账不存在时**必须**先新建台账、追问 `RQ2` 与 `RQ4` 两项并写入，**严禁**在产物类型未确定时开始本段追问
- 台账缺 `PRD` 分区时**必须**把本表所列上游 `PRD` 字段全部标为【缺口】，并在分册首行下方写出「本册未经产品方案锚定」一行，**严禁**凭模型代填的产品方案往下算
- 上游取值标为【缺口】时其下游字段的取值**必须**同步标注依赖该缺口，**严禁**当作已确认事实入算
- 用户在本段改写了上游字段取值时**必须**把该改写回读并交回编排段，**严禁**在本段就地改写上游分册

`scope=screen` 时本段**必须**不做任何追问，直接输出段交回信号并在未闭环行写「本档不调用本段」，**严禁**在本档追问本段任一字段。

- 本段字段不进入快筛档的任何算式，故本档**必须**跳过整段，**严禁**为凑完整度而在本档补问
- 本档跳过时**严禁**建立本段分册 —— 空分册会让索引的分册索引节把本段标为已交回
