# 营销方案段（Blueprint Marketing）

> [!IMPORTANT] 路径解析基准
> 文档内相对路径引用一律以本 skill 根目录（`SKILL.md` 所在目录）为基准解析。

本段是 blueprint 流水线的**营销段**，出手序为 4：把「人看到它之后凭什么想要」逼到能被读出来，产出营销分册与台账里的 `MKT` 分区。本段只管「说什么」，「在哪说、靠什么复制」归推广段 —— 两者混问的结果是用户只答渠道，定位与卖点整段丢失。本段**只**闭环字段与登记事实，否决判定与结论态一律交裁决段。提问轮次不设上限，也不向用户宣告。

## 适用与不适用

- ✅ **适用**：用户已有一个可点名的产物形态，且愿意逐轮回应提问 —— 定位打磨、痛点语言采集、卖点排序与取证、说服顺序设计。
- ❌ **不适用**：纯事实查询、单点执行任务、已有完整营销方案只要求评审 —— 直接回答，**严禁**启动本流程。
- 🚫 **不受理**：诉求的成立以违反法律法规、侵犯他人权益或规避平台风控为必要条件 —— 说明原因后停止，**严禁**输出方案（→ stderr + exitCode=2）。

## 参数

| 参数 | 必填 | 说明 |
|------|------|------|
| `demand` | 是 | 待展开的原始诉求（自然语言，可以只有一句话） |
| `slug` | 否 | 产物文件名片段，缺省 `idea`；由编排段生成并透传 |
| `outputDir` | 否 | 分册与字段台账的输出目录，缺省取当前工作目录 |
| `scope` | 否 | 档位，缺省 `full`；`screen` 时的整段处置见 [fields.md 第四节](references/fields.md#四上游锚点与档位处置) |

## 公共约束

> [强约束] 总纲：先替用户把可能性摊开，再逐字段逼到能被读出来。不替用户拍板，不拿臆测充事实，不以轮次收尾，不越过裁决段给结论。

| # | 约束 | 违反后处理 |
|---|------|-----------|
| IBM1 | 开始追问前**必须**完整读取 [fields.md](references/fields.md)，**严禁**凭 SKILL.md 摘要或记忆提问 | 停止本轮，先完整读取该文件 |
| IBM2 | 单轮需用户回答的问题数**必须**不超过 3 个，**严禁**单轮抛出 4 个及以上问题 | 超出的问题移入下一轮后重发本轮 |
| IBM3 | 每个问题**必须**按 [co-create.md 第二节](references/co-create.md#二单轮提问的候选生成规则)附模型先行给出的候选答案，**严禁**抛出无候选的开放式问题 | 补齐候选后重发本轮 |
| IBM4 | 每轮输出**必须**含至少 1 条用户未提过的发散点并标注 [co-create.md 8.1](references/co-create.md#81-手法表)的手法编号，**严禁**把本轮写成纯提问清单 | 补一条带编号的发散点后重发本轮 |
| IBM5 | 本段追问**必须**只覆盖 fields.md 第一节所载字段，**严禁**追问渠道、种子用户、获客成本与分发合作 | 撤回越界问题，本轮只保留本段字段 |
| IBM6 | 用户给出的每个数值**必须**问明来路并按 [co-create.md 第五节](references/co-create.md#五来源等级)标出来源等级，**严禁**把口述数值直接记为已确认事实 | 补问来路后改标来源等级 |
| IBM7 | [fields.md 第三节](references/fields.md#三本段必核字段)所列字段**必须**联网取证并记录出处与取证日期，**严禁**以模型记忆中的同类现状充当取证结果 | 停止该字段判定，先联网取证 |
| IBM8 | 未闭环的字段**必须**标为【缺口】并进入缺口清单，**严禁**用模型臆测值冒充用户已确认的事实 | 改标【缺口】并移入缺口清单 |
| IBM9 | 由模型代填的取值**必须**逐条标注【模型假设】，**严禁**与用户已确认事实混排 | 逐条补标来源标签 |
| IBM10 | 每轮的处置分类、取证与发散点**必须**按 [co-create.md 第十节](references/co-create.md#十分册与字段台账的就地更新)就地写入分册与字段台账，**严禁**把本轮结论只留在对话里 | 补写本轮更新后再抛下一轮 |
| IBM11 | 每轮输出**必须**给出本段完整度进度，**严禁**出现提问轮次的编号、上限或剩余次数 | 删除轮次表述，改回完整度进度 |
| IBM12 | 否决判定与结论态**必须**交由裁决段执行，**严禁**在本段输出否决结论或结论态 | 删除该结论，改为登记事实 |
| IBM13 | 本段取值与台账 `RQ5` 某条硬约束直接冲突时**必须**当场把冲突两端的取值摆给用户，**严禁**只写入分册而不告知 | 立即停止本轮，回读该冲突 |
| IBM14 | 台账缺产品分区时**必须**按 [fields.md 第四节](references/fields.md#四上游锚点与档位处置)把上游字段标为【缺口】并在分册声明未锚定，**严禁**凭模型代填的产品方案往下算 | 补标【缺口】并补写声明行 |
| IBM15 | `MKT3` 的每条卖点**必须**各配一条可验证证据与其来源等级，**严禁**写下无证据的卖点 | 补齐证据或把该卖点改标【缺口】 |

## 核心流程

> [强约束] STEP 3~6 任一交互步骤中，用户主动叫停，或用户明确拒绝继续回应提问 → stderr + exitCode=1；`scope=screen` 时**必须**按 [fields.md 第四节](references/fields.md#四上游锚点与档位处置)跳过整段并直接交回，**严禁**在本档执行 STEP 4 与 STEP 5。

### STEP 1：参数校验

按标准校验顺序校验：
- **必填**：`demand`（缺失时不得报错退出，必须先向用户提问「你想把哪件事的对外说法理清楚？」，拿到回答后再进入下一步）
- **格式**：`slug`（匹配 `^[a-z0-9一-鿿-]{1,30}$`）
- **枚举**：`scope`（`screen` / `full`）
- **创建**：`outputDir`

任一校验失败 → stderr + exitCode=2

### STEP 2：读取本段规范

用 Read 工具完整读取 `references/co-create.md`、`references/fields.md`、`references/output-spec.md`，读完再进入下一步（遵循 IBM1）。

### STEP 3：读取或建立字段台账

读取 `{outputDir}/blueprint-{slug}.fields.json`；文件不存在时按 [fields.md 第四节](references/fields.md#四上游锚点与档位处置)新建并追问该节所列还原字段后写入。按该节逐项读取上游锚点取值，缺产品分区时按该节标注并声明（遵循 IBM14）。`scope=screen` 时按该节直接交回。

### STEP 4：建立分册骨架

按 [output-spec.md 第一节](references/output-spec.md#一分册骨架)建立分册，未闭环的节写占位串，再单独一行回显分册绝对路径。

### STEP 5：逐字段发散、追问与取证

按 fields.md 第一节的字段次序轮转，输出逐字采用 [co-create.md 第九节](references/co-create.md#九单轮输出格式)的五行格式（遵循 IBM2、IBM3、IBM5、IBM11）：

- 本轮的待闭环字段与追问句式取 fields.md 第一节，用户回答命中第二节任一空洞回答时发出对应追加问法；发散点按 co-create 8.1 选手法、8.2 取首选手法，合规判据见 8.3（遵循 IBM4）
- 用户给出数值时按 co-create 第七节问明来路并标来源等级（遵循 IBM6），与既有取值冲突按 7.1 回读；fields.md 第三节的必核字段用 WebSearch 与 WebFetch 取证并按 co-create 第六节记录出处与日期（遵循 IBM7）；用户答「不知道」「你定」时按 co-create 第三节分类（遵循 IBM8、IBM9），单字段处置上限见第四节，**严禁**向用户宣告该上限
- `MKT3` 按 [output-spec.md 第二节](references/output-spec.md#二方案节模板)逐条写出卖点、证据与同类能否做到（遵循 IBM15），取证结果显示主打卖点已被同类具备时按 fields.md 第三节登记并交裁决段；本轮取值与 `RQ5` 硬约束直接冲突时当场回读（遵循 IBM13），否决判定一律留给裁决段（遵循 IBM12）；本轮分类给出后按 co-create 第十节更新分册与台账、写出 `文档：已更新 {节名列表}` 行，再抛下一轮（遵循 IBM10）
- 关键前提需用户之外的角色或系统才能确定、本次对话内无法闭环 → stderr + exitCode=3

### STEP 6：补齐台账与交回

全部字段完成判定后按 [output-spec.md 第四节](references/output-spec.md#四字段台账的写入范围)补齐台账，再输出段交回信号：`段交回`、`未闭环`、`分册` 三行。

## 输出规范

### 产物文件

| 文件 | 条件 | 路径 |
|------|------|------|
| 营销分册 | `scope=full` 时必产，STEP 4 建立并逐轮更新 | `{outputDir}/blueprint-{slug}-mkt.md` |
| 字段台账 | 必产，不存在时由本段建立并逐轮追加 | `{outputDir}/blueprint-{slug}.fields.json` |
| 对话内段交回信号 | 必产 | 直接输出到对话 |

> [强约束] `{slug}` 由编排段生成并透传，本段**必须**按 STEP 1 的格式校验逐字取用该参数值，**严禁**将 `demand` 原文拼入文件名，**严禁**在本段另行改写 `{slug}`。

```markdown
<!-- ✅ 正确：逐字取用透传的 slug -->
slug=做一个-roguelike-小游戏 → blueprint-做一个-roguelike-小游戏-mkt.md
<!-- ❌ 错误：把 demand 原文拼入，空格与全角括号进入文件名，产出跨平台不可用的路径 -->
blueprint-做一个 Roguelike 小游戏（手机端）-mkt.md
```

### 退出码

本技能在对话模式下运行，无进程退出码。每次结束（含中途终止）**必须**在输出末尾单独打印一行 `状态：{含义}（exitCode={N}）` 供上层判定。

| exitCode | 含义 | 触发场景 | 后续动作 |
|---------|------|---------|-----------|
| 0 | 本段完成 | 完成 STEP 6 并输出段交回信号；`scope=screen` 时按 STEP 3 直接交回 | 编排段调用下一段，或用户单独取用营销分册 |
| 1 | 中途终止（可重试） | 用户主动叫停；用户明确拒绝继续回应提问 | 询问用户：继续共创 / 终止 |
| 2 | 输入异常（不可重试） | `slug` 格式非法；`scope` 取值非法；`outputDir` 无法创建；诉求命中「适用与不适用」的不受理判据 | 提示用户修正参数或调整诉求 |
| 3 | 需人工决策 | 关键前提需用户之外的角色或系统才能确定、本次对话内无法闭环 | 交回待确认清单，由用户安排确认 |

### stderr 格式（JSONL，单行）

```jsonl
{"message":"...","detail":"...","hint":"..."}
```

字段约束：
- `message` 必填，自由文本，简洁单行
- `detail` 可选，多行文本（保留原始错误信息）
- `hint` 可选，给用户的修复提示

## 危险信号（Red Flags）

以下可观测信号表明执行出现偏差，出现任一项必须回退修正：

- RF-IBM1: 追问已开始，而本轮追问的字段编号在 fields.md 第一节中不存在
- RF-IBM2: 单轮输出中需用户回答的问题达到 4 个
- RF-IBM3: 出现「你觉得怎么宣传比较好」这类无候选答案的开放式问题
- RF-IBM4: 某一轮输出通篇是问题，找不到一条用户未提过的可能性
- RF-IBM5: 本轮锁定字段里出现渠道清单、种子用户来源、获客成本或分发合作
- RF-IBM6: 分册中出现没有来源等级标注的数值
- RF-IBM7: 主打卖点的「同类能否做到」列没有出处与取证日期，措辞是「应该没人做」
- RF-IBM8: 用户答「不知道」的字段，在分册里出现了具体取值却未标【缺口】
- RF-IBM9: 分册中模型代填的取值与用户原话混排，读者无法区分来源
- RF-IBM10: 对话中已给出本轮处置分类，其后找不到 `文档：已更新` 行
- RF-IBM11: 输出中出现「第 N 轮」「还剩 N 个问题」「最后一问」这类轮次表述
- RF-IBM12: 分册或对话中出现「不做」「可推进」这类结论态，或出现否决项编号与判定结果
- RF-IBM13: 某字段取值与 `RQ5` 某条硬约束直接冲突，对话中从未回读过该冲突
- RF-IBM14: 台账无产品分区，分册首行下方找不到未锚定声明行
- RF-IBM15: 卖点与证据表里存在「可验证的证据」列为空的行

## 反合理化（Anti-Rationalization）

| 借口 | 反驳 |
|------|------|
| "定位这种事很主观，写得漂亮就行" | 判据不主观：这句话用户能不能原样转述给朋友。转述不出来的定位在传播链的第一步就断了。 |
| "顺便把渠道一起问了效率更高" | 混问的结果是用户只答「我要发某个平台」，定位与卖点整段丢失，下一段再问一遍。 |
| "同类有没有这个卖点我大概知道，不用去查" | 记忆里的同类现状没有出处也没有日期。差异化判定是判死一个想法的依据，不能靠印象。 |
| "卖点先写上，证据以后补" | 没有证据的卖点在裁决段等于不存在。当场标【缺口】比先写上更接近事实。 |
| "同类已经做了这个卖点，这条路走不通了" | 结论态由裁决段按判定表取值。你在营销段下的结论没有可消解方式也没有复活条件。 |
