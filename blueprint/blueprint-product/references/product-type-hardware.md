# 硬件产品方案字段实例化

本文件为 `blueprint-product` 段提供 `RQ2` 产物类型为硬件时，`PRD` 十一个字段各自要拿到的具体东西与计数单位。字段名与闭环判据以 [fields.md](references/fields.md)为唯一来源，取值的记录形态、砍单排序与回读格式以 [product-spec.md](references/product-spec.md)为唯一来源，本文件**严禁**复述。

| 字段 | 该类型下要拿到的东西 | 计数单位 |
|------|------------------|---------|
| `PRD1` | 用户拿到手后每次用它做的那一件事，比现在的做法省下什么 | — |
| `PRD2` | 从开箱到完成一次使用的步骤序列，标出最容易失败的那一步 | 步 |
| `PRD3` | 第一版的零件、模组、配件、包装件逐条点名与各自优先级 | 件 |
| `PRD4` | 每类件第一版做多少件，做一件的加工与装配工时 | 件 · 小时/件 |
| `PRD5` | 尺寸与公差、功耗与续航、材料与工艺、安全阈值的取值 | — |
| `PRD6` | 使用者、安装者、维修者各自能做的动作 | 角色 |
| `PRD7` | 从首次开机到长期使用到保修期的阶段序列 | 阶段 |
| `PRD8` | 装配不良、上电失败、跌落、进水、超温、返修的处理 | 情形 |
| `PRD9` | 从拿到零件到装出一台能开机的样机的那条路径，逐步写出 | 步 |
| `PRD10` | 用户每周用几次、耗材或续航撑多久，一台能撑多少个使用周期 | 次/周 · 周 |
| `PRD11` | 先做手板还是功能样机、几个人试用、什么结果算通过 | 人 |

**本类型的追问侧重**：

- `PRD5` 的安全阈值**必须**单独问到取值，**严禁**并入「按标准做」—— 该项同时是 `OPS6` 合规项的输入
- `PRD4` 的单件工时**必须**分开算首件与批量件，**严禁**用首件工时乘以数量
- `PRD8` 追问时**必须**把返修这一情形问到，**严禁**只问首次装配 —— 返修成本进 `COM4` 单位经济性
- `PRD11` **必须**先做可上电的功能样机，**严禁**用外观手板充当核心体验验证
