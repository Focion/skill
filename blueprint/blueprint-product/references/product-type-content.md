# 内容产品方案字段实例化

本文件为 `blueprint-product` 段提供 `RQ2` 产物类型为内容时，`PRD` 十一个字段各自要拿到的具体东西与计数单位。字段名与闭环判据以 [fields.md](references/fields.md)为唯一来源，取值的记录形态、砍单排序与回读格式以 [product-spec.md](references/product-spec.md)为唯一来源，本文件**严禁**复述。

| 字段 | 该类型下要拿到的东西 | 计数单位 |
|------|------------------|---------|
| `PRD1` | 读者或观众每次看它得到的那一样东西，看完后能做什么 | — |
| `PRD2` | 单篇（单集）的结构序列：开头、主体、收尾各承担什么 | 段 |
| `PRD3` | 第一批的选题、栏目、系列、素材逐条点名与各自优先级 | 篇 |
| `PRD4` | 第一批做多少篇（集），做一篇的采编与制作工时 | 篇 · 小时/篇 |
| `PRD5` | 选题标准、成稿判据、更新频率、素材与引用规则的取值 | — |
| `PRD6` | 作者、编辑、审核、分发各自负责的动作 | 角色 |
| `PRD7` | 读者从看到第一篇到订阅或复看的阶段序列 | 阶段 |
| `PRD8` | 选题撞车、素材拿不到、更新断更、内容被下架时的处理 | 情形 |
| `PRD9` | 从定选题到发出一篇完整成品的那条路径，逐步写出 | 步 |
| `PRD10` | 读者每周看几篇、按承诺的更新频率算，第一批内容能撑多少周 | 篇/周 · 周 |
| `PRD11` | 先发几篇试水（小号、社群）、完读或转发达到多少算通过 | 篇 |

**本类型的追问侧重**：

- `PRD3` **必须**逐条点名选题而非给出选题方向，**严禁**用「围绕 {领域} 做系列」充当条目清单
- `PRD4` 的单篇工时**必须**含采集与素材获取的时间，**严禁**只算写作或剪辑工时
- `PRD8` 追问时**必须**把断更这一情形单独问到并给出处理，**严禁**跳过 —— 更新频率是本类型对外承诺的一部分
- `PRD10` **必须**按承诺的更新频率算可支撑周数，**严禁**用「存稿够多」替代周数
