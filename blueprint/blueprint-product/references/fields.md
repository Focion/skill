# 产品段字段清单

本文件为 `blueprint-product` 段提供本段的待闭环字段、闭环判据、追问句式、空洞回答的追加问法、必核字段与档位子集。候选生成规则、处置分类、来源等级、发散手法与单轮输出格式以 [co-create.md](references/co-create.md)为唯一来源；本段字段在各产物类型下要拿到的具体东西以 [product-spec.md 第一节](references/product-spec.md#一按产物类型的字段实例化)路由到的分册为唯一来源，本文件**严禁**复述两者。

本段字段总数为 11，`scope=screen` 时为 3，单轮输出的完整度分母**必须**按当前 `scope` 取对应数，**严禁**另取。

---

## 一、本段字段清单

| 字段 | 要拿到的东西 | 闭环判据 | 追问句式 |
|------|------------|---------|---------|
| `PRD1` | 核心体验一句话 | 取值型：一句「用户在里面反复做的那一件事」 | 用户打开它之后，反复在做的那一个动作是什么？做完这一下他得到了什么？ |
| `PRD2` | 主流程与核心循环 | 枚举型：从进入到产出结果的步骤序列 | 从进来到拿到结果，中间分几步？哪一步是会被反复重来的那一步？ |
| `PRD3` | 功能与内容清单 | 枚举型：第一版逐条可点名的条目 + 每条的优先级 | 第一版里都有哪些具体条目（关卡、页面、单据、素材、章节）？逐个点名，并说哪几条是砍到最后也要留的。 |
| `PRD4` | 内容规模与单件工时 | 计数型：条目数 + 单位 + 单件产出工时 | 这类条目第一版要做多少个？做一个平均要几小时？ |
| `PRD5` | 规则与数值 | 枚举型：决定结果的规则条目 + 每条的取值或公式 | 结果由哪几条规则决定（难度、掉落、计费、校验、审批）？每条现在的取值或公式是什么？ |
| `PRD6` | 角色与权限 | 枚举型：使用角色清单 + 每个角色可做的动作 | 用它的人分哪几种角色？哪些动作只有某一种角色能做？ |
| `PRD7` | 进度与状态流转 | 枚举型：从开始到结束的状态序列 | 一个用户（或一张单据、一局游戏）会经过哪几个状态？在哪一步会停下不动？ |
| `PRD8` | 边界与失败路径 | 枚举型：异常与失败情形清单 + 每项的处理 | 用户做错、中途退出、数据不合法时分别会发生什么？这些情形第一版怎么处理？ |
| `PRD9` | 端到端可走通切片 | 取值型：一条从入口到结果、能被人原样走一遍的路径 | 第一版里能被完整走一遍的那条路径是哪一条？把它从第一步写到最后一步。 |
| `PRD10` | 内容消耗速度与可支撑时长 | 计数型：单位周期的消耗量 + 第一版内容可支撑的时长 | 一个用户多快把第一版内容用完（每小时几关、每周几篇、每天几笔）？照这个速度第一版能撑多久？ |
| `PRD11` | 核心体验验证动作与判据 | 取值型：一个可先做的验证动作 + 人数 + 一句带数值的通过判据 | 在正式开做之前，用什么先验证这个核心体验成立（纸面原型、可玩 demo、真实业务回放、小规模预演）？找几个人、什么结果算通过？ |

- 本表为**封闭清单**，**必须**逐字取用，**严禁**在本段追问本表之外的字段编号
- `PRD9`、`PRD11` 的闭环另有判定要素，**必须**按 [product-spec.md 第三节](references/product-spec.md#三端到端切片的判定prd9)与[第四节](references/product-spec.md#四核心体验验证动作的判定prd11)判定，**严禁**只按本表闭环判据放行
- `PRD4`、`PRD10` 的取值形态**必须**按 [product-spec.md 第二节](references/product-spec.md#二内容规模与消耗速度的计数口径prd4prd10)书写，**严禁**写成不可乘除的量词

## 二、空洞回答与追加问法

| 空洞回答 | 追加问法 |
|---------|---------|
| 「玩法就是很好玩、很上瘾」 | 把那个上瘾的动作单独拎出来：用户按下去之后屏幕上变的是哪一个数？这一下花他几秒？ |
| 「需求跟竞品差不多，照着做就行」 | 逐条点名你要照做的条目。竞品里哪几条你决定不做？不做的那几条谁在用？ |
| 「内容后面慢慢加，先把框架做出来」 | 第一版要几个条目才够走通一条完整路径？少于这个数时用户看到的是什么？ |
| 「规则以后再细化」 | 先定一条：决定成败（或计费、通过与否）的那条规则，现在的取值是多少？ |
| 「异常情况先不管」 | 用户做错时页面上出现什么？什么都不出现算不算可交付？ |
| 「内容够用很久了」 | 按一个用户每小时（每周）消耗几个算：第一版能撑多少小时？撑不到留存周期时补哪一类条目？ |
| 「先做出来再找人试」 | 试的人从哪来、几个人、什么结果算通过？判据现在就定，做完再定等于没验。 |

- 用户的回答命中本表任一行时**必须**发出对应的追加问法，**严禁**把空洞回答记为【已确认】

## 三、本段必核字段

下列字段**必须**联网取证，**严禁**以模型记忆中的数据代替。

| 字段 | 要核的事实 | 检索方向 |
|------|----------|---------|
| `PRD4` | 同品类同规模产品第一版的公开内容体量 | 同类产品官网、更新日志、开发者复盘文 |

- 取证记录的形态与取不到时的处置以 [co-create.md 第六节](references/co-create.md#六取证记录与取不到时的处置)为唯一来源
- 取到的公开体量与用户给出的条目数差异达到 2 倍时**必须**把两个数并列摆出请用户确认，**严禁**默默采用用户那一个

## 四、上游锚点与档位子集

追问本段字段之前**必须**先读字段台账的下列还原字段，**严禁**在未读台账时开始追问。

| 台账字段 | 本段用它做什么 |
|---------|-------------|
| `RQ2` | 路由到 product-spec 第一节的产物类型分册 |
| `RQ3` | 追问 `PRD1`、`PRD6` 时点名服务对象 |
| `RQ4` | 排序 `PRD3` 优先级时以成功判据为准 |
| `RQ5` | 逐条比对本段取值有无与硬约束直接冲突 |

- 字段台账不存在时**必须**先新建台账、追问 `RQ2` 与 `RQ4` 两项并写入，**严禁**在产物类型未确定时开始本段追问
- 台账中该还原字段标为【缺口】时**必须**在本段分册中标注依赖该缺口，**严禁**当作已确认事实入算
- 本段取值与 `RQ5` 中某条硬约束直接冲突时**必须**当场把冲突两端的取值摆给用户，**严禁**只写入分册不告知

`scope=screen` 时本段字段子集固定为下列三项，**必须**逐字取用，**严禁**增删条目。

| 字段 | 本档为什么要它 |
|------|-------------|
| `PRD1` | 核心体验未成一句话时，下游各段没有对应实物 |
| `PRD2` | 主流程未列步骤时，切片与验收无从写起 |
| `PRD4` | 内容工时是本档工时算式的唯一输入 |

- 子集外的字段在本档**必须**记为【不适用】并附「本档不问」一句，**严禁**标为【缺口】
- 本档**必须**照常执行第三节的取证要求，**严禁**以「只是快筛」为由跳过
- 本档的整体回读**必须**只摘本子集三项的取值，格式仍取 product-spec 第六节，**严禁**摘子集外字段的取值
