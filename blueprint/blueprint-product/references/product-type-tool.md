# 工具与服务产品方案字段实例化

本文件为 `blueprint-product` 段提供 `RQ2` 产物类型为工具或服务时，`PRD` 十一个字段各自要拿到的具体东西与计数单位。字段名与闭环判据以 [fields.md](references/fields.md)为唯一来源，取值的记录形态、砍单排序与回读格式以 [product-spec.md](references/product-spec.md)为唯一来源，本文件**严禁**复述。

未命中其余五种产物类型的诉求一律取本文件，取用规则见 [product-spec.md 第一节](references/product-spec.md#一按产物类型的字段实例化)。

| 字段 | 该类型下要拿到的东西 | 计数单位 |
|------|------------------|---------|
| `PRD1` | 用户每次打开它要完成的那一个任务，完成后得到的产出物 | — |
| `PRD2` | 从输入到拿到产出物的步骤序列，标出耗时最长的那一步 | 步 |
| `PRD3` | 第一版的功能项、输入形态、导出格式、集成对象逐条点名与各自优先级 | 个 |
| `PRD4` | 每类条目第一版做多少个，做一个的开发工时 | 个 · 小时/个 |
| `PRD5` | 额度与限流规则、计费规则、输入合法性规则、结果质量判据的取值 | — |
| `PRD6` | 使用者类型（个人 / 团队 / 管理员）与各自可做的动作 | 类 |
| `PRD7` | 用户从试用到长期使用的阶段序列，标出会放弃的那一阶段 | 阶段 |
| `PRD8` | 输入不合法、处理失败、超额度、结果不满意时分别发生什么 | 情形 |
| `PRD9` | 从第一次打开到拿到一份可用产出物的那条路径，逐步写出 | 步 |
| `PRD10` | 一个用户每周用几次、每次耗掉多少额度，第一版功能能撑几周 | 次/周 · 周 |
| `PRD11` | 让几个目标用户在无引导下完成一次任务、完成率或耗时达到多少算通过 | 人 |

**本类型的追问侧重**：

- `PRD5` 的结果质量判据**必须**写成一个可读出的数值（准确率、通过率、耗时上限），**严禁**写成「结果可用」
- `PRD8` 追问时**必须**把结果不满意这一情形单独问到，**严禁**只问技术性失败 —— 跑通但结果不对是本类型最常见的放弃原因
- `PRD9` 的切片**必须**落在一份可导出、可交给别人看的产出物上，**严禁**以「页面能打开」收尾
- `PRD11` **必须**在无引导条件下测，**严禁**由作者本人在旁边讲解 —— 有讲解的完成率不构成判据
