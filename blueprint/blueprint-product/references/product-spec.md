# 产品方案判定规则

本文件为 `blueprint-product` 段提供产物类型路由、内容规模与消耗速度的计数口径、端到端切片与核心体验验证动作的判定、第一版砍单排序规则与产品方案的整体回读。字段名与闭环判据以 [fields.md](references/fields.md)为唯一来源，各产物类型下字段要拿到的具体东西以第一节路由到的分册为唯一来源，本文件**严禁**复述两者。

产品方案是下游各段的输入源：内容条目没点名就算不出工时，规则没取值就算不出单位经济性，切片没走通就写不出验收标准。

各产物类型的字段实例化分列于下表所载分册，一次只取一份。分册清单为**封闭清单**，**必须**逐字取用，**严禁**在执行中改写路由或另立分册。

| `RQ2` 产物类型 | 分册 | 承载内容 |
|--------------|------|---------|
| 游戏 | [product-type-game.md](references/product-type-game.md) | 策划方案：核心循环、关卡与数值、成长与流失节点 |
| 业务系统 | [product-type-system.md](references/product-type-system.md) | 需求方案：主业务流程、业务规则、角色权限、状态机、异常分支 |
| 工具 / 服务 | [product-type-tool.md](references/product-type-tool.md) | 任务与产出物、额度与质量判据、放弃阶段 |
| 内容 | [product-type-content.md](references/product-type-content.md) | 选题与栏目、成稿判据、更新频率与存量周数 |
| 活动 | [product-type-event.md](references/product-type-event.md) | 环节与物料、报名与名额规则、现场风险 |
| 硬件 | [product-type-hardware.md](references/product-type-hardware.md) | 零件与工艺、公差与安全阈值、样机与返修 |

- 追问本段字段前**必须**完整读取本表路由到的那一份分册，**严禁**凭产物类型名自行推断该类型下的字段形态
- 未命中本表六种类型的产物类型**必须**取 `product-type-tool.md`，**严禁**由模型另拟一套字段形态
- 一次追问**严禁**同时取用两份分册 —— 两份分册的计数单位不同，混用后 `PRD4` 与 `PRD10` 无法相乘或相除
- 各分册的「计数单位」列是本文件第二节的单位来源，**严禁**在分册之外另立单位
- 新增产物类型时**必须**成对增补本表一行与一份同构分册，**严禁**只加路由行

## 二、内容规模与消耗速度的计数口径（`PRD4`、`PRD10`）

`PRD4` 与 `PRD10` 的取值**必须**写成下列固定形态，逐类条目各一行。

```markdown
生产侧 {条目类别} = {条目数} {单位} × {单件工时} 小时/{单位} = {内容工时} 小时（{来源标签}）
消耗侧 {条目类别} = {条目数} {单位} ÷ {消耗速度} {单位}/{周期} = 可支撑 {时长}{周期单位}（{来源标签}）
```

- 单位**必须**取第一节路由到的分册「计数单位」列所载单位，**严禁**另立单位
- 多类条目并存时**必须**逐类分行并给出合计行，**严禁**合成一个总数
- 单件工时与消耗速度**必须**是可乘除的数值，**严禁**写成「一批」「很久」这类不可算的量词
- 内容工时合计与可支撑时长**必须**逐项写入字段台账，**严禁**只写在分册正文 —— 裁决段的算式读的是台账
- 生产侧与消耗侧**必须**逐类各写一行，**严禁**只报生产侧 —— 只有生产侧时「三个月做的内容三天被消耗完」不可见

```markdown
<!-- ✅ 正确：生产侧与消耗侧成对给出，两侧都能算出结果 -->
生产侧 关卡 = {数量} 个 × {工时} 小时/个 = {内容工时} 小时（【E4｜用户算】）
消耗侧 关卡 = {数量} 个 ÷ {速度} 个/小时 = 可支撑 {时长} 小时（【E5｜用户估】）

<!-- ❌ 错误：只报生产侧，用户消耗多快无从判断，可支撑时长不可算 -->
生产侧 关卡 = {数量} 个 × {工时} 小时/个 = {内容工时} 小时
```

## 三、端到端切片的判定（`PRD9`）

一条切片同时过下列三条判据才算成立，任一条未过即该字段未闭环。

| 判据 | 客观判定方式 |
|------|------------|
| 逐步可点名 | 切片的每一步**必须**写成一个动词加一个可点名的对象 |
| 步步有着落 | 切片的每一步所需的功能项或内容项**必须**都出现在 `PRD3` 清单中 |
| 结果可观测 | 走完切片**必须**产出一个可被第三人看到的结果 |

- 切片的步数**必须**可数，**严禁**写成「大致跑通主流程」这类无步骤的表述
- 切片某一步所需的条目不在 `PRD3` 清单内时**必须**在分册中逐条标出该条目名并原样交由裁决段判定，**严禁**在本段给出否决结论
- 切片**严禁**由模型代填后直接判为闭环 —— 代填的切片**必须**标【模型假设】

```markdown
<!-- ✅ 正确：每步一个动词加一个可点名对象，结果可被第三人看到 -->
PRD9 = 打开 {入口} → 选择 {条目名} → 提交 {对象} → 看到 {结果页} 上的 {可观测结果}

<!-- ❌ 错误：无步骤、无可点名对象，第三人无法照着走一遍 -->
PRD9 = 用户能顺利完成主要流程，体验完整
```

## 四、核心体验验证动作的判定（`PRD11`）

`PRD11` 验证的是「这个核心体验成不成立」，与技术段验证「能不能被做出来」两回事，**必须**分别追问，**严禁**互相顶替。

| 要素 | 客观判定方式 |
|------|------------|
| 验证载体 | **必须**是一个可在第一版之前做出来的形态（纸面原型、可玩 demo、历史数据回放、小规模预演、手板） |
| 参与人数 | **必须**写出可数的人数或样本量 |
| 通过判据 | **必须**写成一个可判定真假的结果句，含一个可读出的数值 |
| 执行时机 | **必须**排在实施段第一个里程碑之前 |

- 四个要素缺任一个即该字段未闭环，**严禁**以「做出来再看」替代验证动作
- 验证动作已执行并判为未通过时**必须**在分册中如实记录该结果并交由裁决段判定，**严禁**在本段给出否决结论
- 「找几个朋友看看」**严禁**计为通过判据 —— 无人数、无结果句、无数值

```markdown
<!-- ✅ 正确：载体、人数、判据、时机四要素齐备，结果可读 -->
PRD11 = 用 {纸面原型} 找 {人数} 名 {目标人群} 各走一遍 {PRD2 主流程}；
        {人数} 人中有 {阈值} 人在无提示下完成，且愿意再走第二遍 → 通过；于 {里程碑名} 之前执行

<!-- ❌ 错误：无载体、无人数、无可读数值，验证等于没做 -->
PRD11 = 先做出来给几个朋友试试，反馈好就继续
```

## 五、第一版砍单排序规则（`PRD3`）

用户或裁决段要求把第一版条目砍到预算或工时以内时，按下列排序键**从后往前**砍，**严禁**由模型另设砍单依据。

| 序 | 排序键 | 方向 |
|----|-------|------|
| 1 | 该条目是否出现在 `PRD9` 切片的某一步 | 出现者留到最后 |
| 2 | 该条目是否为 `PRD1` 核心体验的必要组成 | 是者留到最后 |
| 3 | 该条目的单件工时 × 条目数 | 高者先砍 |
| 4 | 该条目在 `PRD3` 中的优先级 | 低者先砍 |

- 排序键 1 与 2 同时成立的条目**必须**保留到最后一档，**严禁**为把工时压进预算而砍掉切片依赖的条目
- 砍单结果**必须**在 `PRD3` 清单里改写为「不做」并写出砍它的排序键编号，**严禁**整条删除
- 四个排序键全部相等时**必须**取 `PRD3` 中书写次序在后的一条先砍，**严禁**由模型任选一条
- 砍单后**必须**重算第二节的内容工时合计并回写台账，**严禁**只改清单不改台账

```markdown
<!-- ✅ 正确：写出砍它的排序键编号，读者能复核为什么砍这一条 -->
- {条目名}：不做（砍单排序键 3 —— 单件工时 × 条目数最高，且不在 PRD9 切片内）

<!-- ❌ 错误：无排序键编号，无法与「模型随手砍」区分 -->
- {条目名}：不做（工作量太大）
```

## 六、产品方案的整体回读

本段全部字段完成判定之后、交回编排段之前，把产品方案整节回读一次并请用户确认。

```markdown
产品方案已成形：核心体验 {PRD1} ｜ 主流程 {步数} 步 ｜ 第一版条目 {条目数} {单位}
可支撑 {时长}{周期单位} ｜ 端到端切片 {步数} 步 ｜ 验证动作 {载体} / {人数} 人
下游各段都按这一版往下算。出口：A 确认，交回 ｜ B 有要改的，我说给你
```

- 回读**必须**在交回编排段之前发出，**严禁**在用户未选出口时输出段交回信号
- 用户选 B → 按其更正改写对应字段，改写与冲突登记以 [co-create.md 第十节](references/co-create.md#十分册与字段台账的就地更新)为唯一来源，改完**必须**再回读一次
- 回读**必须**只摘取已闭环字段的取值，【缺口】与【模型假设】项**必须**在回读中逐项点名
- 回读**严禁**夹带评价性措辞，「这个方案挺完整了」这类表述出现即违规
- 用户选 A 后**必须**在段交回信号中写出 `产品方案回读：已确认` 一行，**严禁**省略该行 —— 编排段按该行放行下游段
- `scope=screen` 时回读**必须**只摘 [fields.md 第四节](references/fields.md#四上游锚点与档位子集)子集内字段的取值，**严禁**摘子集外字段的取值
