# 游戏产品方案字段实例化（策划方案）

本文件为 `blueprint-product` 段提供 `RQ2` 产物类型为游戏时，`PRD` 十一个字段各自要拿到的具体东西与计数单位。字段名与闭环判据以 [fields.md](references/fields.md)为唯一来源，取值的记录形态、砍单排序与回读格式以 [product-spec.md](references/product-spec.md)为唯一来源，本文件**严禁**复述。

| 字段 | 该类型下要拿到的东西 | 计数单位 |
|------|------------------|---------|
| `PRD1` | 玩家反复执行的那一个操作，以及这一下的即时反馈 | — |
| `PRD2` | 一局（或一个循环）从开始到结算的步骤序列，标出可重复的那一步 | 步 |
| `PRD3` | 第一版的关卡、角色、道具、敌人、剧情段落逐条点名与各自优先级 | 个 |
| `PRD4` | 每类内容第一版做多少个，做一个的美术与策划工时 | 个 · 小时/个 |
| `PRD5` | 难度曲线、掉落概率、伤害与成长公式、经济产出与消耗的取值 | — |
| `PRD6` | 玩家身份或职业分类，各自能做的动作与不能做的动作 | 类 |
| `PRD7` | 玩家从新手到留存的进度节点序列，标出会卡住流失的那一节 | 节点 |
| `PRD8` | 失败、死亡、掉线、退出、卡关时分别发生什么 | 情形 |
| `PRD9` | 从启动到完成一局并看到结算的那条路径，逐步写出 | 步 |
| `PRD10` | 一个玩家每小时消耗几个关卡（局、章节），第一版内容能撑多少小时 | 个/小时 · 小时 |
| `PRD11` | 先在纸面原型还是可玩 demo 上试、找几个人试、什么结果算通过 | 人 |

**本类型的追问侧重**：

- `PRD5` **必须**先于 `PRD4` 问到 —— 难度曲线与经济公式未定时，条目数会随数值改动被反复推翻，**严禁**先锁内容量再回头调数值
- `PRD8` 追问时**必须**把死亡、卡关、掉线三种情形分别问到，**严禁**只问胜利路径
- `PRD10` **必须**按一个熟练玩家的稳定消耗速度取值，**严禁**用首次通关时长充当稳定速度
- `PRD11` 的验证载体**必须**能在美术资源到位之前做出来（纸面原型、白盒关卡），**严禁**把验证推到有美术之后
