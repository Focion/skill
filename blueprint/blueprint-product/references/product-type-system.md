# 业务系统产品方案字段实例化（需求方案）

本文件为 `blueprint-product` 段提供 `RQ2` 产物类型为业务系统时，`PRD` 十一个字段各自要拿到的具体东西与计数单位。字段名与闭环判据以 [fields.md](references/fields.md)为唯一来源，取值的记录形态、砍单排序与回读格式以 [product-spec.md](references/product-spec.md)为唯一来源，本文件**严禁**复述。

| 字段 | 该类型下要拿到的东西 | 计数单位 |
|------|------------------|---------|
| `PRD1` | 使用者每天要在系统里完成的那一件业务动作，完成后省下什么 | — |
| `PRD2` | 主业务流程从发起到归档的环节序列，标出会被打回重来的环节 | 环节 |
| `PRD3` | 第一版的页面、单据、字段组、接口、报表逐条点名与各自优先级 | 个 |
| `PRD4` | 每类条目第一版做多少个，做一个的设计与开发工时 | 个 · 小时/个 |
| `PRD5` | 校验规则、计费与折扣规则、审批条件、时效与超期规则的取值 | — |
| `PRD6` | 使用角色清单与每个角色的可见范围、可操作动作、审批权限 | 角色 |
| `PRD7` | 一张单据（或一个业务对象）的状态机：状态序列与各自的流转触发条件 | 状态 |
| `PRD8` | 校验失败、审批驳回、并发修改、数据缺失、超时的处理 | 情形 |
| `PRD9` | 从发起一笔业务到归档可查的那条路径，逐步写出 | 步 |
| `PRD10` | 一个使用者每天走多少笔业务，第一版覆盖的场景能撑到哪个业务量级 | 笔/天 · 笔 |
| `PRD11` | 拿哪条真实业务（历史单据回放、关键用户走查）先走一遍、几个人走、什么结果算通过 | 人 |

**本类型的追问侧重**：

- `PRD6` **必须**问到角色与动作的对应关系而非角色名清单，**严禁**用「管理员 / 普通用户」两个名字充当权限划分
- `PRD7` 的状态**必须**逐个写出流转触发条件，**严禁**只列状态名 —— 缺触发条件的状态机在开发期会被各人各填一套
- `PRD8` 追问时**必须**把校验失败、审批驳回、并发修改三种情形分别问到，**严禁**归成一句「按异常处理」
- `PRD11` **必须**用历史真实单据回放，**严禁**用构造的示例数据充当验证 —— 构造数据永远走得通
