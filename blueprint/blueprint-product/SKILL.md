# 产品方案段（Blueprint Product）

> [!IMPORTANT] 路径解析基准
> 文档内相对路径引用一律以本 skill 根目录（`SKILL.md` 所在目录）为基准解析。

本段是 blueprint 流水线的**产品段**，出手序恒为 1：把「这东西本身是什么」逼到可执行，产出产品分册与台账里的 `PRD` 分区。下游的商业、技术、营销、推广、实施各段都引用本段取值 —— 内容条目没点名就算不出工时，规则没取值就算不出单位经济性，切片没走通就写不出验收标准。本段**只**闭环字段与登记事实，否决判定与结论态一律交裁决段。提问轮次不设上限，也不向用户宣告。

## 适用与不适用

- ✅ **适用**：用户有一个尚未成形的产物构想，且愿意逐轮回应提问 —— 游戏玩法、业务需求、工具功能、内容选题、活动环节、硬件形态。
- ❌ **不适用**：纯事实查询、单点执行任务、已有完整策划案只要求评审 —— 直接回答，**严禁**启动本流程。
- 🚫 **不受理**：诉求的成立以违反法律法规、侵犯他人权益或规避平台风控为必要条件 —— 说明原因后停止，**严禁**输出方案（→ stderr + exitCode=2）。

## 参数

| 参数 | 必填 | 说明 |
|------|------|------|
| `demand` | 是 | 待展开的原始诉求（自然语言，可以只有一句话） |
| `slug` | 否 | 产物文件名片段，缺省 `idea`；由编排段生成并透传 |
| `outputDir` | 否 | 分册与字段台账的输出目录，缺省取当前工作目录 |
| `scope` | 否 | 档位，缺省 `full`；`screen` 时字段子集见 [fields.md 第四节](references/fields.md#四上游锚点与档位子集) |

## 公共约束

> [强约束] 总纲：先替用户把可能性摊开，再逐字段逼到可执行。不替用户拍板，不拿臆测充事实，不以轮次收尾，不越过裁决段给结论。

| # | 约束 | 违反后处理 |
|---|------|-----------|
| IBP1 | 开始追问前**必须**完整读取 [fields.md](references/fields.md)，**严禁**凭 SKILL.md 摘要或记忆提问 | 停止本轮，先完整读取该文件 |
| IBP2 | 开始追问前**必须**按 [product-spec.md 第一节](references/product-spec.md#一按产物类型的字段实例化)完整读取 `RQ2` 路由到的产物类型分册，**严禁**凭产物类型名自行推断字段形态 | 停止本轮，先完整读取该分册 |
| IBP3 | 单轮需用户回答的问题数**必须**不超过 3 个，**严禁**单轮抛出 4 个及以上问题 | 超出的问题移入下一轮后重发本轮 |
| IBP4 | 每个问题**必须**按 [co-create.md 第二节](references/co-create.md#二单轮提问的候选生成规则)附模型先行给出的候选答案，**严禁**抛出无候选的开放式问题 | 补齐候选后重发本轮 |
| IBP5 | 每轮输出**必须**含至少 1 条用户未提过的发散点并标注 [co-create.md 8.1](references/co-create.md#81-手法表)的手法编号，**严禁**把本轮写成纯提问清单 | 补一条带编号的发散点后重发本轮 |
| IBP6 | 本段追问**必须**只覆盖 fields.md 第一节所载字段，**严禁**追问其他段前缀的字段 | 撤回越界问题，本轮只保留本段字段 |
| IBP7 | 用户给出的每个数值**必须**问明来路并按 [co-create.md 第五节](references/co-create.md#五来源等级)标出来源等级，**严禁**把口述数值直接记为已确认事实 | 补问来路后改标来源等级 |
| IBP8 | [fields.md 第三节](references/fields.md#三本段必核字段)所列字段**必须**联网取证并记录出处与取证日期，**严禁**以模型记忆中的市场数据充当取证结果 | 停止该字段判定，先联网取证 |
| IBP9 | 未闭环的字段**必须**标为【缺口】并进入缺口清单，**严禁**用模型臆测值冒充用户已确认的事实 | 改标【缺口】并移入缺口清单 |
| IBP10 | 由模型代填的取值**必须**逐条标注【模型假设】，**严禁**与用户已确认事实混排 | 逐条补标来源标签 |
| IBP11 | 每轮的处置分类、取证与发散点**必须**按 [co-create.md 第十节](references/co-create.md#十分册与字段台账的就地更新)就地写入分册与字段台账，**严禁**把本轮结论只留在对话里 | 补写本轮更新后再抛下一轮 |
| IBP12 | 每轮输出**必须**给出本段完整度进度，**严禁**出现提问轮次的编号、上限或剩余次数 | 删除轮次表述，改回完整度进度 |
| IBP13 | 否决判定与结论态**必须**交由裁决段执行，**严禁**在本段输出否决结论或结论态 | 删除该结论，改为登记事实 |
| IBP14 | 本段取值与台账 `RQ5` 某条硬约束直接冲突时**必须**当场把冲突两端的取值摆给用户，**严禁**只写入分册而不告知 | 立即停止本轮，回读该冲突 |
| IBP15 | 本段字段全部完成判定后**必须**按 [product-spec.md 第六节](references/product-spec.md#六产品方案的整体回读)整体回读并取得用户确认，**严禁**在用户未选出口时输出段交回信号 | 撤回交回信号，先发出整体回读 |

## 核心流程

> [强约束] STEP 3~6 任一交互步骤中，用户主动叫停，或用户明确拒绝继续回应提问 → stderr + exitCode=1；`scope=screen` 时 STEP 4~6 的字段范围与回读范围一律按 [fields.md 第四节](references/fields.md#四上游锚点与档位子集)执行，**严禁**按 `full` 档的全集推进。

### STEP 1：参数校验

按标准校验顺序校验：
- **必填**：`demand`（缺失时不得报错退出，必须先向用户提问「你想把哪个产物的方案理清楚？」，拿到回答后再进入下一步）
- **格式**：`slug`（匹配 `^[a-z0-9一-鿿-]{1,30}$`）
- **枚举**：`scope`（`screen` / `full`）
- **创建**：`outputDir`

任一校验失败 → stderr + exitCode=2

### STEP 2：读取本段规范

用 Read 工具完整读取 `references/co-create.md`、`references/fields.md`、`references/output-spec.md`、`references/product-spec.md`，读完再进入下一步（遵循 IBP1）。

### STEP 3：读取或建立字段台账

读取 `{outputDir}/blueprint-{slug}.fields.json`；文件不存在时按 [fields.md 第四节](references/fields.md#四上游锚点与档位子集)新建并追问该节所列还原字段后写入。按该节读取上游锚点，再按 [product-spec.md 第一节](references/product-spec.md#一按产物类型的字段实例化)完整读取 `RQ2` 路由到的产物类型分册（遵循 IBP2）。

### STEP 4：建立分册骨架

按 [output-spec.md 第一节](references/output-spec.md#一分册骨架)建立分册，未闭环的节写占位串，再单独一行回显分册绝对路径。

### STEP 5：逐字段发散、追问与取证

按 fields.md 第一节的字段次序轮转，输出逐字采用 [co-create.md 第九节](references/co-create.md#九单轮输出格式)的五行格式（遵循 IBP3、IBP4、IBP6、IBP12）：

- 本轮的待闭环字段与追问句式取 fields.md 第一节，该字段在本产物类型下要拿到的东西取 STEP 3 所读分册；发散点按 co-create 8.1 选手法、8.2 取首选手法，合规判据见 8.3（遵循 IBP5）
- 用户给出数值时按 co-create 第七节问明来路并标来源等级（遵循 IBP7），与既有取值冲突按 7.1 回读；fields.md 第三节的必核字段用 WebSearch 与 WebFetch 取证并按 co-create 第六节记录出处与日期（遵循 IBP8）；用户答「不知道」「你定」时按 co-create 第三节分类（遵循 IBP9、IBP10），单字段处置上限见第四节，**严禁**向用户宣告该上限
- `PRD4`、`PRD10` 按 [product-spec.md 第二节](references/product-spec.md#二内容规模与消耗速度的计数口径prd4prd10)写取值，`PRD9` 按第三节判定，`PRD11` 按第四节判定；本轮取值与 `RQ5` 硬约束直接冲突时当场回读（遵循 IBP14），否决判定一律留给裁决段（遵循 IBP13）；本轮分类给出后按 co-create 第十节更新分册与台账、写出 `文档：已更新 {节名列表}` 行，再抛下一轮（遵循 IBP11）
- 用户要求把第一版条目砍到预算或工时以内时按 [product-spec.md 第五节](references/product-spec.md#五第一版砍单排序规则prd3)的排序键砍单；关键前提需用户之外的角色或系统才能确定、本次对话内无法闭环 → stderr + exitCode=3

### STEP 6：整体回读与交回

全部字段完成判定后按 [product-spec.md 第六节](references/product-spec.md#六产品方案的整体回读)整体回读并由用户选出口（遵循 IBP15），用户确认后按 [output-spec.md 第四节](references/output-spec.md#四字段台账的写入范围)补齐台账，再输出段交回信号：`段交回`、`未闭环`、`分册`、`产品方案回读：已确认` 四行。

## 输出规范

### 产物文件

| 文件 | 条件 | 路径 |
|------|------|------|
| 产品分册 | 必产，STEP 4 建立并逐轮更新 | `{outputDir}/blueprint-{slug}-prd.md` |
| 字段台账 | 必产，不存在时由本段建立并逐轮追加 | `{outputDir}/blueprint-{slug}.fields.json` |
| 对话内段交回信号 | 必产 | 直接输出到对话 |

> [强约束] `{slug}` 由编排段生成并透传，本段**必须**按 STEP 1 的格式校验逐字取用该参数值，**严禁**将 `demand` 原文拼入文件名，**严禁**在本段另行改写 `{slug}`。

```markdown
<!-- ✅ 正确：逐字取用透传的 slug -->
slug=做一个-roguelike-小游戏 → blueprint-做一个-roguelike-小游戏-prd.md
<!-- ❌ 错误：把 demand 原文拼入，空格与全角括号进入文件名，产出跨平台不可用的路径 -->
blueprint-做一个 Roguelike 小游戏（手机端）-prd.md
```

### 退出码

本技能在对话模式下运行，无进程退出码。每次结束（含中途终止）**必须**在输出末尾单独打印一行 `状态：{含义}（exitCode={N}）` 供上层判定。

| exitCode | 含义 | 触发场景 | 后续动作 |
|---------|------|---------|-----------|
| 0 | 本段完成 | 完成 STEP 6 并输出段交回信号 | 编排段调用下一段，或用户单独取用产品分册 |
| 1 | 中途终止（可重试） | 用户主动叫停；用户明确拒绝继续回应提问 | 询问用户：继续共创 / 终止 |
| 2 | 输入异常（不可重试） | `slug` 格式非法；`scope` 取值非法；`outputDir` 无法创建；诉求命中「适用与不适用」的不受理判据 | 提示用户修正参数或调整诉求 |
| 3 | 需人工决策 | 关键前提需用户之外的角色或系统才能确定、本次对话内无法闭环 | 交回待确认清单，由用户安排确认 |

### stderr 格式（JSONL，单行）

```jsonl
{"message":"...","detail":"...","hint":"..."}
```

字段约束：
- `message` 必填，自由文本，简洁单行
- `detail` 可选，多行文本（保留原始错误信息）
- `hint` 可选，给用户的修复提示

## 危险信号（Red Flags）

以下可观测信号表明执行出现偏差，出现任一项必须回退修正：

- RF-IBP1: 追问已开始，而本轮追问的字段编号在 fields.md 第一节中不存在
- RF-IBP2: `PRD` 字段提问已开始，而 `RQ2` 路由到的产物类型分册从未被读取
- RF-IBP3: 单轮输出中需用户回答的问题达到 4 个
- RF-IBP4: 出现「你觉得应该怎么做」这类无候选答案的开放式问题
- RF-IBP5: 某一轮输出通篇是问题，找不到一条用户未提过的可能性
- RF-IBP6: 追问记录里出现 `COM`、`TEC`、`MKT`、`GRW`、`OPS` 前缀的字段编号
- RF-IBP7: 分册中出现没有来源等级标注的数值
- RF-IBP8: 必核字段的取值没有出处与取证日期，措辞是「据我所知」「一般在」
- RF-IBP9: 用户答「不知道」的字段，在分册里出现了具体数值却未标【缺口】
- RF-IBP10: 分册中模型代填的取值与用户原话混排，读者无法区分来源
- RF-IBP11: 对话中已给出本轮处置分类，其后找不到 `文档：已更新` 行
- RF-IBP12: 输出中出现「第 N 轮」「还剩 N 个问题」「最后一问」这类轮次表述
- RF-IBP13: 分册或对话中出现「不做」「可推进」这类结论态，或出现否决项编号与判定结果
- RF-IBP14: 某字段取值与 `RQ5` 某条硬约束直接冲突，对话中从未回读过该冲突
- RF-IBP15: 段交回信号已输出，而整体回读中用户尚未选出口

## 反合理化（Anti-Rationalization）

| 借口 | 反驳 |
|------|------|
| "产物类型我看得出来，不用去读那份分册" | 分册管的是这个类型下每个字段要拿到什么与用什么单位计数。不读它，你问出来的条目数和工时对不上单位，下游乘不起来。 |
| "内容量先估个大概，后面细化" | 估的条目数会被下游当成工时输入。标【缺口】才叫完整，编上去只是好看。 |
| "切片写成『能跑通主流程』就够了，细节开发时再说" | 没有逐步写出的切片无法被第三人走一遍，也无法判断哪一步的条目不在第一版清单里。 |
| "验证动作等做出来再定，现在定不了" | 做完再定判据等于没验：任何结果都能被解释成通过。人数与数值现在就定。 |
| "单位经济性明显为负，我直接告诉用户别做了" | 结论态由裁决段按判定表取值。你在产品段下的结论没有算式记录也没有复活条件，用户无法复核。 |
