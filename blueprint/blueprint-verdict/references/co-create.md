# 共创协议（各段共用）

本文件为 blueprint 流水线各段共用的共创协议：字段闭环判据的三形态、候选生成规则、回答处置四分类、单字段处置上限、来源等级、取证记录格式、来源追问话术、矛盾登记、发散手法、单轮输出格式、分册与字段台账的就地更新。

> 本文件是 `blueprint/_shared/co-create.md` 的同步副本。改动**必须**落在主文件后重新同步到各段，**严禁**只改单个 skill 内的副本。

本文件不含任何跨文件链接，**严禁**在同步副本中补入链接——各段的字段清单一律读该段的 `references/fields.md`，各段的产物骨架一律读该段的 `references/output-spec.md`。

## 一、字段闭环判据的三形态

各段字段清单的「闭环判据」列一律采用下列三种可机械核对的形态之一。

| 形态 | 判据写法 | 核对方式 |
|------|---------|---------|
| 取值型 | 该字段已有用户确认的一个具体取值 | 能把取值原样抄进分册 |
| 计数型 | 该字段已有用户确认的数值与单位 | 能把数值与单位原样抄进分册 |
| 枚举型 | 该字段已有用户从候选中选定的一项或多项 | 能列出选定项名称 |

三种形态之外的回答一律未闭环，**必须**按第三节分类处置，**严禁**记为已闭环。

## 二、单轮提问的候选生成规则

每个向用户抛出的问题都先由模型给出候选答案，用户从候选中挑或自填。

| 规则 | 客观判据 |
|------|---------|
| 候选数量 | 每问的候选数**必须**不少于 2 条，少于 2 条即违规 |
| 候选来源 | 候选**必须**落在该段 `references/fields.md` 中该字段追问句式给出的取值空间内，**严禁**另起取值空间 |
| 候选互斥 | 任意两条候选**必须**指向不同取值，出现语义重复的候选即违规 |
| 候选可选中 | 每条候选**必须**是选中后该字段即闭环的具体取值，**严禁**写成不可直接选中的表述 |
| 多选标注 | 每问结尾**必须**标注「可多选」或「可自填」之一，两者缺失即违规 |

```markdown
<!-- ✅ 正确：候选具体、互斥、选中即闭环，结尾带标注 -->
问题：收入模式先按哪一种设计？（可自填）
  A 一次性买断，单价 {金额}
  B 免费下载 + 内购道具
  C 订阅制，{周期} 一付

<!-- ❌ 错误：无候选的开放式问题，用户只会回「你觉得呢」 -->
问题：你觉得这个产品应该怎么变现？

<!-- ❌ 错误：候选不可直接选中，选完字段仍未闭环 -->
问题：定价怎么定？（可自填）
  A 看市场行情
  B 都可以
```

## 三、回答处置四分类

用户回答后，本轮每个字段都归入下列四类之一，分类结果单独一行输出。各段沿用同一套标签，**必须**逐字取用，**严禁**改写为其他措辞。

| 标签 | 判据 | 处置动作 |
|------|------|---------|
| 【已确认】 | 回答符合第一节三形态之一，来源等级已按第七节问明 | 记入分册正文，附来源等级标注 |
| 【模型假设】 | 用户答「你定」「你觉得就行」，或用户未否认模型给出的某条候选 | 模型选定一项并标注该标签，本段收尾前集中回读一次 |
| 【缺口】 | 用户答「不知道」「还没想」「拿不到这个数」 | 写入缺口清单，注明缺什么、单位、可从哪取 |
| 【不适用】 | 用户说明该字段在本诉求下不存在 | 记为不适用，**必须**附一句理由，**严禁**留空 |

- 【缺口】**必须**只写缺什么，**严禁**填入具体数值——一旦填入，用户会拿它去做决定
- 【模型假设】**必须**独立成列表项，**严禁**与【已确认】混排在同一列表中
- 用户答不上来的字段**必须**判为【缺口】，**严禁**判为【不适用】——答不上来是缺口，不存在才是不适用
- 联网取证未取到的必核字段**必须**按第六节标【待核实】，该标签**严禁**计为【已确认】

```markdown
<!-- ✅ 正确：来源逐条标注，缺口不带数字 -->
- COM3 收入模式：内购道具【已确认】
- COM4 单位经济性：待测算【缺口】（缺：单用户服务成本，单位 元/月，可从服务器账单取）

<!-- ❌ 错误：用户答「不知道」，分册里却出现了模型编的数字 -->
- COM4 单位经济性：单用户毛利 3 元
```

## 四、单字段处置上限

同一字段连续 2 轮追问后，回答仍未落到第一节三形态之一 → **必须**按第三节标注为【模型假设】或【缺口】后推进下一字段。

- 本上限只管**单个字段**的追问次数；提问的总轮次不设上限，**严禁**把本节外推为总轮次上限
- 本上限**严禁**向用户宣告，输出中出现「这个问题最后再问一次」这类表述即违规
- 命中上限的字段**必须**留在缺口清单里，**严禁**因为已标注就从分册中删除

```markdown
<!-- ✅ 正确：命中上限后就地标注并推进，不提次数 -->
- GRW4 获客成本：暂无投放数据【缺口】（缺：单用户获客成本，单位 元/人，可从首次投放测试取）

<!-- ❌ 错误：向用户宣告追问次数上限 -->
这个问题我只能再问你一次，回答不了我们就跳过。
```

## 五、来源等级

每个进入分册或算式的数值都带一个来源等级标注。

| 等级 | 来源 | 可用性 | 标注写法 |
|------|------|-------|---------|
| `E1` | 官方统计、主管部门文档、企业公开财报 | 可作硬否决判据 | `【E1｜{出处}｜{取证日期}】` |
| `E2` | 服务商或平台的公开定价页、公开规则页 | 可作硬否决判据 | `【E2｜{出处}｜{取证日期}】` |
| `E3` | 二手报道、第三方榜单、社区帖 | 可入算式，不可单独作硬否决判据 | `【E3｜{出处}｜{取证日期}】` |
| `E4` | 用户口述，用户说明该数是算过或查过的 | 可入算式，不可单独作硬否决判据 | `【E4｜用户算/查】` |
| `E5` | 用户口述，用户说明该数是估的 | 只作参考，不可入否决判据 | `【E5｜用户估】` |
| `E6` | 模型估算 | 只作参考，不可入否决判据 | `【E6｜模型估】` |

- 每个写入分册的数值**必须**带等级标注，无标注的数值**严禁**写入
- 用户语气笃定**严禁**作为升级来源等级的理由，等级**必须**只由该数的来路决定

```markdown
<!-- ✅ 正确：数值带等级、出处与日期 -->
- GRW4 获客成本 = {金额} 元/人【E2｜{渠道官方广告后台公示页}｜{取证日期}】

<!-- ❌ 错误：无等级标注，读者无法判断这个数的来路 -->
- GRW4 获客成本 = {金额} 元/人
```

## 六、取证记录与取不到时的处置

单条取证记录固定形态如下，各段分册的「取证记录」节逐条列出。

```markdown
{字段} = {取值}{单位}【{等级}｜{出处}｜{取证日期}】
```

- 取证动作**必须**先定位来源页再读取原页，**严禁**只凭检索结果摘要就落数
- 取证日期**必须**写明，缺日期的记录**严禁**写入分册
- 取证日期距今超过 12 个月的 `E1` 与 `E3` 记录**必须**追加一句「快照可能过期，须复核」，**严禁**省略该句
- 出处**必须**是可回访的页面标识，**严禁**写成「网上查到」这类无法回访的表述
- 一个字段取到两条互相冲突的证据时**必须**取等级更高的那条，**严禁**保留低等级那条作为唯一取值
- 两条冲突证据的等级相等时**必须**并列写入并请用户择一，**严禁**由模型代为择一

| 取不到的情形 | 处置 |
|------------|------|
| 检索后无可用来源 | 标【待核实】，并记录检索过的关键词 |
| 只找到 `E3` 级来源 | 按 `E3` 标注写入，**严禁**升级为 `E1` |
| 来源页无法读取 | 标【待核实】，记录该页标识 |

- 标【待核实】的字段**必须**进入缺口清单，**严禁**因为已尝试取证就当作已闭环

## 七、来源追问话术与矛盾登记

用户给出任何数值时，固定追问一句：**「这个数是算过的、查到的，还是估的？」**

| 用户回答 | 后续动作 | 落定等级 |
|---------|---------|---------|
| 算过的 | 追问算式与输入项，把算式一并记下 | `E4` |
| 查到的 | 追问出处，能给出可回访标识则按该来源等级落定 | `E1`~`E3` |
| 估的 | 不再追问，直接落定 | `E5` |
| 答不上来这个数怎么来的 | 按估的处置 | `E5` |

- 追问来路**必须**逐个数值执行，**严禁**因为用户是行业内人士而跳过
- 用户给的数值与本段取到的 `E1` 或 `E2` 证据差异达到 2 倍时**必须**把两个数并列摆出请用户确认，**严禁**默默采用用户那一个

### 7.1 冲突的判据与回读

命中下列任一条即为冲突，**必须**当场回读，**严禁**静默覆盖。

| 判据 | 客观判定方式 |
|------|------------|
| 同字段前后不一致 | 同一字段前后两次取值不同 |
| 跨字段结论翻转 | 两个字段的新取值使本段某条结论从成立变为不成立 |

```markdown
你先前说 {字段} = {先前取值}；刚才说 {新取值}。
两者会让 {结论名} 从 {结论A} 变成 {结论B}。
用哪一个？
```

### 7.2 冲突登记表

各段分册的「冲突登记」节逐条登记，表头固定如下。

```markdown
| 字段 | 先前取值 | 新取值 | 用户择定 | 影响的结论 |
|------|---------|-------|---------|-----------|
```

- 已被回读并择定的冲突**必须**留在表中，**严禁**因为已解决就删除该行

```markdown
<!-- ✅ 正确：两个数并列摆出，差异写明，请用户择一 -->
你说获客成本 {金额A} 元/人【E5｜用户估】；我查到该渠道公示价 {金额B} 元/人【E2｜{出处}｜{日期}】，差 {倍数} 倍。按哪个算？

<!-- ❌ 错误：默默采用用户口述值，取到的公开证据被丢掉 -->
好的，获客成本按 {金额A} 元/人。
```

## 八、发散手法

### 8.1 手法表

| 编号 | 手法 | 生成句式 | 适用段 | 产出形态 |
|------|------|---------|-------|---------|
| `DG1` | 约束移除 | 假设「{用户提到的硬约束}」不存在，这件事会变成什么样 | `PRD` `COM` `TEC` `OPS` | 一个被约束挡住的做法 |
| `DG2` | 极端缩放 | 把规模、时长或价格放大 10 倍、缩小到十分之一，还成立吗 | `PRD` `COM` `TEC` | 一个极端档位的产品形态 |
| `DG3` | 类比迁移 | {另一个品类} 里靠 {某机制} 成立，搬到这里是什么 | `COM` `GRW` `MKT` | 一条外来机制的移植方案 |
| `DG4` | 角色置换 | 换成 {另一类人} 来用同一个东西，他会怎么用 | `PRD` `COM` `MKT` | 一个新客群与对应用法 |
| `DG5` | 组合嫁接 | 把这个诉求与用户已有的现成资源强行绑在一起 | `GRW` `OPS` | 一条借用已有资产的路径 |
| `DG6` | 反向假设 | 把「{核心假设}」取反，结论还能不能站住 | `PRD` `COM` `TEC` | 一条推翻原路线的可能性 |
| `DG7` | 时间平移 | 把它提前到还没做完就发布，或推迟到 {节点} 再发 | `GRW` `OPS` | 一个改动发布时序的做法 |
| `DG8` | 拆解重组 | 拆成能单独交付的最小块，换一个顺序先交哪块 | `PRD` `TEC` `OPS` | 一份重排后的交付顺序 |
| `DG9` | 收费翻转 | 现在免费的收费、收费的免费，或换向另一方收费 | `COM` | 一个新的收费对象与方式 |
| `DG10` | 渠道错位 | 放到这个品类通常不出现的渠道会怎样 | `GRW` | 一个非常规渠道与其理由 |
| `DG11` | 最小内核 | 只保留一个循环，其余全砍，还有人愿意用吗 | `PRD` `TEC` `MKT` | 一句最小内核的描述 |
| `DG12` | 反手做供给 | 不做这个产品，改成给做这个产品的人提供工具或服务 | `COM` `TEC` | 一条上游供给侧路线 |

- 单轮的发散点**必须**标出所用手法编号，**严禁**省略编号
- 同一手法编号在同一字段上**必须**只用一次，重复使用即违规
- 用户已明确否决的方向**严禁**再作为发散点抛出，否决记录**必须**以用户原话为准

### 8.2 按产物类型的首选手法

产物类型取字段台账里的 `RQ2`，未命中下表的类型**必须**按「工具 / 服务」行处理。

| 产物类型 | 首选手法 | 侧重说明 |
|---------|---------|---------|
| 游戏 | `DG11` `DG2` `DG4` | 先把核心循环压到一句话，再试极端难度与非目标玩家群 |
| 业务系统 | `DG8` `DG1` `DG11` | 先按可单独交付的业务环节重排交付顺序，再移除流程约束、压到一条最小主流程 |
| 工具 / 服务 | `DG12` `DG9` `DG8` | 先看上游供给侧机会，再翻转收费对象与交付顺序 |
| 内容 | `DG3` `DG10` `DG7` | 先移植其他品类的内容机制，再试非常规渠道与发布时序 |
| 活动 | `DG5` `DG7` `DG10` | 先绑现有资源，再改时序与渠道 |
| 硬件 | `DG1` `DG2` `DG8` | 先移除成本与工艺约束，再压规模与交付顺序 |
| 突发奇想 | `DG6` `DG1` `DG11` | 先取反核心假设验证它是否只是错觉，再压到最小内核 |

- 首选手法**必须**在本段首轮就出手，**严禁**攒到定向补问阶段再补

### 8.3 发散点的合规判据

一条发散点同时过下列三条判据才算合规，任一条未过即本轮违规。

| 判据 | 客观判定方式 |
|------|------------|
| 用户未提过 | 该发散点的核心名词未出现在用户本次对话的全部发言中 |
| 含可执行动作 | 该发散点包含一个动词与一个可点名的对象 |
| 非口号 | 该发散点**严禁**命中下方口号词封闭表中的任一词 |

```text
口号词封闭表：加强  提升  优化  打造  赋能  深耕  抢占  引爆  全面升级
```

- 三条判据**必须**逐条核对，**严禁**用「用户可能没想到」这类理由替代
- 合规判据只管发散点本身的写法，**严禁**据此判定该发散点的商业价值高低

```markdown
<!-- ✅ 正确：核心名词用户未提过，含动词与可点名对象，无口号词 -->
发散：把付费点从玩家挪到赛事主办方，按场次收授权费（手法 DG9）

<!-- ❌ 错误：命中口号词封闭表中的「提升」与「打造」，无可执行动作 -->
发散：提升用户体验，打造差异化竞争力（手法 DG9）

<!-- ❌ 错误：核心名词「内购」在用户上一轮发言中已出现，不构成发散 -->
发散：可以考虑做内购（手法 DG9）
```

## 九、单轮输出格式

每一次向用户输出都逐字采用下列五行，缺任一行即违规。

```markdown
本段：{段代码 + 名称} ｜ 本轮锁定：{要闭环的字段名}
发散：{至少 1 条用户未提过的可能性}（手法 {DG 编号}）
问题：{每问一行，每行问题后附候选答案，并标注「可多选」或「可自填」}
已核实：{本轮取到的事实 + 来源等级 + 出处 + 取证日期}
本段完整度：{已闭环字段数}/{本段字段总数} ｜ 尚缺：{未闭环字段名列表}
```

- 「已核实」行本轮无须取证时**必须**写「本轮无须取证」，**严禁**整行省略
- 「本段完整度」的分母**必须**取该段 `references/fields.md` 所载字段总数，**严禁**按本轮已触达的字段动态缩小分母
- 任何一行**严禁**出现提问轮次的编号、上限或剩余次数
- 拿到回答后**必须**先单独一行按第三节给出本轮各字段的处置分类，再按第十节更新分册与字段台账，**严禁**跳过分类直接抛下一轮

```markdown
<!-- ✅ 正确：五行齐备，取证带出处与日期，无轮次表述 -->
本段：GRW 推广 ｜ 本轮锁定：GRW4 获客成本与预算上限
发散：把首批投放换成向 {同类社群} 的运营者按成交分佣（手法 DG5）
问题：单个用户你能接受花多少钱？（可自填）A {金额} 元以内 B {金额} 元以内
已核实：该渠道公示报价 {金额} 元/人【E2｜{出处}｜{取证日期}】
本段完整度：2/5 ｜ 尚缺：GRW4 获客成本、GRW5 合作与分发

<!-- ❌ 错误：缺「已核实」行，且出现轮次编号 -->
第 6 轮 ｜ 本段：GRW 推广 ｜ 本轮锁定：GRW4 获客成本与预算上限
发散：换成按成交分佣（手法 DG5）
问题：单个用户你能接受花多少钱？
本段完整度：2/5 ｜ 尚缺：GRW4 获客成本
```

## 十、分册与字段台账的就地更新

每一轮在给出本轮处置分类之后、抛出下一轮之前，把本轮产出落进两处：本段分册（骨架见该段 `references/output-spec.md`）与字段台账。

| 本轮产出 | 落点 |
|---------|------|
| 各字段的处置分类与取值 | 分册的方案节 |
| 本轮取到的事实 | 分册的取证记录节 |
| 本轮回读并择定的冲突 | 分册的冲突登记节 |
| 本轮的发散点与用户反应 | 分册的发散池节 |
| 已闭环字段数与未闭环字段名 | 分册的完整度与缺口节 |
| 每个字段的取值、标签、来源等级、出处、取证日期 | 字段台账 |

### 10.1 字段台账的单条记录形态

字段台账是一份 JSON 文件，每个字段一条记录，形态固定如下。

```json
"{字段编号}": {"value": "{取值}", "label": "{处置标签}", "grade": "{来源等级}", "source": "{出处}", "date": "{取证日期}"}
```

- `label` 的取值**必须**属于 `已确认` / `模型假设` / `缺口` / `不适用` / `待核实` 五者之一，出现五者之外的取值即违规
- `grade` 的取值**必须**属于 `E1`~`E6` 之一或 `null`，出现其他字符串即违规
- 未取证的字段**必须**把 `source` 与 `date` 写为 `null`，**严禁**填入空字符串
- 本段**必须**只写入本段字段的记录，**严禁**改写其他段已写入的记录

### 10.2 就地改写与留痕

| 情形 | 处置 |
|------|------|
| 用户改写已写入的取值 | 新值写入原位，旧值按 7.2 登记进冲突登记节 |
| 字段由【缺口】转为【已确认】 | 占位条目替换为取值，同步从缺口清单删掉该行 |
| 字段由【模型假设】转为【已确认】 | 原条目替换为取值，同步从模型假设清单删掉该行 |
| 用户否决某条已入池的发散点 | 发散池「用户反应」列改写为 `否决` |
| 用户主动叫停 | 分册保留在最后一次更新后的状态 |

- 更新动作**必须**对目标节定点改写，**严禁**整份重写覆盖已有内容
- 更新完成后**必须**在对话中单独一行写出 `文档：已更新 {节名列表}`，**严禁**省略该行
- 更新**必须**在抛出下一轮之前完成，**严禁**滞后于下一轮提问——文档落后一轮时，中断即丢掉该轮结论
- 旧取值**严禁**被静默删除，覆盖之前**必须**先完成冲突登记
- 本轮无取证、无冲突时对应落点**必须**保持原状，**严禁**在落点写入空行占位

```markdown
<!-- ✅ 正确：取值带来源标签，更新行列出落点节名 -->
- 定价：{金额} 元 / 月（【已确认】）
文档：已更新 商业方案、取证记录、发散池

<!-- ❌ 错误：取值无来源标签，且缺更新行，读者无法区分谁给的 -->
- 定价：{金额} 元 / 月
```
