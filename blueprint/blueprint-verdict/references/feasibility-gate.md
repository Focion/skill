# 可行性裁决

本文件为 `blueprint-verdict` 段提供硬否决项、一致性算式、路线作废条件与事前验尸、结论态判定表、降级路线生成规则、复活条件写法与硬否决的当场明示格式。数值的来源等级与取证规则以 [co-create.md](references/co-create.md)为唯一来源，非字段门禁与台账读取规则以 [gate-check.md](references/gate-check.md)为唯一来源，本文件**严禁**复述两者。

本文件所有算式的输入一律取字段台账所载取值，**严禁**改取分册正文或对话中的口述值。

---

## 一、硬否决项

命中任一项即为硬否决，命中当场按第七节向用户明示。

| 编号 | 否决项 | 判据 | 可消解方式 |
|------|-------|------|-----------|
| `KO1` | 单位经济性为负 | `FC1` ≤ 0，且三条降本或提价路线均被用户否决 | 提价、砍可变成本项、换低成本交付方式 |
| `KO2` | 获客成本吃掉全部价值 | `FC2` 判为 CAC ≥ LTV | 换零现金渠道、提高留存周期数、提价 |
| `KO3` | 钱不够到第一版 | `FC3` 判为现金需求 > 可投预算 | 砍功能项、换免费依赖、追加预算 |
| `KO4` | 时间不够到第一版 | `FC4` 判为所需工时 > 可投工时 | 砍功能项、延长周期、增加人手 |
| `KO5` | 与硬约束直接冲突 | 台账 `RQ5` 中某条硬约束与 `TEC1` 的第一版功能项或 `COM3` 的收入模式直接冲突 | 由用户改动该条硬约束 |
| `KO6` | 合规或许可过不去 | 台账 `OPS6` 存在判为适用而无对应资质的项，且无不触发该项的替代形态 | 改为不触发该合规项的形态、取得资质 |
| `KO7` | 关键技术难点验证失败 | 台账 `TEC4` 的验证动作已执行并判为未通过 | 换技术路径、砍掉依赖该难点的功能 |
| `KO8` | 唯一渠道进不去 | 台账 `GRW2` 的可用渠道条数为 1，且其准入门槛不可满足 | 换渠道、满足门槛、改为自有流量起步 |
| `KO9` | 同类已存在且无差异化证据 | 台账 `COM5` 已取证存在同类，`MKT3` 记录的 `grade` 不属于 `E1`~`E4` | 换细分人群、换差异化维度 |
| `KO10` | 核心体验不可交付 | 台账 `PRD9` 切片存在某一步所需的条目既不在 `PRD3` 第一版清单、也不在 `TEC1` 第一版功能项内，且用户否决把该条目加入第一版 | 把该条目加入第一版、改用一条全部步骤都在第一版内的更短切片 |
| `KO11` | 核心体验验证失败 | 台账 `PRD11` 的验证动作已执行并判为未通过，且用户否决换核心体验与换目标人群两条路 | 换核心体验、换目标人群、按验证中被卡住的那一步改主流程 |

- 判定硬否决**必须**至少有一条 `E1` 或 `E2` 证据支撑，**严禁**仅凭 `E3`~`E6` 判死一个想法
- 某项判据引用的台账字段全部闭环后**必须**当场判定该项，**严禁**攒到结论态步骤再统一判
- 「可消解方式」列**必须**在明示时一并给出，**严禁**只报否决不给出路
- 用户采纳某条可消解方式后**必须**重算关联算式，**严禁**凭用户口头同意就撤销该否决项
- 判据引用的台账字段标为【缺口】或【待核实】时该项**必须**记为不可判定，**严禁**按未命中处理

## 二、一致性算式

判定结论态前逐条算完下表全部算式，一条不落。

| 编号 | 算式 | 输入台账字段 | 不成立判据 | 关联否决项 |
|------|------|------------|-----------|-----------|
| `FC1` | 单位经济性 = 单用户收入 − 单用户可变成本 | `COM3` `COM4` | 结果 ≤ 0 | `KO1` |
| `FC2` | LTV = 单用户收入 × 付费次数；CAC 取 `GRW4` | `COM3` `COM6` `GRW4` | CAC ≥ LTV | `KO2` |
| `FC3` | 到第一版现金需求 = 依赖费用 + 首批推广投入 + 一次性支出 | `TEC5` `GRW4` `OPS4` | 需求 > `OPS4` 可投预算 | `KO3` |
| `FC4` | 到第一版工时 = 功能项估时合计 + 内容工时合计 | `TEC1` `PRD4` `OPS2` `OPS7` | 工时 > `OPS2` 周数 × `OPS7` 每周小时数 | `KO4` |
| `FC5` | 可达用户量 = 推广预算 ÷ CAC | `GRW4` `OPS5` | 可达量 < `OPS5` 目标值 | — |
| `FC6` | 回本周期 = 现金需求 ÷（月新增用户 × 单位经济性） | `OPS5` `RQ5` | 周期 > `RQ5` 中的期限约束 | — |
| `FC7` | 机会成本差额 = 预期月净收益 − 机会成本基准 | `COM7` `OPS5` `OPS7` | 差额 ≤ 0 | — |
| `FC8` | 内容可支撑时长与留存周期比对 | `PRD10` `COM6` | 可支撑时长 < `COM6` 留存周期 | — |

- 每条算式**必须**写出输入取值、来源等级与计算过程，**严禁**只给结论
- 缺输入项的算式**必须**记为不可判定并写明缺哪个输入，**严禁**估一个数把账做平
- 输入含 `E5` 或 `E6` 的算式，其结果**必须**标注为参考值，**严禁**用该结果触发硬否决
- `FC5`、`FC6`、`FC7`、`FC8` 不成立**必须**按缩范围处置，**严禁**据此判为不做
- 台账 `RQ4` 成功判据不含收入项时 `FC7` **必须**记为不适用，**严禁**用机会成本判死一个不以挣钱为目标的诉求
- `FC7` 不成立时**必须**在结论的一句话理由中写出差额数值，**严禁**只在算式表里留一行不成立
- `FC6` 的现金需求与单位经济性**必须**取 `FC3` 与 `FC1` 的计算结果，**严禁**另取台账原值重算

```markdown
<!-- ✅ 正确：写出输入、等级与算式，结论可复核 -->
FC1 = {金额A}【E2｜{出处}｜{日期}】 − {金额B}【E4｜用户算】 = {结果} → 成立

<!-- ❌ 错误：缺输入项却估了一个数，账被做平 -->
FC1 = {金额A} − 大约 {金额B}（估） = {结果} → 成立

<!-- ❌ 错误：只给结论，无法复核也无法定位是哪个输入错 -->
FC1：单位经济性为正，成立
```

## 三、路线作废条件与事前验尸

每条候选路线在收束时补齐下列两项。

| 项 | 要求 |
|----|------|
| 作废条件 | 一句「若 {关键假设} 不成立则本路线作废」，关键假设取该路线所依赖的最高不确定项 |
| 事前验尸 | 设定「一年后这条路线已被证明是错的」，倒推三条最可能的死因 |

- 每条死因**必须**对应到一个 `KO` 编号或 `FC` 编号，**严禁**写成「执行不到位」这类泛化风险
- 三条死因中**必须**至少有一条标出现在就能验的动作，**严禁**三条全部推给未来
- 作废条件**必须**写成可判定真假的句子，**严禁**写成方向性描述

## 四、结论态判定表

### 4.1 `scope=full` 的判定表

按「判定序」从小到大逐条比对，取第一个命中的结论态，**严禁**跳序取值。

| 判定序 | 结论态 | 判据 | 必须附什么 |
|-------|-------|------|-----------|
| 1 | 证据不足，不判 | 台账 `PRD1`、`PRD2`、`PRD9` 中任一未闭环，或不可判定的算式数 ≥ 2，或【模型假设】占比 ≥ 40% | 缺口清单 + 取数清单 |
| 2 | 不做 | 存在未消解硬否决项，降级路线无法同时过 `FC1` 与 `FC3` | 否决登记 + 复活条件 + 降级路线尝试记录 |
| 3 | 转向 | 存在未消解硬否决项，降级路线可过 `FC1` 与 `FC3` | 降级路线 + 按降级路线改写的各段行动项 |
| 4 | 缩范围推进 | 无未消解硬否决项，`FC5`、`FC6`、`FC7`、`FC8` 中任一不成立 | 缩范围后的主推路线 |
| 5 | 推进 | 无未消解硬否决项，`FC5`、`FC6`、`FC7`、`FC8` 均成立或记为不适用 | 主推路线 |

### 4.2 `scope=screen` 的判定表

| 判定序 | 结论态 | 判据 | 必须附什么 |
|-------|-------|------|-----------|
| 1 | 证据不足，不判 | 台账 `PRD1` 或 `PRD2` 未闭环，或本档所执行算式中不可判定的数 ≥ 2 | 缺口清单 + 取数清单 |
| 2 | 不做 | 存在未消解的硬否决项，且其可消解方式已被用户否决 | 否决登记 + 复活条件 |
| 3 | 可继续 | 无未消解硬否决项 | 本档未判项清单 |

- 【模型假设】占比的分母**必须**按 [gate-check.md 第三节](references/gate-check.md#三模型假设占比的统计口径)取值，**严禁**另取分母
- 结论态**必须**附触发它的判据编号，**严禁**只写结论态
- 判为「证据不足，不判」时**严禁**改写为推进 —— 缺的是证据而不是结论
- 判定序 1 的产品字段判据**必须**先判 —— 产品方案未成形时算出的账无对应实物，**严禁**跳过该判据直接看算式数
- `scope=screen` 时**必须**只取 4.2 的三种取值，**严禁**判为「推进」「缩范围推进」「转向」
- 判为「可继续」**严禁**被表述为「这件事可行」，它只表示本档未发现否决项
- `scope=screen` 时未执行的算式与否决项**必须**在分册中逐条列为「本档未判」，**严禁**省略不提

## 五、降级路线生成规则

存在未消解硬否决项时生成降级路线，按命中的编号取对应动作。

| 命中项 | 降级动作 |
|-------|---------|
| `KO1` | 提价到 `FC1` 转正所需水平，或砍掉占比最高的可变成本项 |
| `KO2` | 换为零现金渠道起步，冷启动来源改自有流量或熟人圈 |
| `KO3` | 把第一版条目砍到 `OPS4` 可投预算以内，砍单由产品段按其排序键执行 |
| `KO4` | 把第一版条目砍到可投工时以内，或把 `OPS2` 周数拉长到工时可容纳 |
| `KO5` | 改动与硬约束冲突的那一项，其余保持 |
| `KO6` | 改为不触发该合规项的形态 |
| `KO7` | 换技术路径，或砍掉依赖该难点的全部功能 |
| `KO8` | 换渠道，或改为不依赖渠道的直接触达 |
| `KO9` | 换细分人群，或换一个有 `E1`~`E4` 证据支撑的差异化维度 |
| `KO10` | 把切片缺的那个条目加入第一版清单，或换一条全部步骤都在第一版内的更短切片 |
| `KO11` | 按验证中被卡住的那一步改写核心体验与主流程，或把目标人群换成验证中通过率最高的那一类 |
| `FC5` | 把 `OPS5` 目标值下调到可达用户量，或换单位成本更低的渠道 |
| `FC6` | 提价、砍现金需求项，或由用户把 `RQ5` 的期限约束放宽到回本周期之外 |
| `FC7` | 砍 `OPS7` 投入工时改为副线推进，或把预期月净收益提到机会成本基准之上 |
| `FC8` | 回补高优先级条目，或把 `COM6` 留存周期目标下调到可支撑时长以内 |

- 结论态为缩范围推进时**必须**按 `FC5`~`FC8` 行生成缩范围后的主推路线，**严禁**沿用原目标值
- 降级路线**必须**重算 `FC1` 与 `FC3`，两者均成立才算生成成功
- 降级路线**必须**写出它砍掉了什么，**严禁**只写它还剩什么
- 降级动作涉及改写某段字段取值时**必须**交回该段执行，**严禁**在本段就地改写其他段的分册
- 降级路线仍无法过 `FC1` 或 `FC3` 时**必须**如实记为尝试失败，**严禁**再降一档凑出一个能过的形态

## 六、复活条件写法

被否决的每一项都配一条复活条件，格式固定如下。

```markdown
{判据编号}：{当前值} → 达到 {阈值} 时可重启
```

- 阈值**必须**是可观测的数值或可判定的事实，**严禁**写成方向性描述
- 每个未消解的硬否决项**必须**各有一条复活条件，**严禁**多项合并成一条

```markdown
<!-- ✅ 正确：判据编号、当前值、阈值三者齐备，可观测 -->
KO3：现金需求 {金额A} 元 > 可投预算 {金额B} 元 → 预算达到 {金额A} 元，或功能项砍到现金需求 ≤ {金额B} 元时可重启

<!-- ❌ 错误：方向性描述，无法判断什么时候算达到 -->
KO3：等预算宽裕一些、成本降下来以后可以再看
```

## 七、硬否决的当场明示格式

判定过程中命中硬否决项时，立即以下列四行输出，**严禁**等到结论态步骤再一起说。

```markdown
命中硬否决：{KO 编号} {否决项名}
判据：{算式编号或事实} = {当前值}，否决线 {阈值}
证据：{来源等级｜出处｜取证日期}
出口：A 调整 {具体哪一个前提} 后重算 ｜ B 直接出否决报告（含复活条件）
```

- 出口**必须**由用户选，**严禁**替用户选定其中任一个
- 明示**严禁**夹带安慰性措辞，「其实也可以试试看」这类表述出现即违规
- 用户选 A → 该前提改动后**必须**重算关联算式，命中即再次明示
- 用户选 B → 直接按第四节判定表取结论态

```markdown
<!-- ✅ 正确：判据带阈值与证据，两个出口都留给用户 -->
命中硬否决：KO2 获客成本吃掉全部价值
判据：FC2 CAC {金额A} ≥ LTV {金额B}，否决线 CAC < LTV
证据：【E2｜{渠道官方公示页}｜{取证日期}】
出口：A 调整「只投付费渠道」这一前提后重算 ｜ B 直接出否决报告（含复活条件）

<!-- ❌ 错误：夹带安慰性措辞，并替用户选了继续 -->
CAC 好像有点高，不过应该也还能试试，我们接着往下看别的。
```
