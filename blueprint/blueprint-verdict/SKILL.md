# 可行性裁决段（Blueprint Verdict）

> [!IMPORTANT] 路径解析基准
> 文档内相对路径引用一律以本 skill 根目录（`SKILL.md` 所在目录）为基准解析。

本段是 blueprint 流水线的**裁决段**，出手序恒为最后一位：把各段写进字段台账的取值当作唯一输入，算完算式、判完否决、取出结论态、收束路线。跨段的算式与否决项只有在本段才算得出来 —— 八条算式里七条的输入跨两个以上段，十一个否决项里六个同样跨段。本段**只**判定与收束，**不**追问字段、**不**改写其他段的分册。结论态包含「不做」，命中硬否决时当场告知。

## 适用与不适用

- ✅ **适用**：字段台账已存在且各段分册已交回 —— 算账、判否决、取结论态、比路线、给复活条件。
- ❌ **不适用**：字段台账不存在，或产品段字段全部未闭环 —— 改由 `blueprint-product` 起头，**严禁**在无输入时给结论。
- ❌ **不适用**：用户要的是把某个方面继续问深 —— 改由对应的单段 skill 承接，**严禁**在本段追问字段。

## 参数

| 参数 | 必填 | 说明 |
|------|------|------|
| `demand` | 是 | 原始诉求（用于分册标题摘要） |
| `slug` | 否 | 产物文件名片段，缺省 `idea`；由编排段生成并透传 |
| `outputDir` | 否 | 裁决分册与字段台账所在目录，缺省取当前工作目录 |
| `scope` | 否 | 档位，缺省 `full`；两档的判定表见 [feasibility-gate.md 第四节](references/feasibility-gate.md#四结论态判定表) |

## 公共约束

> [强约束] 总纲：只判定、只收束，不追问、不改写、不替用户拍板。账算不平就说不行，缺输入就记不可判定。

| # | 约束 | 违反后处理 |
|---|------|-----------|
| IBV1 | 判定前**必须**完整读取 [feasibility-gate.md](references/feasibility-gate.md)、[gate-check.md](references/gate-check.md)、[output-spec.md](references/output-spec.md)，**严禁**凭 SKILL.md 摘要或记忆判定 | 停止判定，先完整读取三份文件 |
| IBV2 | 每条算式的输入**必须**取字段台账所载取值，**严禁**改取分册正文或对话中的口述值 | 撤回该次计算，回台账取值重算 |
| IBV3 | [feasibility-gate.md 第二节](references/feasibility-gate.md#二一致性算式)的全部算式**必须**逐条算完，缺输入项的**必须**记为不可判定，**严禁**估一个数把账做平 | 停止裁决，补算或记为不可判定 |
| IBV4 | 命中 [feasibility-gate.md 第一节](references/feasibility-gate.md#一硬否决项)任一硬否决项时**必须**当场按第七节向用户明示该项与其判据，**严禁**只登记不告知就继续判定 | 立即停止判定，按第七节明示并请用户选出口 |
| IBV5 | 硬否决判定**必须**至少有一条 `E1` 或 `E2` 证据支撑，**严禁**仅凭 `E3`~`E6` 判死一个想法 | 撤回该否决，改记为不可判定 |
| IBV6 | 结论态**必须**按 [feasibility-gate.md 第四节](references/feasibility-gate.md#四结论态判定表)的判定表取值，**严禁**由模型另设判定依据或绕开该表直接判推进 | 回到判定表重取结论态 |
| IBV7 | [gate-check.md 第二节](references/gate-check.md#二非字段门禁项清单)的六项门禁**必须**逐条给出判定，**严禁**留空任一项 | 补齐该项判定后再取结论态 |
| IBV8 | 结论态为不做或转向时**必须**按 [feasibility-gate.md 第五节](references/feasibility-gate.md#五降级路线生成规则)给出降级路线，**严禁**只给否决结论而不给更小的可行形态 | 补出降级路线后重出 |
| IBV9 | `scope=full` 时**必须**输出 2 条及以上可横向对比的落地路线，**严禁**只给单一路线 | 补出候选路线与对比表后重出 |
| IBV10 | 主推路线**必须**由用户选定，**严禁**替用户拍板 | 撤回该选定，请用户选路线 |
| IBV11 | 需要改写其他段字段取值时**必须**交回编排段调对应段执行，**严禁**在本段就地改写其他段的分册 | 回滚该改写，改为交回编排段 |
| IBV12 | 索引回填**必须**只动结论节与分册索引节，**严禁**把算式、否决登记或路线对比抄进索引 | 撤回超范围回填内容 |
| IBV13 | `scope=screen` 时**必须**只取判定表 4.2 的三种结论态并逐条列出本档未判项，**严禁**判为推进、缩范围推进或转向 | 撤回超档结论，改按 4.2 重取 |
| IBV14 | 全局缺口与模型假设清单**必须**从字段台账逐条汇总，**严禁**从各段分册转抄 | 回台账重新汇总两份清单 |

## 核心流程

> [强约束] STEP 4~7 任一交互步骤中，用户主动叫停 → stderr + exitCode=1；`scope=screen` 时 STEP 5~7 的算式子集、否决项子集、结论态与产物形态一律按 [feasibility-gate.md](references/feasibility-gate.md)与 [output-spec.md 第一节](references/output-spec.md#一分册骨架)执行，**严禁**按 `full` 档的全集推进。

### STEP 1：参数校验

按标准校验顺序校验：
- **必填**：`demand`（缺失时不得报错退出，必须先向用户提问「要对哪件事出裁决结论？」，拿到回答后再进入下一步）
- **格式**：`slug`（匹配 `^[a-z0-9一-鿿-]{1,30}$`）
- **枚举**：`scope`（`screen` / `full`）
- **文件**：`{outputDir}/blueprint-{slug}.fields.json`
- **创建**：`outputDir`

任一校验失败 → stderr + exitCode=2

### STEP 2：读取本段规范

用 Read 工具完整读取 `references/co-create.md`、`references/feasibility-gate.md`、`references/gate-check.md`、`references/output-spec.md`，读完再进入下一步（遵循 IBV1）。

### STEP 3：读取字段台账与各段分册

读取 `{outputDir}/blueprint-{slug}.fields.json` 全部分区，再逐份读取 `{outputDir}` 下已存在的各段分册；台账缺失 → stderr + exitCode=2。分册缺席的段按 [gate-check.md 第二节](references/gate-check.md#二非字段门禁项清单)的 `CG1` 登记，**严禁**代该段补写取值。

### STEP 4：完整度门禁判定

按 [gate-check.md 第一节](references/gate-check.md#一台账读取与字段判定)把台账每个字段判为三态之一，按第二节逐条判定六项非字段门禁（遵循 IBV7），按 [第三节](references/gate-check.md#三模型假设占比的统计口径)算出【模型假设】占比，结果按第四节写入分册的完整度门禁节。

### STEP 5：算式与硬否决判定

按 [feasibility-gate.md 第二节](references/feasibility-gate.md#二一致性算式)逐条算完全部算式，输入一律取台账取值（遵循 IBV2、IBV3）；每条算式算完后立即判定其关联否决项，命中即按第七节当场明示并请用户选出口（遵循 IBV4、IBV5）；用户选 A 时按其改动重算关联算式，改动落在其他段字段上时交回编排段（遵循 IBV11）；用户在本段提出的关键前提需其他角色确认、本次对话内无法闭环 → stderr + exitCode=3。

### STEP 6：结论态、路线收束与降级路线

按 [feasibility-gate.md 第四节](references/feasibility-gate.md#四结论态判定表)取结论态并附判据编号（遵循 IBV6、IBV13）；`scope=full` 时按 [output-spec.md 第二节](references/output-spec.md#二候选路线对比与默认排序)产出 2~3 条候选路线并各按 feasibility-gate 第三节补齐作废条件与事前验尸（遵循 IBV9），请用户选定主推路线（遵循 IBV10）；结论态为不做或转向时按第五节生成降级路线并重算 `FC1` 与 `FC3`（遵循 IBV8）；每个未消解的硬否决项各配一条复活条件，格式取第六节。

### STEP 7：成文、索引回填与回显

按 [output-spec.md 第一节](references/output-spec.md#一分册骨架)建立裁决分册并按第三节写入结论、算式、否决登记与降级路线，按 [第四节](references/output-spec.md#四全局清单与索引回填)从台账汇总两份全局清单（遵循 IBV14）、回填索引（遵循 IBV12），再单独一行回显裁决分册的绝对路径。

## 输出规范

### 产物文件

| 文件 | 条件 | 路径 |
|------|------|------|
| 裁决分册 | 必产，STEP 7 建立 | `{outputDir}/blueprint-{slug}-verdict.md` |
| 索引回填 | 索引文件已存在时必产 | `{outputDir}/blueprint-{slug}.md` |
| 对话内结论态 | 必产 | 直接输出到对话 |

> [强约束] `{slug}` 由编排段生成并透传，本段**必须**按 STEP 1 的格式校验逐字取用该参数值，**严禁**将 `demand` 原文拼入文件名，**严禁**在本段另行改写 `{slug}`。

```markdown
<!-- ✅ 正确：逐字取用透传的 slug -->
slug=做一个-roguelike-小游戏 → blueprint-做一个-roguelike-小游戏-verdict.md
<!-- ❌ 错误：把 demand 原文拼入，空格与全角括号进入文件名，产出跨平台不可用的路径 -->
blueprint-做一个 Roguelike 小游戏（手机端）-verdict.md
```

### 退出码

本技能在对话模式下运行，无进程退出码。每次结束（含中途终止）**必须**在输出末尾单独打印一行 `状态：{含义}（exitCode={N}）` 供上层判定。

| exitCode | 含义 | 触发场景 | 后续动作 |
|---------|------|---------|-----------|
| 0 | 裁决完成（含判为不做） | 完成 STEP 7 并回显裁决分册路径 | 按主推路线执行，或按复活条件重启 |
| 1 | 中途终止（可重试） | 用户主动叫停 | 询问用户：继续裁决 / 终止 |
| 2 | 输入异常（不可重试） | `slug` 格式非法；`scope` 取值非法；字段台账不存在；`outputDir` 无法创建 | 提示用户先跑共创各段或修正参数 |
| 3 | 需人工决策 | 用户提出的关键前提需其他角色确认、本次对话内无法闭环 | 交回待确认清单，由用户安排确认 |

### stderr 格式（JSONL，单行）

```jsonl
{"message":"...","detail":"...","hint":"..."}
```

字段约束：
- `message` 必填，自由文本，简洁单行
- `detail` 可选，多行文本（保留原始错误信息）
- `hint` 可选，给用户的修复提示

## 危险信号（Red Flags）

以下可观测信号表明执行出现偏差，出现任一项必须回退修正：

- RF-IBV1: 判定已开始，三份判据文件中存在从未被读取的文件
- RF-IBV2: 某条算式的输入取值在字段台账中找不到对应记录
- RF-IBV3: 结论态已给出，而算式表中存在既无计算结果、也未记为不可判定的条目
- RF-IBV4: 否决登记里有硬否决项，而判定过程中从未向用户明示过该项
- RF-IBV5: 某个硬否决项的证据列全部为 `E3`~`E6`
- RF-IBV6: 存在未消解的硬否决项，结论态却写成推进
- RF-IBV7: 完整度门禁节里六项非字段门禁中存在无判定的项
- RF-IBV8: 结论态为不做或转向，输出里找不到降级路线
- RF-IBV9: `scope=full`，候选路线对比表只有一行
- RF-IBV10: 某条路线被标为主推，对话中用户从未选定过它
- RF-IBV11: 某个其他段的分册文件在本段执行期间被改写
- RF-IBV12: 索引里出现算式行、否决登记表或候选路线对比表
- RF-IBV13: `scope=screen`，结论态写成推进、缩范围推进或转向
- RF-IBV14: 全局缺口表里的某一行在字段台账中找不到对应记录

## 反合理化（Anti-Rationalization）

| 借口 | 反驳 |
|------|------|
| "算式缺一个输入，我按经验估个数把账做平" | 把账做平的估值等于伪造结论。缺输入就记不可判定，让缺口自己说话。 |
| "台账里的数看着不太对，我按分册正文里的写法算" | 台账是各段按取证规则写下的唯一事实源。改取正文等于绕开来源等级标注。 |
| "用户看起来很兴奋，先别说不行，免得打击他" | 让他花三个月做一件账算不平的事才是真正的打击。现在说清楚，他还有改前提的机会。 |
| "只给一条最优路线更利落，多路线会让用户犹豫" | 单路线剥夺了用户的选择权，也掩盖了这条路线成立所依赖的前提。 |
| "这个字段该段没问到，我顺手补一个合理取值" | 补上的取值没有经过该段的闭环判据与取证要求。记为未通过并交回该段，账才可复核。 |
| "结论态是不做，路线和降级就不用写了" | 不做也要给出更小的可行形态与复活条件，否则用户只拿到一个「否」，不知道改什么。 |
