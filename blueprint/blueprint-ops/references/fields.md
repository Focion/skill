# 实施段字段清单

本文件为 `blueprint-ops` 段提供本段的待闭环字段、闭环判据、追问句式、空洞回答的追加问法、必核字段、上游锚点与档位子集。候选生成规则、处置分类、来源等级、发散手法与单轮输出格式以 [co-create.md](references/co-create.md)为唯一来源，本文件**严禁**复述。

本段字段总数为 7，`scope=screen` 时为 2，单轮输出的完整度分母**必须**按当前 `scope` 取对应数，**严禁**另取。

---

## 一、本段字段清单

| 字段 | 要拿到的东西 | 闭环判据 | 追问句式 |
|------|------------|---------|---------|
| `OPS1` | MVP 范围与验收标准 | 取值型：一句可判定的验收句 | 第一版做到什么程度算能交？用一句能判定真假的话说出来。 |
| `OPS2` | 里程碑与时间表 | 计数型：各里程碑的日期或周数 | 从今天算，第一个可给别人看的版本要几周？中间设几个检查点？ |
| `OPS3` | 人力与角色分工 | 枚举型：角色清单 + 每个角色的承担人 | 这件事需要哪几种角色？每个角色现在谁来做？哪个角色空着？ |
| `OPS4` | 预算与资金来源 | 计数型：总预算 + 资金来源 | 到第一版上线要花多少钱？这笔钱现在在谁手里？ |
| `OPS5` | 度量指标 | 枚举型：选定的指标 + 各自的目标值 | 上线后看哪几个数？多少算成功，多少算该停？ |
| `OPS6` | 合规、许可与风险预案 | 枚举型：合规项清单 + 每项的应对动作 | 涉及版权、资质、平台规则、个人信息中的哪几项？各自打算怎么处理？ |
| `OPS7` | 可投工时 | 计数型：每周可投入的小时数 | 这件事你每周能真正投进去几个小时？连续投几周不会断？ |

- 本表为**封闭清单**，**必须**逐字取用，**严禁**在本段追问本表之外的字段编号
- `OPS1` 的验收句**必须**写成走通产品分册端到端切片的判定句，**严禁**写成「基本可用」这类不可判定的表述
- `OPS2` 的每个里程碑**必须**各带日期或周数，**严禁**写「有空就做」这类无时点的表述
- `OPS2`、`OPS4`、`OPS7` 的取值**必须**带单位写入字段台账，**严禁**只写在分册正文 —— 裁决段的工时与现金算式读的是台账
- `OPS3` 的每个角色**必须**各写出承担人，角色空缺时**必须**写「空缺」并附替代安排，**严禁**留空该列

## 二、空洞回答与追加问法

| 空洞回答 | 追加问法 |
|---------|---------|
| 「有空就做，不设时间」 | 那设一个放弃线：到哪一天还没做出可给人看的版本，就判定这件事停掉？ |
| 「我一个人全干」 | 把角色列出来对一遍：设计、开发、内容、推广、客服，哪一个是你最不擅长的？那一项谁来？ |
| 「上线了再看数据」 | 现在就定：哪个数上不去就说明方向错了？这个数从哪里读？ |
| 「预算不好说，能省就省」 | 到第一版上线之前必须付出去的钱有哪几笔？加起来的上限是多少？ |
| 「合规应该没问题」 | 逐项对一遍：版权素材、资质要求、平台上架规则、个人信息，哪几项适用？各自谁去确认？ |

- 用户的回答命中本表任一行时**必须**发出对应的追加问法，**严禁**把空洞回答记为【已确认】

## 三、本段必核字段

下列字段**必须**联网取证，**严禁**以模型记忆中的数据代替。

| 字段 | 要核的事实 | 检索方向 |
|------|----------|---------|
| `OPS4` | 该品类同规模项目的公开投入量级 | 公开行研、同类项目复盘文 |
| `OPS6` | 资质、上架审核与个人信息合规要求 | 主管部门与平台官方文档 |

- 取证记录的形态与取不到时的处置以 [co-create.md 第六节](references/co-create.md#六取证记录与取不到时的处置)为唯一来源
- `OPS6` 存在取证后确认适用而用户无对应资质的项时**必须**在分册中原样记录并交由裁决段判定，**严禁**在本段给出否决结论
- 用户给的预算与取到的 `E1` 或 `E2` 公开量级差异达到 2 倍时**必须**把两个数并列摆出请用户确认，**严禁**默默采用用户那一个

## 四、上游锚点与档位子集

追问本段字段之前**必须**先读字段台账的下列上游取值，**严禁**在未读台账时开始追问。

| 台账字段 | 本段用它做什么 |
|---------|-------------|
| `RQ5` | 逐条比对本段取值有无与硬约束直接冲突 |
| `RQ8` | `OPS3` 的角色清单**必须**含拍板人与否决人 |
| `PRD9` | `OPS1` 的验收句写成走通该切片的判定句 |
| `PRD4` | `OPS2` 的里程碑周数引用内容工时合计 |
| `PRD11` | `OPS2` 第一个里程碑的交付物就是核心体验验证动作 |
| `PRD7` | `OPS5` 的度量指标读状态或阶段序列中的某一节点 |
| `PRD8` | `OPS6` 的合规项覆盖失败情形清单里的高风险情形 |
| `TEC1` | `OPS2` 的里程碑周数引用功能项估时合计 |
| `TEC5` | `OPS4` 的现金需求含依赖费用 |
| `GRW4` | `OPS4` 的现金需求含首批推广投入 |

- 字段台账不存在时**必须**先新建台账、追问 `RQ2` 与 `RQ4` 两项并写入，**严禁**在产物类型未确定时开始本段追问
- 台账缺 `PRD` 分区时**必须**把本表所列上游 `PRD` 字段全部标为【缺口】，并在分册首行下方写出「本册未经产品方案锚定」一行，**严禁**凭模型代填的产品方案往下算
- 台账缺 `TEC` 或 `GRW` 分区时**必须**在 `OPS4` 的取值上标注缺哪一项输入，**严禁**按零计入现金需求
- 用户在本段改写了上游字段取值时**必须**把该改写回读并交回编排段，**严禁**在本段就地改写上游分册

`scope=screen` 时本段字段子集固定为下列两项，**必须**逐字取用，**严禁**增删条目。

| 字段 | 本档为什么要它 |
|------|-------------|
| `OPS4` | 可投预算是本档现金需求算式的对照值 |
| `OPS7` | 可投工时是本档工时算式的对照值 |

- 子集外的字段在本档**必须**记为【不适用】并附「本档不问」一句，**严禁**标为【缺口】
- 本档**必须**照常执行第三节中 `OPS4` 的取证要求，**严禁**以「只是快筛」为由跳过
