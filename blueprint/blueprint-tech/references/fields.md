# 技术段字段清单

本文件为 `blueprint-tech` 段提供本段的待闭环字段、闭环判据、追问句式、空洞回答的追加问法、必核字段、上游锚点与档位子集。候选生成规则、处置分类、来源等级、发散手法与单轮输出格式以 [co-create.md](references/co-create.md)为唯一来源，本文件**严禁**复述。

本段字段总数为 5，`scope=screen` 时为 3，单轮输出的完整度分母**必须**按当前 `scope` 取对应数，**严禁**另取。

---

## 一、本段字段清单

| 字段 | 要拿到的东西 | 闭环判据 | 追问句式 |
|------|------------|---------|---------|
| `TEC1` | 功能边界 | 枚举型：第一版做的功能项 + 明确不做的功能项 | 第一版必须有哪几个功能？哪些功能你现在就决定不做？ |
| `TEC2` | 技术选型与架构 | 枚举型：选定的端 + 选定的技术栈 | 跑在哪（网页、手机、桌面、机器人）？用什么栈实现？ |
| `TEC3` | 数据与状态 | 枚举型：要持久化的数据项 | 要存下哪些数据？存在本地还是服务端？涉及个人信息吗？ |
| `TEC4` | 关键难点与验证方式 | 取值型：最可能做不出来的那一处 + 一个可先跑的验证动作 | 整件事里最可能卡住的是哪一块？用什么最小实验能在几天内证明它可行？ |
| `TEC5` | 依赖与外部资源 | 枚举型：第三方服务、素材与许可清单 | 要用到哪些第三方服务、素材或模型？授权与费用清楚了吗？ |

- 本表为**封闭清单**，**必须**逐字取用，**严禁**在本段追问本表之外的字段编号
- `TEC1` 的功能项**必须**逐条对应产品分册 `PRD3` 清单中的条目，**严禁**另起一套功能命名
- `TEC4` 的验证动作**必须**含验证载体、通过判据与耗时三项，缺任一项即该字段未闭环
- `TEC4` 验证的是「能不能被做出来」，与产品段验证「核心体验成不成立」两回事，**必须**分别追问，**严禁**互相顶替
- `TEC5` 的每一项依赖**必须**带费用与许可条件写入字段台账，**严禁**只写依赖名 —— 裁决段的现金需求算式读的是台账

## 二、空洞回答与追加问法

| 空洞回答 | 追加问法 |
|---------|---------|
| 「技术上都能实现」 | 那把最难的一块单独拎出来：它的输入输出是什么？你上次做类似的花了多久？ |
| 「用 AI 生成就行」 | 生成的东西谁来验收？验收不通过的比例多高时这条路就不成立？ |
| 「先全都做出来再说」 | 按你现在能投入的时间，第一版只能做几个功能？哪一个功能拿掉后产品就不成立？ |
| 「依赖的服务都免费」 | 免费额度是多少、超出之后单价多少？许可条款允许商用吗？ |
| 「数据先存本地，以后再迁」 | 迁的时候谁来做、要几天？涉及个人信息时本地存放要满足哪一条要求？ |

- 用户的回答命中本表任一行时**必须**发出对应的追加问法，**严禁**把空洞回答记为【已确认】

## 三、本段必核字段

下列字段**必须**联网取证，**严禁**以模型记忆中的数据代替。

| 字段 | 要核的事实 | 检索方向 |
|------|----------|---------|
| `TEC5` | 第三方依赖的费用与许可条件 | 官方许可与定价页 |

- 取证记录的形态与取不到时的处置以 [co-create.md 第六节](references/co-create.md#六取证记录与取不到时的处置)为唯一来源
- 免费额度与超额单价**必须**分别取证并各自记出处，**严禁**只记一句「有免费额度」
- 许可条款禁止本诉求所需用途时**必须**在分册中原样记录该条款并交由裁决段判定，**严禁**在本段给出否决结论

## 四、上游锚点与档位子集

追问本段字段之前**必须**先读字段台账的下列上游取值，**严禁**在未读台账时开始追问。

| 台账字段 | 本段用它做什么 |
|---------|-------------|
| `RQ5` | 逐条比对本段取值有无与硬约束直接冲突 |
| `RQ6` | `TEC2` 的选型优先落在用户已有的技能与代码资产上 |
| `PRD3` | `TEC1` 的功能项与 `TEC5` 的依赖清单逐条对应第一版条目 |
| `PRD5` | `TEC4` 的难点优先落在规则与数值最复杂的那一条上 |
| `PRD8` | `TEC4` 与 `TEC3` 覆盖失败情形清单里的高风险情形 |
| `PRD9` | `TEC1` 的第一版功能项**必须**覆盖端到端切片的每一步 |

- 字段台账不存在时**必须**先新建台账、追问 `RQ2` 与 `RQ4` 两项并写入，**严禁**在产物类型未确定时开始本段追问
- 台账缺 `PRD` 分区时**必须**把本表所列上游 `PRD` 字段全部标为【缺口】，并在分册首行下方写出「本册未经产品方案锚定」一行，**严禁**凭模型代填的产品方案往下算
- 切片某一步所需的条目既不在 `PRD3` 清单、也不在 `TEC1` 第一版功能项内时**必须**在分册中逐条标出该条目名并交由裁决段判定，**严禁**在本段给出否决结论
- 用户在本段改写了上游 `PRD` 字段取值时**必须**把该改写回读并交回编排段，**严禁**在本段就地改写产品分册

`scope=screen` 时本段字段子集固定为下列三项，**必须**逐字取用，**严禁**增删条目。

| 字段 | 本档为什么要它 |
|------|-------------|
| `TEC1` | 功能边界是本档工时算式的输入 |
| `TEC4` | 关键难点验证失败时本档即可判死 |
| `TEC5` | 依赖费用与许可是本档现金需求算式的输入 |

- 子集外的字段在本档**必须**记为【不适用】并附「本档不问」一句，**严禁**标为【缺口】
- 本档**必须**照常执行第三节的取证要求，**严禁**以「只是快筛」为由跳过
