# 约束书写规范

本文件定义所有 SKILL 文档中约束条件的书写格式。

## 规则

### 1. 约束章节标题

使用 `## 公共约束` 作为章节标题（h2）。禁止使用 `## 核心约束`、`## 约束` 等变体。

```markdown
## 公共约束
```

### 2. 约束表格格式

约束条目**必须**以 Markdown 表格承载，列**固定为三列且顺序不可变**：`#`（编号）、`约束`（描述）、`违反后处理`。**禁止增删列**。完整示例参见规则 8。

### 3. 编号格式

约束编号使用 **大写英文字母前缀 + 阿拉伯数字**，同一章节内连续递增。

前缀为 1~3 个大写英文字母，从 Skill 名称中取有意义的缩写。同一章节内编号连续递增，从 `1` 开始。

| 前缀长度 | 适用场景 | 示例 |
|----------|---------|------|
| 单字母 | 通用/顶层约束 | `G1`（General）、`M1`（Main） |
| 双字母 | Skill 特有约束（推荐） | `EX1`（Extract）、`RS1`（Research）、`PG1`（Program）、`VD1`（Validate） |
| 三字母 | 名称易冲突时使用 | `SCR1`（Score） |

前缀的重复禁令拆为下列两条，每条只对应一个判定动作：

- 编号前缀**必须**保证同仓库唯一，出现与其他 Skill 相同的约束前缀即违规
- 编号前缀**严禁**与检查/审查类 Skill 的检查项 ID 前缀重复，出现重复即违规

拆分理由：两套 ID 混在同一份报告里将无法区分「被检出的约束」与「检查项本身」；合并成一条时报告只能给出一条违规，无法指明撞的是别的约束前缀还是检查项 ID 前缀。选定前缀前需先核对同仓库内全部约束前缀与全部检查项 ID 前缀两个集合。

**前缀命名参考**：

| Skill 名称 | 推荐前缀 |
|---|---|
| my-checker | MC |
| data-transform | DT |
| code-review | CR |

### 4. 约束描述书写要求

每条约束必须满足以下三项，每项均给出客观判据：

**单一职责**：一条约束只描述一个限制，不合并多个独立约束。

- 客观判据：单条约束描述中**严禁**出现 `且`、`同时`、`并且` 连接两个独立的祈使或禁止。（连接同一动作的修饰成分不在此列，如「必须保留原始内容且不改变顺序」中两者指向同一写入动作。）

**可判定**：描述必须明确到可客观判断是否违反。

- 客观判据：描述中**严禁**出现模糊词封闭表中的任一词。
- 模糊词封闭表（**封闭列表**，不得增补也不得裁剪）与其命中排除判据，以 [organization.md 规则 9](references/organization.md#9-规范条目的可判定性) 原文为唯一来源；本文件**严禁**自留副本。

**正面陈述 + 反面强调**：先写「必须怎样」，再用 `**粗体**` 标注「严禁什么」。

- 客观判据：描述**必须**同时包含强制词（`必须` / `应`）与禁止词（`严禁` / `禁止`），且禁止词所在片段被 `**` 包裹。

```markdown
<!-- ✅ 正确 -->
| G5 | 必须通过子代理产出代码，**严禁自行编写** | — |

<!-- ❌ 错误：不可判定，命中模糊词封闭表中的「尽量」 -->
| G5 | 尽量不要自己写代码 | — |

<!-- ❌ 错误：违反单一职责，「且」连接了两个独立禁止 -->
| G5 | **严禁**自行编写代码且**严禁**直接读取状态 | — |

<!-- ❌ 错误：缺强制词，且禁止词未被 ** 包裹 -->
| G5 | 严禁自行编写代码 | — |
```

### 5. 违反后处理列

描述违反约束后的**即时动作**（非惩罚），格式为简短祈使句：

| 写法 | 适用场景 |
|------|---------|
| `立即暂停，等待{角色}` | 需要人工介入 |
| `转发后等待{角色}指示` | 信息传递后等待决策 |
| `拒绝执行并提醒{角色}` | 阻断非法操作 |
| `立即回滚并使用原始内容重新写入` | 数据污染修复 |
| `阻断并向{角色}询问` | 缺少必要输入 |
| `—` | 无特殊处理（靠流程自身兜底） |

### 6. 强调标记

约束描述中需要突出的关键词使用 `**粗体**` 标记。

- 客观判据：每条约束的 `约束` 列描述中**必须**至少含一处 `**…**` 包裹，无任何粗体标记即违规。

```markdown
<!-- ✅ 正确 -->
| G9 | 写入内容**必须保留原始输入，严禁压缩、缩写、摘要、改写或以任何方式修改** | 立即回滚 |

<!-- ❌ 错误：全文无粗体标记 -->
| G9 | 写入内容必须保留原始输入，严禁改写 | 立即回滚 |
```

### 7. 引用块约束（补充格式）

当约束需要脱离表格、在流程步骤中内联声明时，使用 `> [强约束]` 引用块前缀：

```markdown
> [强约束] **总纲：只搬运、只整理、不发散、不评判。**
```

引用块约束不编号，仅用于对表格约束的**就近提醒**或**总纲声明**。

### 8. 完整示例

```markdown
## 公共约束

| # | 约束 | 违反后处理 |
|---|------|-----------|
| G1 | 所有确认点必须等审批人批复，**严禁擅自决策** | 立即暂停，等待审批人 |
| G2 | 子代理汇报的错误必须原样转发审批人，**严禁自行加工** | 转发后等待审批人指示 |
| G3 | 阶段必须按声明顺序执行，**严禁跳过、合并或并行** | 拒绝执行并提醒审批人 |
| G4 | 每阶段产出文档必须验证齐全后再通知审批人，**严禁未验证即通知** | 立即终止流程 |
| G5 | 代码必须通过子代理产出，**严禁自行编写** | — |
```

## 禁止事项

| 禁止 | 原因 | 正确写法 |
|------|------|---------|
| 无前缀纯数字编号（`1.`、`2.`） | 与步骤列表和有序列表冲突 | `G1`、`EX1` |
| 中文编号（`一、`、`（一）`） | 不利于机器解析和跨文档引用 | `RS1`、`PG1` |
| 超过 3 个字母的前缀（如 `PROG1`） | 过长，影响表格可读性 | `PG1` |
| 前缀使用小写字母（如 `ex1`） | 与正文混淆，不醒目 | `EX1` |
| 模糊措辞（命中规则 4 所引用的模糊词封闭表） | 约束必须可判定 | `必须`、`严禁`、`禁止` |
| 单条约束混入多个独立限制 | 违反单一职责，难以单独引用 | 拆分为多条 |
| 约束散落在正文各处无统一章节 | 不易检索，维护困难 | 集中在 `## 公共约束` 章节 |
| 违反后处理写惩罚而非动作 | 约束面向 Agent 执行，需要可执行指令 | 写即时动作（暂停/回滚/阻断） |

**编号类禁止项的作用域**：上表中「无前缀纯数字编号」与「中文编号」两项**仅**作用于约束表格的 `#` 列。章节标题自身的序号（如 `### 一、约束总览`、`### 1. 约束章节标题`）以及正文中的普通有序列表**不在此列**，**严禁**据此判定为违规。

## 跨 Skill 引用

当某 Skill 需要引用另一文件中已定义的约束时，使用 Markdown 链接 + 编号引用：

```markdown
遵循 [common-flow.md 公共约束 G1-G10](references/common-flow.md#公共约束)，本 Skill 额外约束如下：
```

### 约束继承规则

- 子文件可**追加**约束（使用不冲突的编号前缀），不可**覆盖**父文件约束
- 冲突时以层级更高的文件（更靠近仓库根目录）为准
