# 文档组织与写法规范（Documentation Organization Guide）

本文件定义一个 Skill 全部文档（`SKILL.md` 与 `references/*.md`）的组织方式、写法与可判定性要求。

与 [basic.md](references/basic.md) 的分工：

- [basic.md](references/basic.md) 管**单个 `SKILL.md` 内部的结构与格式**——frontmatter 字段、章节构成、表格列结构、流程步骤编号
- 本文件管**跨文件的文档组织与写法**——目录结构、渐进式披露、链接基准、免责声明禁令、检查对象范围、脚本与指令取舍、示例书写、条目可判定性

本文件是 [basic.md](references/basic.md) 在文首声明引用的子规范之一；两者冲突时以 [basic.md](references/basic.md) 优先。

## 规则

### 1. 目录结构

一个 Skill 的目录结构固定为以下四项，**严禁**新增同级目录：

| 路径 | 职责 |
|------|------|
| `SKILL.md` | 唯一入口，描述「何时做什么 + 去哪读细节」 |
| `references/*.md` | 按需加载的规范与知识，由 `SKILL.md` 显式指引读取 |
| `scripts/*` | 可执行脚本 |
| `assets/*` | 模板与静态资源 |

`references/` 下的文件名必须为小写 kebab-case + `.md` 后缀，一个文件承载一个主题。**严禁**使用 `misc.md`、`other.md`、`common.md` 这类无主题的聚合命名——聚合文件必然被写成大杂烩，导致每次都要整份加载。

```
<!-- ✅ 正确 -->
references/constraint.md
references/error-handling.md

<!-- ❌ 错误：无主题聚合命名 -->
references/misc.md
references/other-rules.md
```

### 2. 渐进式披露

- `SKILL.md` 单文件**不得超过 200 行**；判定依据、字段清单、格式细则等全部下沉到 `references/`
- 单个 `references/*.md` **不得超过 500 行**；超出必须按主题拆分为多个文件
- 引用另一份文档的判定依据时，引用方**只允许**写「检查项/步骤名 + 指向被引用文档的锚点」；判定标准与操作细节以被引用文档原文为**唯一来源**
- **严禁**把被引用文档中的判定依据或操作细节复制、摘录或压缩一份写进引用方
- 上两条的适用范围**不限于** `SKILL.md` → `references/` 方向：`references/*.md` 之间的互相引用、以及任一文档声明「遵循 / 依赖另一文档」的场合同样逐字适用（含 [basic.md](references/basic.md) 与其在文首声明引用的各子规范之间，本文件亦在其列），**严禁**以「引用方本身也是 reference」为由排除适用
- 客观判据：引用方承载该检查项的单元格或列表项中，**严禁**出现被引用文档原文的判定要素——列数、枚举值、正则、封闭词表、数值阈值、格式模板串；只允许出现检查项名与锚点链接

复制禁令的理由必须被理解而非仅被遵守：双份内容必然随维护而漂移，届时无法判断哪一份有效；更严重的是，引用方里只要存在一份压缩版判定依据，Agent 就会认为已获得足够信息而不再打开被引用文档，渐进式披露反向失效——加载的信息量变少了，但错误率上升了。

```markdown
<!-- ✅ 正确：只给检查项名 + 锚点 -->
| 检查项 | 依据 |
|--------|------|
| 约束表格列结构 | [constraint.md 规则 2](references/constraint.md#2-约束表格格式) |

<!-- ❌ 错误：把被引用文档的判定标准压缩一份写进引用方 -->
| 检查项 | 判定标准 |
|--------|---------|
| {检查项名} | 必须为 {N} 列且列序固定为 {列名清单}，缺列或换序即违规 |
```

### 3. 声明不等于指令

凡 `SKILL.md` 声明「必须对照 reference 原文执行/判定」的，其核心流程中**必须存在一个显式的读取步骤**（如 `### STEP 2：读取规范原文`，正文列出待读文件路径清单）。

**严禁**仅在文档开头写一句「本 Skill 依据 `references/xxx.md` 执行」就视为已满足——那是一条声明，不是一条指令；Agent 不会为一句背景描述产生读取动作。

### 4. 相对链接

- `SKILL.md` 中出现的每一个相对链接，其目标文件必须真实存在，**严禁**死链
- 相对链接一律以 skill 根目录（`SKILL.md` 所在目录）为基准书写，如 `references/constraint.md`
- `references/` 内文件之间的互相引用同样以 skill 根目录为基准，**严禁**写成同目录相对形式

```markdown
<!-- ✅ 正确：references/a.md 引用 references/b.md -->
详见 [b.md](references/b.md)

<!-- ❌ 错误：以当前文件所在目录为基准 -->
详见 [b.md](./b.md)
```

### 5. reference 不得含免责/豁免声明

作为**判定依据**被引用的 `references/*.md`，**严禁**包含面向执行者的免责或豁免声明。

**客观判据**：文件中出现下列封闭禁止词表里的任一字符串即违规（字符串命中的统计范围见 [6](#6-检查对象范围)）。

```text
可自行判断  视情况  酌情  仅供参考  权衡取舍  按需取舍  不强制  非强制  选择性遵循  琐碎任务  简单场景可
```

**唯一例外**：命中串所在引用块内同时出现 `作为**执行准则**时` 与 `作为**检查依据**时` 两个身份限定串（写法见下方正例）时不计违规；缺任一身份限定串即回落为违规。

理由：判定依据一旦含有豁免条款，该条款就是 Agent 跳过全部判定的合法逃逸口——任何任务都可以被自我论证为「琐碎」。

若原文确实需要保留权衡说明，**必须**显式区分两种引用身份：

```markdown
<!-- ✅ 正确 -->
> 本文件作为**执行准则**时，下列条目可结合成本权衡取舍；
> 作为**检查依据**时逐条适用，严禁以任务琐碎、场景简单为由跳过判定或将违规降格为提示。

<!-- ❌ 错误：无身份区分的豁免声明 -->
> 以下规则视任务复杂度酌情适用，琐碎任务可自行判断。
```

### 6. 检查对象范围

本文件与 [basic.md](references/basic.md) 各条目的作用对象逐条归属如下（未带文件名前缀的 `§N` 指本文件章节）。**严禁**对表中未列入的条目自行推断作用对象。

| 条目 | 作用对象 |
|------|---------|
| basic.md §1（含 1.1）、§2、§3、§4、§5、§6、§7、§8 | `SKILL.md` |
| §1 目录结构四项 | skill 根目录 |
| §1 `references/` 文件命名要求 | `references/*.md` |
| §2 `SKILL.md` 200 行上限 | `SKILL.md` |
| §2 单文件 500 行上限 | `references/*.md` |
| §2 引用不得复述判定依据 | `SKILL.md` 与 `references/*.md` |
| §3 声明不等于指令 | `SKILL.md` |
| §4 相对链接基准与死链 | `SKILL.md` 与 `references/*.md` |
| §5 免责 / 豁免声明禁令 | `references/*.md` |
| §6 本节 | 检查器自身 |
| §7 脚本与指令的取舍 | `SKILL.md` |
| §8 示例书写要求 | `SKILL.md` 与 `references/*.md` |
| §9 规范条目的可判定性 | `references/*.md` |

**检查器责任边界**：

- 检查对象**必须**包含被检 skill 的 `SKILL.md`
- 检查对象**必须**包含该 skill `references/` 目录下的全部 `.md` 文件，含未被 `SKILL.md` 链接引用的文件
- **严禁**把 `SKILL.md` 作为唯一检查对象：只检查 `SKILL.md` 的结果一律判为「检查不完整」，不得给出合规结论
- 检查报告**必须**逐条列出实际检查过的文件路径；清单缺少任一 `references/*.md` 即判为检查不完整
- **例外**：检查器可提供显式的部分检查档位（如仅检查 `SKILL.md`），该档位**必须**在报告开头声明本次检查不完整；未声明即回落为上一条的违规
- 部分检查档位的结论**严禁**写为「合规」，写为「合规」即违规

**字符串命中的统计范围**：分下列 A、B 两类，各自适用范围互斥。**严禁**把任一类的范围当作通则套用到另一类。

| 类别 | 适用条目（封闭清单） | 统计范围 |
|------|--------------------|---------|
| A 类 | 仅 §5 禁止词表、§9 模糊词封闭表、§9 主观形容词封闭表、§9 的 S3 判据合并形态，共四处 | 一律只统计围栏代码块（```` ``` ```` 包裹）之外的文本——正例、反例与词表本体不参与命中判定 |
| B 类 | §8 的正反例注释标记、`{占位符}`、表头一致性、示例行一致性 | **必须**照常统计围栏代码块之内的文本，围栏内外均计入 |

- A 类的「只统计围栏外」**严禁**外推到 A 类清单之外的任何条目
- §8 的检查对象（`<!-- ✅ 正确 -->` / `<!-- ❌ 错误：{原因} -->` 标记、`{占位符}`、示例表格的表头与示例行）绝大多数写在 ```` ```markdown ```` 围栏内部；跳过围栏内文本会使 §8 对文件的检查全程空转，等于该节失效

**跨条目命中去重**：同一字符串同时命中 §5 禁止词表与 §9 模糊词封闭表时（交集词见下方封闭清单），**必须**只按 §5 判定一次违规，**严禁**在两个条目下各计一次，否则统计数大于实际问题数。

```text
两表交集词：酌情  视情况
```

### 7. 脚本与指令的取舍

同一操作在 `scripts/` 与 `SKILL.md` 正文之间**只能存在一份实现**，**严禁**脚本与指令各写一份。

| 操作性质 | 承载形式 | 示例 |
|---------|---------|------|
| 确定性、可重复、无需判断 | 必须落到 `scripts/`，`SKILL.md` 只写调用方式与参数 | 数据查询、格式转换、批量校验、文件收集 |
| 需要语义判断 | 必须写成指令（自然语言步骤） | 合规判定、文案改写、根因分析、优先级排序 |

- 属于第一类的操作**严禁**在 `SKILL.md` 中展开为逐步自然语言描述——那是让 Agent 每次手工重演一段本应固化的逻辑，结果不可重复
- 属于第二类的判断**严禁**用脚本硬编码——关键词匹配无法替代语义判断，只会产生大量假阳性与假阴性
- 脚本的调用方式在 `SKILL.md` 中只写一行命令与参数含义，脚本内部实现细节不得复述

```markdown
<!-- ✅ 正确 -->
### STEP 3：收集待检文件
执行 `scripts/collect.sh {targetDir}`，输出为待检文件路径列表（每行一条）。

<!-- ❌ 错误：确定性操作写成自然语言步骤 -->
### STEP 3：收集待检文件
遍历目录下所有文件，跳过隐藏文件与二进制文件，按修改时间排序后逐个记录路径……
```

### 8. 示例书写要求

- 涉及格式约定的规则**必须**给出正例
- 涉及易错点的规则**必须**给出反例
- 反例**必须**标注违规原因
- 正反例统一使用注释标记：`<!-- ✅ 正确 -->` / `<!-- ❌ 错误：{原因} -->`，**严禁**只写「错误」而不写原因
- 示例中**严禁**出现具体业务系统名、真实路径、真实 ID、真实人名；统一使用 `{占位符}` 或通用示例（如 `{taskId}`、`example-skill`、`/path/to/dir`）

**表头一致性**：同一份文档内描述同一事物的表格，表头必须完全一致（列名、列数、列序三者均一致）。**严禁**在 A 处定义 4 列、B 处的输出模板却用 5 列——Agent 会以最后见到的表头为准生成产物，与检查逻辑对不上。

```markdown
<!-- ✅ 正确：定义与模板列结构一致 -->
定义： | 列A | 列B | 列C |
模板： | 列A | 列B | 列C |

<!-- ❌ 错误：模板多出一列 -->
定义： | 列A | 列B | 列C |
模板： | 列A | 列B | 列C | 列D |
```

**示例行一致性**：同类表格若带示例行（表头下方的样例数据），必须**全部带**或**全部不带**，**严禁**混用。原因：部分带示例行时，Agent 无法区分示例行是格式演示还是必填内容，会把示例行原样抄进产物。

### 9. 规范条目的可判定性

规范条目必须可机械判定——即仅凭文本本身即可给出「符合 / 违规」的确定结论。

**不可机械判定的客观信号**：一条规范条目（单个列表项、单个表格单元格或单个段落）命中下列任一信号即判定为不可机械判定，违反本节（字符串命中的统计范围见 [6](#6-检查对象范围)）。

| 信号 | 判据 |
|------|------|
| S1 模糊词 | 条目内出现模糊词封闭表中的任一词 |
| S2 主观判断 | 条目内出现主观形容词封闭表中的任一串 |
| S3 判据合并 | 条目内出现 `且` / `同时` / `并且` 之一，而该连接词左右两侧各含 `必须` / `严禁` / `不得` 之一 |

```text
模糊词封闭表：尽量 建议 最好 适当 酌情 原则上 一般来说 视情况 必要时 合理范围内
主观形容词封闭表：是否合理 是否清晰 是否恰当 是否充分 是否足够 是否友好 是否明显 合理即可 清晰即可 恰当即可
```

**命中的排除判据**：表中词必须作为**独立的语义单元**出现才计命中，嵌在更长词内部、被引述、处于并列名词位置的出现一律不计。每一次出现按下列四步顺序过判据，任一步判为「不计命中」即终止；四步全部通过才计命中。四步均为纯字符串运算，**严禁**引入语义判断。

各步的适用信号（**封闭对应关系**，不得外推）：

| 步骤 | 适用信号 |
|------|---------|
| 1 复合词排除 | S1、S2 |
| 2 前置字符排除 | S1、S2 |
| 3 被引用字符排除 | S1、S2、S3 |
| 4 并列名词排除 | S1 |

第 3 步对 S3 的适用方式：S3 判据涉及三个命中串——连接词本身、连接词左侧的 `必须` / `严禁` / `不得`、连接词右侧的 `必须` / `严禁` / `不得`；三者**必须**各自独立过第 3 步，被判为不计命中的串视为不存在，据此重新判断 S3 是否成立。

1. **复合词排除**：在条目文本中先按下方复合词封闭清单做最长匹配；凡该次出现的字符区间落在清单中任一串的区间内，不计命中
2. **前置字符排除**：取命中串左侧紧邻的 1 个字符——该字符码点落在 `U+4E00`–`U+9FFF`（中日韩统一汉字）区间时不计命中；左侧无字符（行首）或该字符为空白、标点、括号、引号、`|`、`-`、字母、数字时进入下一步
3. **被引用字符排除**：命中串被引用标记成对包裹时不计命中；未被包裹则进入下一步
4. **并列名词排除**：命中串处于并列名词位置时不计命中；否则计命中

```text
复合词封闭清单：修复建议  建议补充  参考建议
```

**第 3 步细则**：规范条目在定义一条判据时必然要写出被禁止的字符本身，那些字符是条目**引述的对象**而非条目自身的措辞，故不计命中。引用标记为下方封闭清单中的四对，不得增补也不得裁剪：

```text
引用标记封闭清单（四对，左右标记以码点给出）：
反引号      U+0060  `   与  U+0060  `
英文双引号  U+0022  "   与  U+0022  "
中文双引号  U+201C  “   与  U+201D  ”
直角引号    U+300C  「  与  U+300D  」
```

- 同形标记（反引号、英文双引号）按同一行内的出现次序两两配对：第 1 个与第 2 个为一对、第 3 个与第 4 个为一对，依此类推；行内出现次数为奇数时，末尾那个未配对标记不构成区间
- 异形标记（中文双引号、直角引号）按左标记与其右侧最近的同类右标记配对
- 「成对包裹」指命中串全部字符的下标均大于配对左标记的下标、小于配对右标记的下标
- 配对与区间判定一律限定在同一行内，**严禁**跨行配对

**第 4 步细则**：模糊词封闭表中的词在中文里也是常用名词（交付物名称等），列举名词时并非模糊措辞。取命中串左侧紧邻 1 个字符记为 L、右侧紧邻 1 个字符记为 R（行首 / 行尾时记为空），命中下表任一行即不计命中；两行均不命中则计命中。

| L | R | 判定 |
|---|---|------|
| `、` | 不限 | 不计命中 |
| `：` 或 `:` | `、` / `与` / `和` / `或` 之一 | 不计命中 |

- 第一行不看 R 的理由：顿号在中文里只出现于并列成分之间，左邻为顿号本身已足以确定该串处于并列项位置
- 第二行看 R 的理由：左邻冒号并不构成并列位置的证据，`：建议先校验必填参数` 属动词用法，**必须**计命中；只有 R 为并列连接符时才判为并列首项

```markdown
<!-- ❌ 错误：模糊词左侧紧邻字符为「：」，右侧为「先」，计命中，条目不可机械判定 -->
- 校验顺序：建议先校验必填参数

<!-- ✅ 正确：换成强制词，无模糊词命中 -->
- 校验顺序：**必须**先校验必填参数

<!-- ✅ 正确：左侧紧邻字符为中文字符「复」，属固定名词，不计命中 -->
| 违规项 | 修复建议 |

- RF-EX1: 报告中出现「建议补充」这类无判据的措辞
```

**多判据必须拆分**：一条规则中混入多个独立判据时，必须拆分为多条，使每条只对应一个判定动作。

```markdown
<!-- ❌ 错误：一条混入两个判据 -->
- 表格固定 4 列且值域仅 0-3

<!-- ✅ 正确：拆为两条 -->
- 表格列数**必须**为 4，缺列或多列均违规
- 首列取值**必须**属于 `0` / `1` / `2` / `3`，出现其他值违规
```

拆分的必要性在于定位：合并写法下报告只能给出一条违规，无法指明是列数错还是值域错，修复方向不明。

**主观判据必须给客观替代**：确实存在主观成分的判据，必须给出封闭的词表、正则或计数阈值作为替代判定手段，**严禁**只写主观形容词。

```markdown
<!-- ❌ 错误：主观且无替代 -->
- 描述措辞必须清晰有力

<!-- ✅ 正确：给出封闭词表 -->
- 描述**必须**含强制词（`必须` / `应`）之一，且**严禁**出现模糊词表中的任一词
- 模糊词表（封闭列表）：`尽量`、`建议`、`最好`、`适当`、`酌情`、`原则上`、`一般来说`、`视情况`
```
