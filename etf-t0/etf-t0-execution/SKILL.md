# ETF T+0 个性化操作手册

> [!IMPORTANT] 路径解析基准
> 文档内相对路径引用一律以本 skill 根目录（`SKILL.md` 所在目录）为基准解析。

## 参数

| 参数 | 必填 | 说明 |
|------|------|------|
| `reportPath` | 是 | 分析报告文件路径（`etf-t0-{6位代码}-{date}.md`）。**缺失时不得报错退出，必须先向用户提问** |
| `statePath` | 否 | 同批产出的 `.state.json` 路径；提供时用于读已用轮次与连亏计数 |
| `symbol` | 否 | 6 位数字代码；缺省从报告首部继承 |
| `date` | 否 | 手册基准日（`YYYY-MM-DD`）；缺省从报告首部继承 |
| `holdCost` | 否 | 问询项 `Q1` 持仓成本价（元/股）；未提供时按 STEP 3 问询，**严禁自填** |
| `holdShares` | 否 | 问询项 `Q2` 持仓总股数；未提供时按 STEP 3 问询，**严禁自填** |
| `keepShares` | 否 | 问询项 `Q4` 长期不动底仓股数；未提供时按 STEP 3 问询，**严禁自填** |
| `availableCash` | 否 | 问询项 `Q3` 可用现金（元）；未提供时按 STEP 3 问询，**严禁自填** |
| `execLevel` | 否 | 问询项 `Q5` 下单能力档：`manual` / `alert` / `conditional`；未提供时按 STEP 3 问询 |
| `watchWindows` | 否 | 问询项 `Q7` 可盯盘时段（如 `09:30-10:00,14:30-15:00`）；缺省按「全天可盯盘」假设并标注 |
| `outputDir` | 否 | 手册输出目录，默认当前工作目录 |

## 公共约束

> [强约束] 总纲：策略参数只继承不重算，个人数据只问不猜，每个价位都写出推导，每个时段都写出无信号时做什么。

| # | 约束 | 违反后处理 |
|---|------|-----------|
| ETE1 | 三态、`W`、`L`、生效上限、轮次上限、关键价位、委托单触发条件必须逐项继承报告所载值，**严禁自行重算或改写** | 改回报告原值后重出 |
| ETE2 | 生成手册前必须取得用户对必答六项的答复，**严禁**以默认值、估算值或旧值代替未答项 | 停止生成，回到问询步骤 |
| ETE3 | 买卖触发价必须由报告的 `W` 与 `L` 派生，**严禁**把成本价或保本价写成任何触发条件 | 删除该触发条件并改回 `W`/`L` 口径后重出 |
| ETE4 | 每条委托必须写出「报告原始价位 / 错位方向 / 最终委托价」三元组，**严禁**只给一个无推导的价格 | 补齐三元组后重出 |
| ETE5 | 本轮股数必须写出现金上限、仓位上限与两者取小结果，**严禁**只按可用现金算股数 | 补出仓位上限与取小过程后重出 |
| ETE6 | 交易所规则派生的时点与申报单位必须取报告所载值并原样带其快照标注，**严禁**由本 skill 填入报告未载的规则数值 | 改回报告值或标注「须用户自行核实」后重出 |
| ETE7 | 摊薄进度与抹平浮亏所需轮次必须标注为假设值，**严禁**表述为确定收益或确定回本时间 | 补加「假设值，待回测」标注后重出 |
| ETE8 | 报告结论为不做 T 时手册必须只出不做 T 守则与底仓处置，**严禁**输出任何开仓时间表 | 删除开仓时间表后重出 |
| ETE9 | 每个时段必须写出「无信号时的动作」，**严禁**留空或写成无读数的观察性描述 | 补出无信号动作后重出 |
| ETE10 | 用户声明不可盯盘的时段必须只保留可自动触发的委托，**严禁**在该时段安排需人工确认的 B 档动作 | 移出该段的 B 档动作后重出 |
| ETE11 | 报告基准日必须与手册执行日为同一交易日，**严禁**沿用过期报告的任何价位、差价或上限 | 停止生成，要求重跑分析后重出 |
| ETE12 | 存在未平 T 仓时首个动作必须是了结该轮，**严禁**在其平仓前安排任何开仓委托 | 把开仓行改标前置条件后重出 |

## 核心流程

### STEP 1：参数校验

按标准校验顺序校验：
- **必填**：`reportPath`（**缺失时不得报错退出，必须先向用户提问**）
- **格式**：`symbol`（匹配 `^[0-9]{6}$`）、`date`（`YYYY-MM-DD`）、`holdCost` 与 `availableCash`（可解析为非负数值）、`holdShares` 与 `keepShares`（可解析为非负整数）——均仅在提供时校验
- **枚举**：`execLevel`（`manual` / `alert` / `conditional`），仅在提供时校验
- **文件**：`reportPath`、`statePath`（仅在提供时校验存在）
- **透传**：`watchWindows`
- **创建**：`outputDir`

任一校验失败 → stderr + exitCode=2

### STEP 2：读取规范原文与来源报告

用 `Read` 逐份读取下列文件原文，**严禁**凭记忆或凭摘要执行：

- [intake.md](references/intake.md) — 问询清单、逐字问法、答复校验与未答处置
- [cost-anchor.md](references/cost-anchor.md) — 成本锚点口径、摊薄测算、用途白名单与禁用清单
- [order-craft.md](references/order-craft.md) — 现金流适配四步、tick 网格与尾数错位、量能确认、委托单落地表
- [timetable.md](references/timetable.md) — 八段划分、每段四项固定内容、跳空处置、不可盯盘处置
- [error-playbook.md](references/error-playbook.md) — 八类预案与时段对应关系
- [manual-template.md](references/manual-template.md) — 手册输出模板（九节）
- `{reportPath}`、`{statePath}`（提供时）

用户答「没有分析报告」或所给路径无报告 → stderr + exitCode=3（提示先出分析与策略报告）。报告缺 `W`、`L`、生效上限、委托单清单任一项 → stderr + exitCode=3。**报告基准日与手册执行日不是同一交易日** → stderr + exitCode=3（ETE11，提示重跑分析）。

**完成标准**：六份规范原文与报告均已读取；报告时效已核对通过；报告结论、`symbol`、`date` 已确定。

### STEP 3：用户确认与信息采集

按 [intake.md](references/intake.md) §一 的问询规则，**一次性列出必答六项**（已由入参提供的项跳过）等用户答复；逐项过 §五 答复校验与 §四 口径二次确认。`Q6` 与选答项 `Q8`–`Q10` 不设入参，一律在本步问询取得。

- 用户明示不需要手册 → 不生成任何文件，打印状态行，exitCode=0
- `Q2`、`Q5`、`Q6` 任一为 `未答` → 只出待补信息清单 → stderr + exitCode=3
- `Q1`、`Q3`、`Q4` 为 `未答` → 按 §二「未答处置」列降级出手册，并在首部写出受影响的节

**完成标准**：必答六项均为「已校验的显式值」或「已按未答处置降级」；全部答复已带「用户提供 + 时间」标注。

### STEP 4：继承参数抽取

从报告逐项抄出 [manual-template.md](references/manual-template.md) 第一节表格的每一行（含报告位置），**严禁**改写数值或补算报告未载项。

- 报告结论属「不适合做 T / 不适用本体系 / 当日不做 T / 停手」→ 直接转 STEP 9，只出不做 T 守则与底仓处置（ETE8）
- 报告已对规则派生值标注「快照可能过期，须复核」→ 原样抄入手册（ETE6）
- `statePath` 提供时读出已用轮次与连亏计数，据其算出本日剩余可用轮次

**完成标准**：继承参数快照表无空行、无自算值；本日剩余可用轮次已确定。

### STEP 5：成本锚点与摊薄测算

按 [cost-anchor.md](references/cost-anchor.md) §一 算四个锚点、§二 算摊薄与轮次，逐个写出代入过程与输入来源；`N_flat` 与 `N_exp` **必须同时给出**并标「假设值，待回测」（ETE7）。同时按 §三 用途白名单与 §四 禁用清单逐条自查。

**完成标准**：九项测算结果齐备且均带代入过程；四条禁用项均已勾选未触犯。

### STEP 6：现金流适配与本轮股数

按 [order-craft.md](references/order-craft.md) §一 走四步：现金上限 → 仓位上限 → 取小 → 门槛校验，写出三种可行性结论中命中的一种，并算反向 T 可卖上限（ETE5）；反向 T 另按 §五 过买回资金校验与 `Q9` 第 ④ 项确认。再按 §六 把报告的回撤触发线换算为绝对元数、算本轮与本日最坏亏损，本日最坏亏损超出口径 B 当日档 → 下调本日可用轮次至不冲突。两向皆不可行 → 转 STEP 9，只出「今日不做 T」与底仓处置。

**完成标准**：`n_cash`、`n_cap`、`n`、门槛校验、`n_sell` 五项均有代入过程；停手线四档绝对额与最坏亏损已写出且轮次冲突已消解。

### STEP 7：委托价错位与委托单落地

按 [order-craft.md](references/order-craft.md) §二 对每个价位做 tick 归整与尾数错位，写出三元组并过 R1–R6 与错位后复核两条（ETE4）；按 §三 定 A/B 档动作形态与量能确认口径；按 §四 填 11 列委托单落地表（条件单行写「触发 / 委托」两值）；反向 T 行按 §五 派生三价并互换止盈止损列语义。

- `Q6` = 有 → 表第 1 行固定为「了结未平轮」，其后各开仓行标注「该轮平仓后方可执行」，本日可用轮次减 1（ETE12）

**完成标准**：每行委托的三元组、股数、止盈价、止损价齐备；行数 ≤ 本日可用轮次；`Q5 = manual` 时 B 档行已全部作废。

### STEP 8：全天时间表与预案对照

按 [timetable.md](references/timetable.md) 填八段，每段写齐四项（ETE9），并按 §六 处置不可盯盘段（ETE10）、写入 §四 两种失效情形与 §五 的 P7 三步；`Q6` = 有时按 §三 的未平轮覆盖规则改写 P1/P3 首动作（ETE12）；按 [error-playbook.md](references/error-playbook.md) §三 为每段禁止动作标上预案编号。

**完成标准**：八段均有四项内容；每段禁止动作均带预案编号；不可盯盘段无 B 档动作；未平轮覆盖规则已落入首动作。

### STEP 9：手册写入与自查

套用 [manual-template.md](references/manual-template.md) 的速览卡与九节生成手册，写入 `{outputDir}/etf-t0-ops-{symbol}-{date}.md`，逐条勾选第八节自查表（覆盖 ETE1–ETE12）。向 stdout 打印一句话执行摘要（今日照单执行 / 今日不做 T）、手册绝对路径与状态行。

**完成标准**：速览卡与九节齐全、自查表全部勾选、手册绝对路径已回显。

| 文件 | 条件 | 路径 |
|------|------|------|
| 个性化操作手册 | 必答项齐备时必产 | `{outputDir}/etf-t0-ops-{symbol}-{date}.md` |

> [强约束] 文件名片段生成规则：`{symbol}` 字符白名单为 `^[0-9]{6}$`（长度恒为 6 个字符，纯数字无大小写），为空时回退为报告首部所载 6 位代码；`{date}` 白名单为 `^\d{4}-\d{2}-\d{2}$`，为空时回退为报告首部所载分析基准日。**严禁**把用户传入的中文名或带市场前缀的写法拼入文件名；两处回退值均取不到即按输入异常处置。落盘后必须回显产物绝对路径。

### 退出码

> 本 skill 由 Claude 在对话中直接执行、无外部进程返回退出码，每次结束时必须在输出末尾单独打印一行 `状态：{含义}（exitCode={N}）`。

| exitCode | 含义 | 触发场景 | 后续动作 |
|---------|------|---------|-----------|
| 0 | 完成 | 手册写入成功；或报告结论为不做 T 而只出守则与底仓处置；或用户明示不需要手册 | 用户照单执行 |
| 1 | 执行失败（可重试） | 手册或待补信息清单写入失败 | 询问用户：重试 / 终止 |
| 2 | 输入异常（不可重试） | `reportPath` 或 `statePath` 指向的文件不存在；`symbol`、`date`、数值或枚举参数格式非法；`{symbol}` 与 `{date}` 两处回退值均取不到 | 提示用户修正参数 |
| 3 | 需人工决策 | 用户无分析报告；报告缺 `W`、`L`、生效上限、委托单清单任一项；**报告基准日与执行日非同一交易日**；`Q2`/`Q5`/`Q6` 未答；当前价已穿透报告区间致价位失效 | 提示先出分析报告或补答问询项 |

### stderr 格式（JSONL，单行）

```jsonl
{"message":"...","detail":"...","hint":"..."}
```

字段约束：
- `message` 必填，自由文本，简洁单行
- `detail` 可选，多行文本（保留原始错误信息）
- `hint` 可选，给用户的修复提示

## 危险信号（Red Flags）

以下可观测信号表明执行出现偏差，出现任一项必须回退修正：

- RF-ETE1: 手册中出现报告未载的 `W`、`L`、上限或价位数值，或同一参数在手册与报告中不一致
- RF-ETE2: 必答六项中出现「按经验取」「一般为」这类来源，或问询未发出即已生成手册
- RF-ETE3: 出现「回到成本价再卖」「等解套」「浮亏大所以先补仓」形态的触发条件
- RF-ETE4: 委托价只给最终值而无原始价位与错位方向，或错位幅度超过 1 个 tick
- RF-ETE5: 股数只按可用现金算出，或 `n` 大于 `n_cap`
- RF-ETE6: 手册写出报告未载的集合竞价时点、申报单位或税费数值，或抄漏报告的快照标注
- RF-ETE7: 出现「N 轮回本」「每月摊薄 X%」等无假设标注的确定性表述
- RF-ETE8: 报告结论为不做 T，手册中仍出现委托单行或开仓时段
- RF-ETE9: 时段表存在空白的「无信号时的动作」格，或该格写成「关注走势」「灵活应对」
- RF-ETE10: 不可盯盘段仍安排需人工确认量能的 B 档动作，或作废行被直接删除导致行号与报告不对应
- RF-ETE11: 手册的报告基准日早于执行日却照常输出了委托单清单，或首部失效条件里没有日期核对项
- RF-ETE12: `Q6` 答「有」而委托单第 1 行不是了结未平轮，或多个轮次可同时在场，或本日可用轮次未因未平轮减 1

## 反合理化（Anti-Rationalization）

| 借口 | 反驳 |
|------|------|
| "报告的 W 太小，我按盘面帮用户调大一点" | 调 W 等于改整套期望计算与仓位上限。要改就回分析流程重出报告，不在执行层偷改。 |
| "用户没说成本价，按现价上浮 20% 估一个也差不多" | 成本价决定摊薄进度与是否已实现亏损，估错方向就全错。未答就是未答，缺项降级出手册。 |
| "都亏 20% 了，卖出触发价定在成本价附近才不吃亏" | 市场不知道你的成本，成本价上没有任何阻力。把触发价挂在那里的唯一结果是永远不成交、T 仓过夜。 |
| "现金够买 400 股，就写 400 股，用户自己会掌握" | 现金上限不是仓位上限。写 400 股就是让用户超限下单，触及止损时亏损翻倍。 |
| "挂单价直接写最终价就行，谁还看错位过程" | 不写原始价位就无法复核错位是否只走了 1 个 tick，错位 3 个 tick 时 W 已被改小而没人发现。 |
| "时段表里没信号的时候不用写，用户自然知道别动" | 不写就会自己找事做。「不下单、不改单、不撤单」是必须写出的动作，不是留白。 |
| "集合竞价时点常识就是那几个，直接写上省事" | 规则数值的出处只有报告的快照。凭常识写上去的时点无法判断是哪一版，按错的时点安排清零就是过夜。 |
| "报告是昨天出的，隔一天区间变化不大，照着用就行" | 昨天的上沿下沿是昨天的价。照过期区间挂单，最好的结果是不成交，最坏的结果是在今天的趋势里逆势接刀。重跑一次分析比赔一轮便宜。 |
| "用户还有一笔没平的 T 仓，先按新清单开一轮，回头一起处理" | 两轮同时在场时你已经不知道哪笔止损对应哪笔买入。串行是这套体系能算清期望的前提，先了结再开新轮。 |
| "算出要 86 个交易日才能靠做 T 抹平浮亏，太打击人，删掉" | 那正是用户下单前最该知道的数字。删掉它等于把最乐观假设当成计划卖给用户。 |
