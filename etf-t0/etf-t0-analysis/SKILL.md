# ETF T+0 单标的分析与操作策略

> [!IMPORTANT] 路径解析基准
> 文档内相对路径引用一律以本 skill 根目录（`SKILL.md` 所在目录）为基准解析。

对单只 ETF 完成"利空利多信息收集 + 盘面技术分析 + 当日情况整合 + T+0 操作策略设计"的闭环分析，产出一份可直接执行的结构化报告。

策略判断与分析维度依据本目录下三份文件：
- [strategy-framework.md](./references/strategy-framework.md) — T+0 交易体系（核心数学与口径符号 §1、三态框架 §2、仓位 §3、信号量化 §4、风控铁律与回撤 §5、策略衰减 §7、可转债与跨境 ETF 特殊约束 §8），一切操作建议以此为准
- [info-checklist.md](./references/info-checklist.md) — 多面分析维度清单（利空利多 7 维 + 盘面技术 4 维 + 当日时段 + 多日视角）
- [calc-methods.md](./references/calc-methods.md) — 放量/ATR/折溢价/振幅/RSI 的精确计算口径速查，及凯利风险预算校验（§五）、三态判定量化（§六）、区间与支撑阻力口径（§七）、真实成本 2C 与最低佣金咬合判定（§八）
- [data-sources.md](./references/data-sources.md) — 数据获取口径：新闻面工具无关（用户 `news` 优先 → 环境可用的联网检索工具 → 数据缺失降级链），行情用公开接口（新浪/腾讯快照、东财 K 线）经 Bash 取数，交易日历口径亦以本文件为准
- [report-template.md](./references/report-template.md) — 分析报告输出模板

## 参数

| 参数 | 必填 | 说明 |
|------|------|------|
| `symbol` | 是 | ETF 代码或名称（如 `513310` 或 `半导体ETF`） |
| `date` | 否 | 分析基准日（`YYYY-MM-DD`），默认今日 |
| `horizon` | 否 | 分析视野：`today`（默认，当日）/ `multiday`（多日路径） |
| `position` | 否 | 当前持仓：底仓股数、成本价、可用现金；用于精确仓位与金额建议，缺省则给比例化建议。**可附带「昨收账户总资产」**（券商 App「昨日资产 / 参考市值」一栏直接可见，用户只需填一个数字）——其性质与 `cost` / `news` 完全相同：**用户一手信息、有来源、不违反 ETA1**，采用时来源标注「用户提供」。用途：作为 STEP 7「三级取数降级链」的第 ② 级，让用户**一步跳出冷启动档**（口径 A 单日档得以核查）。本项**不新增顶层入参**，挂在 `position` 下即可（`position` 本就含 `cash`，已是账户级信息） |
| `news` | 否 | 用户直接提供的新闻/公告原文或链接；提供时作为利空利多的**一手信息优先采用**，缓解联网工具缺失导致的基本面缺失 |
| `cost` | 否 | 账户成本参数：佣金率、单笔最低佣金（如 `万0.5 / 最低5元`）。缺省 = **万0.5 单边、无最低佣金**（framework §1 硬门槛假设），并按 ETA2 标注为假设值。提供时用于按 calc-methods §八 算真实往返成本 2C、校验边界条件②「W ≥ 4×2C」并判定最低佣金是否咬合 |
| `history` | 否 | 该标的历史 T+0 成交样本，或已统计好的 `p`（胜率）/ `r`（盈亏比）/ 样本数。缺省 = 视为样本不足，走 framework §3 执行硬顶保守端并按 ETA2 标为假设值。提供且样本 ≥100 时启用 calc-methods §五 凯利风险预算校验与 framework §7 策略衰减检测 |
| `outputDir` | 否 | 报告输出目录，默认当前工作目录 |

> 📌 **T 仓上限阶梯（全文统一引用，"降一档"= 沿阶梯左移一格）**：`20% → 15% → 10% → 5% → 0（停做 T）`；从**当前生效上限**起算而非三态名义上限；多触发源要求降档按次数累计不去重；降档当日有效、次日按三态重新起算（收盘清零例外惩罚为**当周**有效）。本 skill 所有"降一档"表述一律指本阶梯（定义同 framework）。
> **"减半"与阶梯的对齐**：凡"T 仓上限减半"（回撤口径 B 的单日 0.2%–0.4% 档与单周 > 0.8% 档、策略衰减表"疑似衰减"行）一律**减半后向下取最近档位**：`20% → 10%`、`15% → 5%`（7.5% 向下取 5%）、`10% → 5%`、`5% → 0（停做 T）`。理由：向下取档在风险方向保守，且保证「当前生效上限」始终是阶梯上可复现的单一值，不出现 7.5% 这类无法与"降一档"叠加运算的中间态。
> **降档与减半的结算顺序（五步，任意触发组合必收敛到唯一格点）**：
> ① **起点** = 三态名义上限（震荡 20% / 下跌 10–15% / 上涨 ≤10%）；
> ② **降档** = 每个"降一档"触发源各降一格，**累计不去重**（熔断、回撤口径 A 的 1%–2% 档、券商能力不支持、清零例外惩罚、**冷启动**）；其中 **`cold_start`（冷启动·无历史 state）至多计一次**——这是对"累计不去重"的**唯一具名例外**：4 个跨日字段同源于「无历史 state」这**一个状态**，按 4 次计等于把一个事件罚 4 次（详见 STEP 7 冷启动档）；
> ③ **减半** = 若存在**任一**"减半"触发源则对 ② 的结果减半**一次**——**多个减半触发源不叠加**（回撤口径 B 与策略衰减同时命中也只减一次）；
> ④ **取格** = 向下取最近阶梯格点；
> ⑤ **结果** = 唯一「当前生效上限」，报告必须写出该值**及其推导链**。
> 算例：震荡 20% + 熔断降一档 + 口径 B 减半 → ② 15% → ③ 7.5% → ④ 取 **5%**。
> 五步的**每一步输入、触发源与输出**须整体落成 state 的**结构化对象 `risk_state.t_cap`**（完整路径；下文与报告中可简写 `t_cap.*`；字段与枚举见「状态文件字段」节）：结果落 `t_cap.effective`（小数，**必须落在 `0.20/0.15/0.10/0.05/0` 之一，否则视为结算错误**，见 RF-ETA3），推导链文字落 `t_cap.derivation_text`（如 `"0.20 名义（震荡）→ 降2档 0.10 → 口径B减半 0.05 → 取格 0.05"`）；且必须同时满足**五条不变式 I1–I5**（见「状态文件字段」节），违反任一亦为结算错误。报告 §五/§六 的推导链一律写成**五行表格**（五步各一行）以与 `t_cap` 逐字段对应。
> （降档是"事件计数型"收缩、减半是"状态型"收缩，故减半只作用一次且置于降档之后。）

## 核心流程

### STEP 1：参数校验

按标准校验顺序校验：
- **必填**：`symbol`
- **枚举**：`horizon`（`today` / `multiday`），缺省为 `today`
- **格式**：`date` 若提供须为 `YYYY-MM-DD`，缺省为今日
- **交易日**：`date` 落在周末或节假日（按 [data-sources.md](./references/data-sources.md) 的交易日历口径判定）→ **不报错**，自动改为「上一交易日复盘 + 下一交易日预案」视角，并在报告首部与 stdout 显式标注实际取数日与预案日；交易日历无法核实时按"数据缺失"标注并沿用 `date`
- **成本**：`cost` 若提供须能解出「佣金率」与「单笔最低佣金 F」两个数值，解不出 → stderr + exitCode=2；缺省为 `佣金率=万0.5 单边、F=0`，并在报告中标注为默认假设
- **历史样本**：`history` 若提供须能解出「样本数」，或能解出 `p` 与 `r`；解不出则视为**缺省**（样本不足）而非报错，并在报告中标注"历史样本不可用，按执行硬顶保守端"
- **透传**：`position`、`news` 为自由文本，有则原样保留供后续步骤使用，缺省为空
- **创建**：`outputDir`，缺省为当前工作目录

任一校验失败 → stderr + exitCode=2。

**完成标准**：所有参数已归一化为确定取值；`cost`、`history` 已归一化为「显式值」或「默认口径 + 假设标注」；分析视角（当日 / 上一交易日复盘 + 下一交易日预案）已确定。

### STEP 2：标的核实与门槛判定

按 [data-sources.md](./references/data-sources.md) 用联网/行情工具核实 `symbol`：确认其为有效 ETF，查明**6 位代码**、跟踪指数、所属赛道、规模、近 20 日日均成交额。对照 framework §1 边界条件与 info-checklist §一 判定其是否为合格做 T 标的；跨境/QDII ETF 与可转债标的须额外过 framework §8 的特殊约束。

> [强约束] 成交额门槛"日均 ≥ 5 亿"必须用**东财日线近 20 根成交额算日均**，**严禁**用盘中当日未走完的半日额直接对比全日门槛（口径见 data-sources §四）。

> [强约束] **代码归一化**：本步核实出的 6 位代码是后续所有产物文件名的唯一依据，**严禁**把用户传入的中文名或带市场前缀的写法带进文件名。

本步须逐项判定并显式记录结论：

1. **成本硬门槛**（用 `cost`）：按 calc-methods §八 算真实往返成本 `2C`，判定单笔最低佣金是否咬合（咬合阈值 = `F / 佣金率`），并校验边界条件②`W ≥ 4×2C`。若**咬合**且计划单轮金额低于不咬合阈值 → 直接判「**不适合做 T**」，并按 calc-methods §八 公式给出所需最小单笔金额（成本约束 `≥ 8×F×P/W`、性价比下限 `≥ 40/w`、整手 `≥ 申报单位×P` 三者取最大；**申报单位按品种取**，ETF = **100 份**、可转债 = **10 张**，见主文档附录 D 并带快照日期——⚠️ 两者差 10 倍且单位不同，套错会把可转债的整手门槛高估 10 倍），报告照常产出、结论为"不适合做 T"，exitCode=0。
2. **振幅门槛（双档）**：ATR 动态口径要求近 20 日均振幅 ≥ 1.5%；静态表口径要求 ≥ 4% 且满足 ETA8 的分档「所需最低振幅」。两档均不满足 → 判「不适合做 T」。
3. **日线样本量**：取到的日线不足 **60 根**（新上市 ETF 算不出 60 日均线）→ 显式**降级**并标注"60 日均线不可得，三态判定降级为 20 日线斜率单一依据（calc-methods §六）"；**严禁**用不足样本硬算 60 日均线或硬给三态。若连 20 日线斜率所需样本（≥30 根）也不足 → 三态无法判定，exitCode=3。
4. **停牌 / 复牌首日 / 涨跌停锁死**（framework §5.1 铁律 5：涨跌停日、**停牌日、复牌首日**不做 T）：当日停牌或可转债临停 → 停做 T，报告说明原因，exitCode=3；**复牌首日** → 停做 T（量能失真使放量判定失效，见 calc-methods §1.3），报告照常产出、结论"当日不做 T"，exitCode=0；涨跌停封死 → 判"当日不做 T"。
5. **适用范围**：本体系适用于**股票型 ETF、跨境 ETF、可转债**。若标的属**货币 ETF、债券 ETF** 等报价与申报规则不同的品种 → 判「**不适用本体系**」，并说明须先自行核实其最小变动价位、申报单位与费用结构，**严禁**套用本文的 0.001 元 tick / 100 份整手 / 参数表数值；报告照常产出、结论为"不适用本体系"，exitCode=0。

- `symbol` 无法核实为有效 ETF → stderr + exitCode=2。
- 无任何联网/行情工具可用 → 标注全局"数据缺失"，仅产出框架性报告，最终 exitCode=3。

**完成标准**：6 位代码已确定；成本硬门槛、振幅双档门槛、日线样本量、停牌/复牌首日状态、适用范围五项均有明确结论；"适合 / 有条件 / 不适合做 T / 不适用本体系"结论已确定。

### STEP 3：利空利多信息收集

按 info-checklist §一（A–G 七维：宏观政策 / 行业主题 / 成分指数 / 资金面 / 折溢价 / 公告事件 / 舆情）逐维收集。取数**按 [data-sources.md](./references/data-sources.md) §二的降级链**，优先级：`用户提供的 news` → `环境可用的联网检索工具（如 WebSearch/WebFetch 或等效 MCP/浏览器工具）` → `已知公告页直取` → `数据缺失`。**严禁因某个工具缺失就整块跳过该维度**。每条给出：关键信息 + 定性（利多/利空/中性）+ 强度（强/中/弱）+ 来源与时间戳（用户提供的须标"用户提供"）。汇总出"偏多/偏空/中性"综合结论，并判定 framework §2.1 **基本面闸门**是否触发。跨境 ETF 的溢价分位、可转债的强赎公告按 framework §8 一并纳入闸门判定。

> **跨境 / QDII ETF 溢价判定的三级降级口径（必须逐级尝试，不得因取不到 IOPV 就跳过该维度）**：
> ① 有 IOPV 历史序列 → 原口径：溢价率 > 自身近 1 年 80% 分位 → **停做正向 T**；
> ② 无 IOPV 历史但有二级价日线 → **代理指标**：`当日收盘价 / 近 20 日均价 − 1 > +3%`（且标的市场同期无对应涨幅）→ 视同高溢价、停做正向 T，**必须标注「代理指标，非真实折溢价分位」**；
> ③ 二者皆无 → 标注「溢价分位不可得」，并对跨境 ETF **一律保守停做正向 T**（高溢价回归可在标的市场平盘时单独造成 3%+ 跌幅，与 W/L 无关，不确定时按不做处理）。

**完成标准**：七维均有结论或明确"数据缺失"；多空综合结论与闸门判定已给出（若因数据缺失无法判定闸门，须显式写"闸门无法判定"并提示补 `news`）。

### STEP 4：盘面技术分析

按 info-checklist §二（H–K：趋势三态 / 量能 / 波动关键价位 / 盘口流动性）分析。行情取数按 [data-sources.md](./references/data-sources.md) §三/§四（新浪快照 + 东财 K 线）。

- **三态判定**：必须依 framework §2.1 与 **calc-methods §六** 的斜率口径给出——写出 `20 日线斜率 = (20MA(t) − 20MA(t−10)) / 20MA(t−10)` 的**数值**与阈值判定过程（|斜率| < 0.5% → 震荡；≥ +0.5% → 上涨；≤ −0.5% → 下跌；高波动标的按 §六 可放宽），**严禁**用主观的"斜率≈0"表述。冲突态按 framework §2.1 tie-break 裁决；并给出 **regime 二次确认**状态（是否连续 2 个交易日一致；过渡日取新旧两态中更保守者）。
- **关键价位**：支撑/阻力/日内区间上下沿一律按 **calc-methods §七** 口径生成，并逐个价位标注所用**候选来源**（近 20 日高/低、前一日高/低、当日开盘价、20 日均线、整数关口），同时做有效性校验 `上沿 − 下沿 ≥ 2W`（不满足 → 本轮不做）。所有价位落在 0.001 元 tick 网格（ETA9）。
- **指标计算**：放量、ATR(14)、折溢价、振幅、RSI 一律按 [calc-methods.md](./references/calc-methods.md) §一/§二/§三/§四 口径。跨境/QDII ETF 折溢价取不到 IOPV 时按 STEP 3 的三级降级口径处理（②级须标「代理指标，非真实折溢价分位」，③级一律保守停做正向 T），**严禁**写"折溢价数据缺失"后照常给正向 T 策略。
- **W / L**：默认按 framework §4.4 的 **ATR 动态**口径 `W = k × ATR(14)`、`L = W/2`，`k ≤ 1/3` 为硬上限、**默认 k = 0.30**；仅在 §4.4 允许的两种情形（① 无法取足 K 线算 ATR(14) ② 纯手动心算无脚本环境且近 20 日均振幅 ≥ 4%）才退回静态表，退回时必须过 ETA8 的分档振幅校验。报告须写明本次用的是哪种口径及 k 值。
- **盘口价差 / 深度 / 滑点**：一律按 **calc-methods §九** 算，并写出**三个实际数值 + 门槛比对结果**，不得只打勾：① 一档价差 = 卖一 − 买一（新浪快照下标 7 − 下标 6），门槛 `≤ W/5`；② 盘口深度**按方向取同向档位**——买入看卖一~卖三挂单量之和、卖出看买一~买三之和，门槛 `≥ 本轮计划股数 × 3`；③ 预估滑点 `≈ max(1 个最小变动价位, 一档价差/2)`（单边穿档按穿过档位的加权均价与买一/卖一之差计），门槛为边界条件③ `< W/3`。任一项不满足 → 本轮不做。**集合竞价与临停期间五档失真 → 三项一律标"不可用"**，严禁用失真盘口下结论。

**完成标准**：三态判定（含斜率数值与二次确认状态）、带口径来源的关键价位、W/L（含口径与 k 值）、盘口三项（价差/深度/滑点）的实际数值与门槛比对结论齐备。

### STEP 5：当日情况整合

依 `date` 与当前时段，按 info-checklist §三取对应视角（盘前预期 / 盘中实况 / 收盘复盘）整合；STEP 1 判定为非交易日时按「上一交易日复盘 + 下一交易日预案」双视角输出。`horizon=multiday` 时追加 info-checklist §四（事件日历、多日区间预判、分日打法路径）。盘中视角须同时判定 framework §2.3 盘中熔断是否触发；触发则按**T 仓上限阶梯**降一档并写出降档后的「当前生效上限」。

> **熔断时「已在场未平轮」超过新生效上限的处理**：① **不即时减仓**——已在场轮次按原止盈/止损纪律了结，容忍其超限至本轮平仓为止（即时减仓等于在非信号点被动改变本轮 W/L 结构、破坏该轮期望计算，framework §1）；② 新上限对**后续轮次立即生效**；③ 该轮平仓前**禁止开新轮**（串行原则）；④ 报告必须显式写出「**当前有未平轮超出生效上限**」这一状态，**不得静默**。

**完成标准**：当日（及多日）情境与关键观察点已明确；熔断判定、降档后的当前生效上限、以及"未平轮是否超出生效上限"的状态已给出。

### STEP 6：操作策略生成

综合 STEP 3–5，依 framework §2.2 三态速查表与 §3 仓位法则、§4 信号体系生成策略。生成策略前先做两项前置诊断：

> **6a 仓位结构诊断（前置）**：用 `position` 算出用户实际的底仓 / T 仓 / 备用金比例，与 framework §3 的 **2-2-6** 对照。严重偏离时**先给结构调整建议，再出策略**：满仓无现金 → 本期只能做**反向 T**（先卖后买），并写明这一限制；现金比例过高 → 说明 T 仓上限受可用资金而非比例约束；底仓不足 6 个月持有计划（边界条件⑤）→ 判不满足做 T 前提。`position` 缺省 → 跳过精算，按比例化建议输出并标注"未提供持仓，结构诊断略过"。

> **6b 组合层校验（前置）**：若 `position` 或 `history` 显示用户已在其他标的做 T → 按 framework §3「全组合合计 T 仓 ≤ 20%（震荡上限）、同时盯盘 ≤ 3 只、标的间低相关」核对，并把**本标的 T 仓上限相应压低**（如已有 2 只在做 → 本标的上限 ≈ 20% ÷ 3）。无组合信息 → 标注"按单标的口径给出，若已在其他标的做 T 须自行按 framework §3 压低本标的上限"。

策略正文须给出：主用工具、T 仓上限（须写出三态名义上限与经降档后的**当前生效上限**，降档一律按 **T 仓上限阶梯**）、每日轮次、具体买卖点与触发条件、W/L 数值与口径、单轮 T 仓金额（有 `position` 则算绝对数量，否则给比例，并写明占总资金比例 θ 与占 T 仓比例）、A/B 档自动化建议、**今日委托单清单**（按 report-template §五 表格逐单列出）；信号冲突按 framework §4.5 串行裁决；`multiday` 给分日路径。

> **券商能力核对（写入自动化建议处，强度不得削弱）**：⚠️ 实盘前必须逐条核对所用券商的能力——① 是否支持条件单及其在 14:57 后的触发行为；② 是否允许挂**涨停价买 / 跌停价卖**的限价单（framework §5.3 升级链依赖此项）；③ 条件单的有效期与撤单规则。**任一项不支持 → 对应环节退化为人工执行，并据此按 T 仓上限阶梯下调一档**（执行确定性变差即风险变大）。核对结论与降档后的当前生效上限须写入报告。

> **仓位精算（凯利风险预算校验）**：当 `position` 提供、且 `history` 提供的该标的可信历史成交样本 **≥100 次**时，按 [calc-methods.md](./references/calc-methods.md) §五做**完整凯利风险预算校验**——`f* = p−(1−p)/r` 是风险预算（**非仓位**），实际单轮仓位取 `min(执行硬顶, f*×(买入价/L))`。**执行硬顶（震荡 20% / 下跌 10-15% / 上涨 ≤10%）优先，严禁突破 2-2-6**。`history` 缺省、样本 < 100 或无法解析 → **退回 framework §3 执行硬顶的保守端**，并按 ETA2 标注胜率为假设值。若 `f* ≤ 0`（p ≤ 1/3）→ 判本标的无正期望，策略转"停手"。
>
> **样本来源优先级**：`history`（用户一手信息）**优先于**上一日 state 文件的 `rolling_stats`（历史留痕）。两者的 `p` 或样本数不一致时 → **以 `history` 为准**，并在报告"数据来源与口径快照"节标注两者差异值；**严禁取平均、严禁静默采信其一**（与新闻面 `news` 优先于检索结果同理）。
>
> [强约束] **月度胜率不可用于仓位决策**：月样本仅 15–25 轮、胜率标准误约 10%，按月胜率（≥50% 及格 / ≥60% 优秀）调仓等于按噪声调仓。月度指标仅为**执行质量观察值**（查轮次是否超限、止损是否照做、成本是否异常），**严禁**据其增减仓位；任何仓位调整一律以 framework §7 的 **n=100 滚动窗**判定为准。
>
> **策略衰减检测**（样本 ≥100 时按 framework §7）：该表**按行序自上而下、命中即定，后续行不再判**，行序为从严到宽——① `p_100 ≤ 1/3` → 停做该标的；② `p_100 ≤ 0.45` → 疑似衰减，T 仓上限**减半（减半后向下取最近档位**，见阶梯定义：20%→10%、15%→5%、10%→5%、5%→0）且只做 A 档；③ `r_100 < 1.5` → 盈亏比失效，先查止损执行与 W 设定；④ 以上均不命中且 95% 下界 > 1/3 → 正常。

**完成标准**：仓位结构诊断与组合层校验已输出；策略每一项均为可执行的具体数值或触发条件，委托单清单可直接照单下单，无模糊表述（满足 ETA3）。

### STEP 7：风控核查与报告输出

依 framework §5.1（五大铁律）、§5.2（**两套回撤口径**：口径 A 账户总资产管"打法收缩"、口径 B 已实现盈亏管"停手"，两套触发线均须写出）、§5.3（**收盘清零升级链** 14:50 对手价 → 14:55 涨跌停价限价单 → 14:57 后仅客观不可成交才例外过夜及其三项惩罚；**部分成交处理**）逐条核查，并核对 framework §4.5 信号冲突裁决已在策略中体现。回撤口径 A/B 的降档/减半动作一律按 **T 仓上限阶梯**及其**五步结算顺序**，并写出「当前生效上限」**及完整推导链**（名义上限 → 逐项降档 → 是否减半 → 取格 → 生效上限）；口径 B 的"T 仓上限**减半**"（单日 0.2%–0.4% 档、单周 > 0.8% 档）按**减半后向下取最近档位**执行（20%→10%、15%→5%、10%→5%、5%→0）；口径 B 的"等价占 T 仓"列仅供参照（按 θ=20% 换算），**触发线以占总资金为准**。铁律 5 核查须覆盖**涨跌停日、停牌日、复牌首日**三种情形。若存在**已在场未平轮且其仓位超过本次生效上限** → 报告必须显式写出该状态（不即时减仓、新上限只约束后续轮次、该轮平仓前禁开新轮），**不得静默**。

> **单周累计的取数（四步，缺一不可；两套口径的单周档共用同一次历史 state 查找）**：
> ① 在 `{outputDir}` 内查找**同一 6 位代码、日期早于本次 `date`、且 `settled == true` 的最近一个 `.state.json`**（`settled != true` 的份为计划态，其结算类字段按 ETA10 应为 `null`，**严禁**当作已核实值采用；跳过它继续往前找）；
> ①' **命中份的日期连续性决定三类字段各自可用到什么程度**，三类**必须**分开处置，**严禁**一并采信：**(a)** `rolling_stats` / `rounds_ledger` 与日期连续性无关 → **不要求**命中份紧邻上一交易日，直接采用；**(b)** `prev_close_equity` **必须**取**紧邻上一交易日**那一份的 `account_equity`，命中份不紧邻 → 写 `null` 并标「口径 A 单日档不可核查」；**(c)** 单周累计两字段（`realized_pnl_week`、`account_equity_week_high`）在命中份与本次 `date` 之间**存在未结算交易日**时 → 其值**不完整**（漏掉中间各日的盈亏与权益峰值，低估回撤属危险方向），**必须**标「单周档不完整（中间 ____ 个交易日未结算），按不可核查处置」并走单周档的人工确认话术，**严禁**当作已核实值触发或宣称未触发；
> ② 命中且其日期与本次 `date` 属**同一自然周** → 口径 B：`realized_pnl_week = 该文件的 realized_pnl_week + 本日已实现盈亏`；口径 A：`account_equity_week_high = max(该文件的 account_equity_week_high, 本日 account_equity)`；
> ③ 命中但跨周 → 本周重新起算：`realized_pnl_week = 本日已实现盈亏`、`account_equity_week_high = 本日 account_equity`；
> ④ 未命中任何 `settled == true` 的历史 state 文件 → `realized_pnl_week`、`account_equity_week_high` 一律写 **`null`**，并在报告风控核查节显式标注「**单周回撤口径不可用（缺历史 state），本次仅按单日口径核查**」（口径 A 另标「口径 A 单周档不可核查，本次仅按单日口径」）；同时按下述**冷启动档**处置。
>
> **冷启动档（「无历史 state」= 一个状态，只计一次降档）**：首次运行会同时缺失 4 个跨日字段（`prev_close_equity`、`account_equity_week_high`、`realized_pnl_week`、`rolling_stats`）。这 4 个字段**同源于「无历史 state」这一个事件**，若按缺失字段数各触发一次降档，则 `20% → 15% → 10% → 5% → 0`，**新账户首日必然做不了 T**——那不是保守，而是把同一个事件罚了 4 次，把规则推到它自己无法执行的地步，规则本意从未如此。故裁定：
> - ① T 仓上限 = 三态名义上限**降一档**，且在 `t_cap.downgrades` 中记为**恰好一个** `source = "cold_start"` 条目，**严禁按缺失字段数累计降档**；
> - ② 本次**仅做 A 档信号**（纯价格阈值，可挂条件单）；
> - ③ **每日轮次上限不变**——轮次上限管的是频率累积风险，单轮风险已由 ① 控制；再砍轮次会使**上涨态**（名义 ≤1 轮）直接归零，在上涨态重造同一个死锁。本条明确否决"冷启动轮次 −1"的做法；
> - ④ 报告须**显著标注「冷启动档，风控历史不可核查」**，并落 state 的 `cold_start` 对象（`active` / `missing_fields` / `restrictions`）。
> 理由：① + ② 已是两重收缩，足以覆盖"历史不可核查"带来的不确定性。
>
> **权益字段的三级取数降级链（逐级尝试，让用户能一步跳出冷启动档）**：
> - ① **命中紧邻上一交易日的已结算 state**（`settled == true`）→ 取其 `account_equity` 作本次 `prev_close_equity`（即上述四步，口径不变）。命中份**不紧邻**上一交易日（中间有未结算交易日）→ 本级**不可用**，转 ②，**严禁**用更早那一日的权益充当昨收权益；
> - ② **①不可用，但 `position` 入参提供了「昨收账户总资产」** → **采用**，来源标注「用户提供」（券商 App「昨日资产 / 参考市值」直接可见；性质同 `cost` / `news`，一手信息、有来源、不违反 ETA1）。采用 ② 时**冷启动状态就口径 A 单日档部分解除**；若 `account_equity_week_high` 仍缺失，单周档仍标"不可核查"，但**不再额外降档**（同属冷启动这一个事件）；
> - ③ **二者皆无** → 口径 A 单日档标「**不可核查**」，按上述**冷启动档**执行。
>
> **单日档与单周档的不对称缺失处置（这是刻意的，不是疏漏）**：
> - 口径 A / B 的**单日**档缺失 → **可自动降一档**（惩罚轻，且与冷启动档**合并计一次**）；
> - 口径 A / B 的**单周**档缺失 → **只标注 + 要求用户人工确认，不自动触发**。理由：单周档的动作是「暂停做 T 一周」/「下周上限减半」，**代价过重，不能由"数据缺失"这种非风险事件自动触发**。人工确认话术两句：「**本周账户总资产是否已从周内最高点回撤超过 3%？**」「**本周 T 交易已实现亏损是否已超总资金 0.8%？**」用户答"未超" → 按未触发处理，并标注「依据用户口述，未经数据核实」（有来源，不违反 ETA1）；用户不答 / 答不出 → 标「单周档不可核查」，**但不额外降档**。
> - ⚠️ 以上均**不放松 ETA10 边界**：标「不可核查」**≠** 标「未触发」。区别在于——"不可核查"是既不触发动作、也不宣称安全；把 `null` 当 0 则是**宣称"单周未触发"**，后者严禁。
>
> **口径 A 单周跌幅** = `(account_equity_week_high − account_equity) / account_equity_week_high`，其中 `account_equity` = 当日收盘账户总资产（底仓市值 + 现金）。
>
> **口径 A 单日跌幅（基准 = 昨收权益，唯一口径）** = `(prev_close_equity − equity_now) / prev_close_equity`。三个权益字段一律取**市值口径**（底仓按收盘市价计的市值 + 现金），**严禁用成本口径的 `total_capital` 参与口径 A 计算**；多标的时这三个字段为**账户级**、各份 state 须一致（以时间戳最新者为准，不一致则报告提示"账户级字段不一致，口径 A 结论可能失真"）。
> `prev_close_equity`（上一交易日收盘账户总资产）同样**依赖历史 state 或用户提供**：按上述**三级降级链**取（① 命中**紧邻上一交易日**的已结算 state → 取其 `account_equity`，不紧邻则本级不可用；② `position` 提供了昨收账户总资产 → 采用并标「用户提供」；③ 皆无 → 写 `null`、标注「**口径 A 单日档不可核查**」并按**冷启动档**执行）。
> 选昨收权益而非当日峰值权益的三条理由（须写入报告 §六 或 §九）：① **可复现**——昨收权益唯一确定，日内峰值权益需 tick 级记录、散户拿不到且不同采样频率结果不同；② 与市场惯例一致（涨跌幅一律以昨收为基准）；③ 单周档能用 `week_high`，是因为**周内峰值可由每日收盘权益序列构造**，而日内峰值不能——两者**可得性不同故基准不同，这不是口径不一致**。
>
> [强约束] ④ 情形下**严禁把 `null` 当 0** 处理后宣称"单日/单周未触发、未超限"（ETA10），两套口径、单日与单周四种档位同样适用。

套用 [report-template.md](./references/report-template.md) 生成完整报告（九节），写入 `{outputDir}/etf-t0-{6位代码}-{date}.md`；同时产出状态文件 `{outputDir}/etf-t0-{6位代码}-{date}.state.json`（格式见主文档 `T0日内回转交易体系.md` 附录 B 修订版）。最后向 stdout 打印一句话行动建议（做 / 观望 / 停手）、报告路径与状态文件路径，并**追加一行交接问询**：「需要基于本报告生成个性化操作手册（成本锚点 / 全天分时时间表 / 具体挂单价 / 错误预案）吗？」——本步到此结束并等用户答复；用户同意后由 `etf-t0-execution` skill 以本报告路径作为其 `reportPath` 执行，**严禁**在本 skill 内生成操作手册（ETA12）。

**完成标准**：交接问询已发出且未擅自生成操作手册；报告九节齐全、风控核查节全部打勾或标注（含两套口径的单周可用性标注、冷启动状态 `cold_start.active` 及其 `missing_fields` / `restrictions`、以及**写成五行表格**的推导链与唯一「当前生效上限」`t_cap.effective`）、`t_cap` 已通过五条不变式 I1–I5 自检、报告与状态文件均写入成功。

### 状态文件字段

`.state.json` 在主文档附录 B 基础字段（`symbol`、`name`、`total_shares`、`cost_basis`、`cash`、`total_capital`、`regime`、`params`、`open_rounds`、`sell_triggers`、`buy_triggers`、`risk_lines`）之上，必须包含以下风控与口径字段，供次日续用与自动化衔接。字段按**账户级 / 标的级**分组：

**账户级字段**（多标的时各份 state 中的值**必须一致**；以本次运行**时间戳最新的一份**为准；发现各份不一致 → 报告显式提示「账户级字段不一致，口径 A 结论可能失真」，**不擅自取其一静默使用**）

| 字段 | 含义 |
|------|------|
| `account_equity` | 当日收盘**账户总资产（市值口径）** = 底仓按**当日收盘市价**计的市值 + 现金，等同券商 App 的「账户总资产」；对接 §5.2 回撤口径 A |
| `prev_close_equity` | 上一交易日收盘账户总资产（**市值口径**）= 口径 A **单日**跌幅的基准；`口径A单日跌幅 = (prev_close_equity − equity_now)/prev_close_equity`。取历史 state 的 `account_equity`；未命中且用户未提供 → 写 `null` 并标注「口径 A 单日档不可核查」（**不得当 0**，ETA10） |
| `account_equity_week_high` | 本自然周内 `account_equity` 的峰值（**市值口径**）；`口径A单周跌幅 = (week_high − equity)/week_high`。按 STEP 7 四步口径续算（同周取较大者、跨周以本日 equity 重起算），未命中历史 state 时写 `null`（**不得当 0**，ETA10） |

> [强约束] **口径一致性**：上述三者一律为**市值口径**，三者同口径才可比，**跨口径相减得出的跌幅无意义**。附录 B 的 `total_capital` 是**成本口径**（持仓市值按成本估算 + 现金），**严禁用 `total_capital` 参与回撤口径 A 的任何计算**。附录 B 示例中两者数值相同仅因**成本价 = 市价**，非通例，实盘必然分叉。

**标的级字段**（各份 state 独立，多标的时不要求一致；组合层"合计 T 仓 ≤ 20%"校验仍按 framework §3 单独执行）

| 字段 | 含义 |
|------|------|
| `rounds_used_today` | 当日已开仓轮次（对接 framework §5.1 铁律 3 单日 ≤3 轮；部分成交仍计 1 轮） |
| `consecutive_losses` | 当前连亏轮次（对接铁律 4 连亏 3 轮停手） |
| `realized_pnl_today` | 当日 T 交易已实现盈亏（占总资金，对接 §5.2 回撤口径 B 单日档） |
| `realized_pnl_week` | 本周 T 交易已实现盈亏累计（占总资金，对接口径 B 单周档）；按 STEP 7 四步口径由上一份 state 文件续算，未命中历史 state 时写 `null`（**不得当 0**，ETA10） |
| `risk_state.t_cap` | 五步结算的**结构化对象**，挂在 `risk_state` 下（与被替换的两个旧平铺字段同位；**不保留旧名别名**）。完整路径示例：`risk_state.t_cap.effective`、`risk_state.t_cap.derivation_text`。子字段：`nominal`、`nominal_source`、`downgrades[]`、`after_downgrade`、`halved`、`halve_sources[]`、`after_halve`、`effective`、`derivation_text`。`t_cap.effective` = 当前生效 T 仓上限（小数），**必须落在 `0.20 / 0.15 / 0.10 / 0.05 / 0` 之一**；`t_cap.derivation_text` = 推导链字符串，与报告 §五 五行推导链表格一致。**必须同时满足不变式 I1–I5**（见下），任一不满足即为结算错误（RF-ETA3） |
| `risk_state.cold_start` | 冷启动状态对象，同样挂在 `risk_state` 下。完整路径示例：`risk_state.cold_start.active`。子字段：`active`（bool）、`missing_fields[]`（实际缺失的跨日字段，如 `prev_close_equity` / `account_equity_week_high` / `realized_pnl_week` / `rolling_stats`）、`restrictions[]`（如 `t_cap_downgrade_1`、`signal_tier_A_only`）。与 `t_cap.downgrades` **非冗余分工**：`cold_start` 说明**为什么**（哪些字段缺、施加了哪些限制），`t_cap.downgrades` 承载**算术效果**（一个 `cold_start` 条目）。约束：`cold_start.active == true` **⟺** `downgrades` 中存在**恰好一个** `source == "cold_start"` |
| `regime_asof` | 本次三态判定的基准日期（与 `regime` 配对） |
| `regime_confirm_days` | 三态连续一致天数（对接 §2.1 regime 二次确认，<2 表示过渡日、按更保守者执行） |
| `cost` | 本次所用成本参数：佣金率、单笔最低佣金 F、真实往返成本 2C、是否咬合 |
| `tick_size` | 最小变动价位（ETF 为 `0.001`，所有价位须落在该网格，对接 ETA9） |
| `halted` | 当日是否停牌/临停（true 则停做 T）；**复牌首日**须一并标注（铁律 5：复牌首日不做 T，量能失真） |
| `limit_lock` | 是否涨跌停封死（对接铁律 5 与 §5.3 例外过夜判定） |
| `rolling_stats` | 滚动统计：`sample_n`、`p_100`、`r_100`（优先取 `history`，其次沿用上一份 state 的 `rolling_stats`；两者冲突以 `history` 为准并在报告 §九 标差异值；样本不足时置 `null` 并标注"按执行硬顶保守端"） |
| `settled` | 该份 state 是否已结算。本 skill 在盘前/盘中写入，结算类字段（`account_equity`、`realized_pnl_today`/`_week`、`account_equity_week_high`）当时客观不可知，故一律写 `false`；收盘后由 `etf-t0-summary` 覆盖为 `true` 并补齐这些字段。STEP 7 命中的历史 state 若为 `false`，其结算类字段仍是计划态（按 ETA10 应为 `null`），按"未命中"处置 |

字段值缺失时写 `null` 并在报告 §八 说明原因，**严禁**填臆测值（ETA1）。

#### `risk_state.t_cap` / `risk_state.cold_start` 结构与枚举（不得自造枚举值）

两者均挂在 `risk_state` 下——与被替换的旧平铺字段同位置（最小破坏），且 `risk_state` 本就是风控状态的聚合节点，语义归属一致。

```json
"risk_state": {
  "t_cap": {
    "nominal": 0.20,
    "nominal_source": "range",
    "downgrades": [
      {"source": "circuit_breaker", "detail": "盘中突变熔断"},
      {"source": "drawdown_a",      "detail": "口径A单日跌幅1.4%，落1%–2%档"}
    ],
    "after_downgrade": 0.10,
    "halved": true,
    "halve_sources": ["drawdown_b"],
    "after_halve": 0.05,
    "effective": 0.05,
    "derivation_text": "0.20 名义（震荡）→ 降2档 0.10 → 口径B减半 0.05 → 取格 0.05"
  },
  "cold_start": {
    "active": true,
    "missing_fields": ["prev_close_equity", "account_equity_week_high",
                       "realized_pnl_week", "rolling_stats"],
    "restrictions": ["t_cap_downgrade_1", "signal_tier_A_only"]
  }
}
```

```
nominal_source ∈ { range | downtrend | uptrend | transition }
  transition = regime 二次确认过渡日，nominal 取新旧两态更低者

downgrades[].source ∈ {
  cold_start          冷启动·无历史 state（至多出现一次）
  circuit_breaker     盘中突变熔断（framework §2.3）
  drawdown_a          回撤口径 A 单日 1%–2% 档
  broker_capability   券商能力不支持
  flatten_exception   收盘清零例外惩罚（当周有效）
}

halve_sources[] ⊆ { drawdown_b（回撤口径 B）, decay（策略衰减疑似）}
```

#### 五条可机械校验的不变式 I1–I5（`t_cap` 必须全部满足）

```
LADDER = [0.20, 0.15, 0.10, 0.05, 0.00]

I1  nominal ∈ LADDER，且与 nominal_source 相容
      range → 0.20 ; downtrend → 0.15 或 0.10 ; uptrend → 0.10 ; transition → 取两态更低者

I2  after_downgrade == LADDER[ min(index(nominal) + len(downgrades), 4) ]
      且 downgrades 中 source == "cold_start" 的条目【至多一条】

I3  halved == (len(halve_sources) > 0)
      after_halve == after_downgrade / 2      若 halved
      after_halve == after_downgrade          若 !halved
      （halve_sources 可含多个，但只减一次）

I4  effective == max{ x ∈ LADDER : x <= after_halve }      （向下取格）

I5  effective ∈ LADDER
```

> **这五条解决什么问题**：原 `RF-ETA3` 只盯「`effective` 是否落在五个格点」，抓不住「**该降 2 档只降了 1 档**」这类算术错误——因为结果 `0.10` **照样在格点上**，red flag 全部通过，而下单量已经错了。I2/I3/I4 把每一步的输入、触发源数量与输出**绑成可逐字段比对的等式**，使模型的算术错误可被机械检出；报告 §五/§六 因此必须把推导链写成**五行表格**，与本 JSON 逐字段对应，让**人工复核与机械校验用同一份数据**。

### 退出码

> 退出码判定为决策树，**按序命中即定**：① 输入非法或 `symbol` 无法核实 → **2**；② 接口超时/写文件失败等可重试故障 → **1**；③ **标的属货币/债券 ETF 等范围外品种** → **0**（报告结论为"不适用本体系"）；④ **成本硬门槛不通过**（最低佣金咬合且单轮金额低于阈值）→ **0**（分析已完成，报告结论为"不适合做 T"）；⑤ **复牌首日** → **0**（报告结论为"当日不做 T"，铁律 5）；⑥ **标的停牌** 或 **日线样本不足致三态无法判定** 或 **三态无法判定**（行情/K 线不可得）**或 基本面闸门无法判定**（新闻大面积缺失且用户未提供 `news`）→ **3**；⑦ 三态可判、且基本面闸门明确（通过或触发）→ **0**（新闻部分缺失但不影响闸门时，仍判 0，并在"数据完整度"标"部分缺失"）。

| exitCode | 含义 | 触发场景 | 后续动作 |
|---------|------|---------|-----------|
| 0 | 分析完成 | 三态可判、基本面闸门明确；或得出"不适合做 T"（成本硬门槛不通过）/"不适用本体系"（货币、债券 ETF 等范围外品种）/"当日不做 T"（复牌首日、涨跌停封死）等明确结论；数据完整或仅非关键项缺失 | 读取报告 → 用户决策 |
| 1 | 执行失败（可重试） | 联网/行情接口超时、写文件失败 | 询问用户：重试 / 终止 |
| 2 | 输入异常（不可重试） | `symbol` 缺失或无法核实、`date` 格式非法、`cost` 无法解析出佣金率与最低佣金 | 提示用户修正参数 |
| 3 | 需人工决策 | 标的当日停牌/临停、**日线样本不足致三态无法判定**、**三态无法判定**（无行情/K 线）**或 基本面闸门无法判定**（新闻大面积缺失且无 `news`），仅能给框架性/观望建议 | 提示用户补 `news` 或数据源后重跑 |

## 危险信号（Red Flags）

以下可观测信号表明执行出现偏差，出现任一项必须回退修正：

- RF-ETA1: 报告中出现无来源、无时间戳的具体新闻/公告/资金数字
- RF-ETA2: 出现"预计上涨 X%""稳赚""必涨"等确定性收益或涨跌预测措辞
- RF-ETA3: 策略节出现"择机""注意风险""灵活操作"等无具体价位/数值的表述；或盘口价差/深度/滑点三项只打勾、未给出实际数值与门槛比对；或出现 7.5% 这类不在 T 仓上限阶梯格点上的"生效上限"（`t_cap.effective` 不在 `0.20/0.15/0.10/0.05/0` 之一即为结算错误）；**或违反 I1–I5 任一不变式亦为结算错误**（典型形态：该降 2 档只降了 1 档，结果 `0.10` 照样在格点上、只有 I2 能抓到；或 `halved` 与 `halve_sources` 不一致、`effective` 未向下取格、`cold_start` 条目出现多于一条）；或只给出生效上限结果而无五步推导链表格（缺 `t_cap.derivation_text`）
- RF-ETA4: 未给出三态判定（或只写结论、不写 20 日线斜率数值与阈值判定过程），或三态为"下跌"却建议正向 T 接飞刀等打法错配
- RF-ETA5: 当日情况用了明显过时的数据却未标注"数据缺失"
- RF-ETA6: 报告缺少风控核查节，或核查项被跳过而非打勾/标注，或只写一套回撤口径
- RF-ETA7: 报告出现替用户下单、或省略免责声明
- RF-ETA8: 对近 20 日均振幅 < 该价格档「所需最低振幅」的标的直接套用静态表 W/L，或静态表口径下未给出振幅校验过程
- RF-ETA9: 出现无口径来源标注的支撑/阻力/区间价位，或出现 0.1234 这类不落在 0.001 元 tick 网格上的不可下单价
- RF-ETA10: `realized_pnl_week` 在无历史 state 时被填成 0、或风控节写出"单周回撤未触发"却无历史 state 支撑；或 `account_equity_week_high` / `prev_close_equity` 缺失时写出"口径 A 单周/单日未触发"；或存在超出生效上限的未平轮却未在报告中写出；或**用成本口径的 `total_capital` 代替市值口径权益字段计算回撤口径 A**（跨口径相减，跌幅必错）；或多标的时各份 state 的账户级字段不一致却静默取其一；亦包括出现未定义的"降一档"（未写出降档后的当前生效上限）、跨境 ETF 折溢价缺失后照常给正向 T 策略、或用月度胜率（15–25 轮样本）作为仓位增减依据；或**冷启动时按缺失字段数累计降档**（4 个缺失字段各降一档 → 归零），或 `cold_start.active = true` 却在 `t_cap.downgrades` 中出现 0 条 / 多于 1 条 `cold_start` 条目，或**因单周档数据缺失就自动执行"暂停做 T 一周 / 下周上限减半"**（单周档缺失只标注 + 人工确认，不自动触发）；或**采信了 `settled != true` 的计划态 state 的结算类字段**；或**用不紧邻上一交易日那一份 state 的 `account_equity` 充当 `prev_close_equity`**（中间隔了未结算交易日，昨收基准即错）；或**把跨过未结算交易日续算出的单周累计值当作已核实值**（漏掉中间各日盈亏与权益峰值会低估回撤，属危险方向）
- RF-ETA11: 报告引用了涨跌幅 / 临停阈值 / 税费 / 最小变动价位 / 申报单位 / 集合竞价时段等交易所规则数值，却**未写出快照日期**；或快照日期已超 **180 天**却未标「规则快照可能过期，须复核」；或把主文档**附录 D** 中标「待核实」的行**填成了具体数值**
- RF-ETA12: 报告中出现逐时段操作时间表、个人成本锚点、按用户现金算出的股数或具体挂单尾数等执行层内容；或未发出交接问询即产出了操作手册文件

## 反合理化（Anti-Rationalization）

| 借口 | 反驳 |
|------|------|
| "找不到实时数据，我按常识补一个合理数字" | 编造数据比没有数据更危险。缺失就标注缺失，让用户知道该补什么。 |
| "用户就想知道能赚多少，给个明确收益更爽快" | 收益依赖胜率与标的走势，是假设不是承诺。给确定数字就是误导。 |
| "行情瞬息万变，策略写模糊点更安全" | 模糊策略无法执行也无法复盘。做 T 的价值正在于纪律化的具体价位。 |
| "三态判定太麻烦，直接给买卖点更快" | 三态错则打法全错，是本体系最大亏损来源。判定不可省。 |
| "只报机会不报风险，报告更好看" | 只报机会等于诱导。风控核查是报告的一部分，不是附加项。 |
| "低波动 ETF 也用静态表 0.10 的差价，反正好记" | 静态表隐含要求日内振幅 3.6%–6%。价 5 元、振幅 1.5% 的标的全天高低差仅 0.075 元，小于 W=0.10 本身，一轮 T 根本不可能成交——好记的代价是策略在数学上无法执行。 |
| "支撑阻力凭经验给个价位就行，用户看不出来" | 无口径的价位不可复现、不可回测，也无法判断上沿−下沿是否容得下一轮 T。用户看不出来，账户看得出来。 |
| "找不到上一天的 state，单周盈亏就先当 0 算，反正大概没超" | 把 `null` 当 0 会伪造出"单周未触发"的结论，正好在最该停手的时候放行。不可用就写不可用，只按单日口径核查。 |
| "取不到 IOPV，跨境 ETF 的溢价这项就跳过" | 跳过等于默认无风险。溢价回归能在标的市场平盘时单独砸 3%+，与 W/L 无关。要么用代理指标并标注，要么保守停做正向 T。 |
| "这些交易所规则很久没变了，不用标日期" | 规则没变不等于你核对过。未标日期的数值无法判断是哪一版；按过期的临停阈值设应对方案 = 临停时无法平仓，直接破坏收盘清零。 |
| "用户肯定想直接知道怎么操作，报告里顺手把时间表和挂单价一起写了" | 执行层要的是用户的成本价、持仓股数、可用现金与能否盯盘，报告里没有这些输入，凭空写出的时间表与股数只能是猜的。先出策略、再问人、再落手册，顺序不可颠倒。 |
| "首次运行缺了 4 个跨日字段，那就降 4 档、首日别做 T，最保守" | 4 个字段同源于「无历史 state」这一个状态，按 4 次罚等于把规则推到自己无法执行——新账户永远做不了首日 T，这不是规则本意。冷启动只降一档 + 只做 A 档信号，轮次不变；用户填一个「昨收账户总资产」即可跳出。 |
