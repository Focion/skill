# 数据获取口径速查（方式 2：公开接口 + 联网工具）

> 本文件定义各类数据用什么工具、怎么取、字段怎么解析。
> 铁律：**取到什么用什么，取不到就标注"数据缺失"**（对接 SKILL 约束 ETA1/ETA5/ETA9、退出码 3）。公开接口字段顺序**可能随时变更，以实际返回为准**；解析前先看一眼原始返回再对字段。
> **工具无关原则**：下文点名的联网工具（WebSearch/WebFetch 等）仅为**示例**，实际以当前环境可用的等效工具为准（联网检索工具、新闻类 MCP、浏览器工具，或用户直接提供的原文）。**严禁把任何具体工具名当作硬前置条件**——工具缺失时走降级链，而非直接放弃整个维度。

## 一、数据类型 → 工具映射

| 数据 | 工具（示例，取环境等效者） | 用于 STEP |
|---|---|---|
| 新闻 / 公告 / 政策 / 舆情 | 用户提供的 `news` 优先 → 联网检索工具（如 WebSearch/WebFetch 或等效 MCP/浏览器工具） → 已知公告页 WebFetch | STEP 3 利空利多 |
| 标的基础信息（跟踪指数/规模/成交额） | 联网检索工具 / 行情快照接口 | STEP 2 核实 |
| 实时快照（价/量/五档/振幅） | `Bash` + 新浪(主)/腾讯(备)接口 | STEP 4 盘面 |
| 日线 / 分钟 K 线（算三态/ATR/放量/日均额） | `Bash` + 东财(主)/新浪(备)/腾讯 K 线接口（见 §4.1） | STEP 2、STEP 4 盘面 |
| IOPV / 折溢价 | 见 §五（多数免费接口不直接提供） | STEP 4 折溢价 |
| **交易日历（`date` 是否交易日 / 是否停牌）** | 见 §九（周末自查 → 用户明示 → 日线最近一根日期 → 快照日期字段 → 交易所休市公告） | STEP 1 归一化 `date`、STEP 5 时段视角 |
| **ETF 份额 / 规模变化（申赎资金进出）** | 见 §5.1（免费接口普遍不提供份额 → 走降级链，取不到标数据缺失） | STEP 3 资金面（info-checklist §D） |
| **账户成本参数（佣金率、单笔最低佣金 `F`）** | 见 §十 —— **来自用户 `cost` 入参或用户口述，不是接口取数**，无法联网核实 | STEP 2 成本硬门槛、STEP 4 K（calc-methods §八） |
| **账户权益类字段（`prev_close_equity` 昨收账户总资产、`account_equity_week_high`）** | 见 §10.1 —— **只能来自历史 state 或用户 `position` 入参，不是接口取数**，无法联网核实 | STEP 5 回撤口径 A（framework §5.2） |
| **交易所规则数值（最小变动价位、申报单位、涨跌幅、临停阈值、集合竞价时段、印花税/过户费）** | **主文档【附录 D 外部规则快照表】为唯一出处** —— 只引用、不复写；引用须带该行**快照日期**（ETA11） | 全流程（§三、§八、§九、calc-methods §七/§八/§九） |

## 二、新闻面（工具无关 + 降级链）

**取数按优先级降级，直到取到或标注缺失——严禁因某个工具缺失就整块放弃：**

1. **用户提供的 `news`（最高优先）**：入参 `news` 有内容时，先解析用户粘贴的新闻/公告原文或链接，作为一手信息（来源标注为"用户提供"+ 用户给的时间/出处）。
2. **联网检索工具**：环境有 WebSearch/WebFetch 或等效检索类 MCP / 浏览器工具时，搜："{ETF名称} 公告"、"{跟踪指数} 政策"、"{赛道} 行业 最新"、"{前十大权重股} 业绩/减持"，对命中的交易所/基金公司公告页、财经门户提取正文。
3. **已知公告页直取**：知道交易所/基金公司公告页 URL 时，用可用的抓取工具直接取正文。
4. **以上全不可用** → 该维度标注 `数据缺失`，并在报告显著提示"基本面/消息面缺失，基本面闸门无法判定，建议用户补 `news` 后重跑"（对接退出码 3）。

- 每条落库：信息 + 定性 + 强度 + **来源 + 时间戳**（无来源不得写入，ETA1；用户提供的也要标"用户提供"及其时间）。

## 三、实时快照（新浪，主用）

**接口**：`https://hq.sinajs.cn/list=<prefix><code>`　**必须带 Referer，返回是 GBK 需转码**。

```bash
curl -s --max-time 8 -H 'Referer: https://finance.sina.com.cn/' \
  'https://hq.sinajs.cn/list=sh510300' | iconv -f GBK -t UTF-8
```

返回：`var hq_str_sh510300="沪深300ETF华泰柏瑞,4.750,4.787,4.813,4.820,4.750,...,2026-07-22,11:24:30,00,";`

**字段（逗号分隔，下标从 0）**：

| 下标 | 含义 | 下标 | 含义 |
|---|---|---|---|
| 0 | 名称 | 6 | 买一价 |
| 1 | 今开 | 7 | 卖一价 |
| 2 | 昨收 | 8 | 成交量（**股**） |
| 3 | **现价** | 9 | 成交额（元） |
| 4 | 最高 | 10–19 | 五档买（量,价 ×5） |
| 5 | 最低 | 20–29 | 五档卖（量,价 ×5） |
| | | 30 / 31 | 日期 / 时间 |

**可直接算**：当日振幅 =(下标4−下标5)/下标2（口径见 calc-methods §四）。

**五档 → 盘口价差与深度的取数字段**（完整计算口径见 [calc-methods.md](./calc-methods.md) §九「盘口价差、深度与滑点估算」，此处只给字段对应，不重复公式）：

| 指标 | 取数字段 | 用于 |
|---|---|---|
| 一档价差 | **下标 7（卖一价） − 下标 6（买一价）**；相对价差 = 一档价差 / 下标 3（现价） | 门槛 `一档价差 ≤ W/5` |
| `depth_buy`（**买入**时看卖侧） | 下标 20–29 中**卖一~卖三**的挂单量之和 | 门槛 `depth ≥ 本轮计划股数 × 3` |
| `depth_sell`（**卖出**时看买侧） | 下标 10–19 中**买一~买三**的挂单量之和 | 同上 |
| 预估滑点 | `max(1 个最小变动价位, 一档价差 / 2)`；单边穿档时按穿过档位的加权均价与买一/卖一之差计 | 校验 framework §1 边界条件「滑点 < W/3」 |

> ⚠️ **集合竞价（三段，缺一不可）与临停期间五档失真**：价差、深度、滑点**三项判定一律标注"不可用"**，不得用失真盘口下结论、更不得据此宣称门槛通过。三段为：
> ```
> 09:15–09:25（开盘集合竞价）、09:25–09:30（无撮合）、14:57–15:00（收盘集合竞价）
> ```
> 📌 **三段缺一不可的理由**：这三段的五档均不反映连续竞价的真实可成交量，**漏掉任一段都会让该时段的失真盘口被当作有效盘口使用**（旧版本处漏掉 14:57–15:00 收盘集合竞价段）。时段取值以**主文档附录 D**「集合竞价时段」行为唯一出处，引用时须带该行**快照日期**；快照为空或距分析日 > 180 天 → 标「规则快照可能过期，须复核」（ETA11）。与 calc-methods §9.4 同口径。
> ⚠️ 单位注意：新浪五档挂单量为**股**（与下标 8 一致），与"本轮计划股数"同单位可直接比；若改用腾讯快照（§六）取五档，须先核对其量单位再比对。

> ⚠️ **停牌 / 涨跌停的快照特征**（完整判定见 §九）：交易时段内现价为 0 或成交量为 0 → 疑似停牌；买一价（下标 6）为 0 → 疑似跌停封死；卖一价（下标 7）为 0 → 疑似涨停封死。三者均属"当日不做 T"情形（framework §5.1 铁律 5），不得当作正常盘口继续推 W/L。

## 四、日线 / 分钟 K 线（东方财富）

**接口**：`https://push2his.eastmoney.com/api/qt/stock/kline/get`

```bash
# secid: 1.=沪  0.=深 ; klt: 5=5分 15/30/60 101=日线 ; fqt: 1=前复权 ; lmt: 取多少根
curl -s --max-time 10 \
 'https://push2his.eastmoney.com/api/qt/stock/kline/get?secid=1.510300&klt=101&fqt=1&fields1=f1,f2,f3&fields2=f51,f52,f53,f54,f55,f56,f57&end=20500101&lmt=60'
```

返回 `data.klines[]`，每根为逗号串：**`时间,开,收,高,低,成交量(手),成交额`**。

> ⚠️ **顺序是"开·收·高·低"（O,C,H,L），不是常见的 OHLC**；成交量单位为**手（×100=股）**。解析 ATR 的 TR 时高=第 4 段、低=第 5 段，别取错。

**用途**：
- 取日线 60+ 根 → 算 20/60 日均线、三态（framework §2.1）、ATR(14)、近 20 日均振幅（calc-methods §二、§四）、**近 20 日日均成交额**。
- 取 5 分钟线 → 近 20 根均量做放量判定（calc-methods §一）。

> ⚠️ **成交额门槛口径（易踩坑）**：做 T 标的门槛"日均成交额 ≥ 5 亿"（info-checklist K）必须用**日线近 20 根成交额算日均**，**严禁**用盘中当日尚未走完的半日成交额直接对比全日门槛（半日额天然偏小、且当日未定型会误判）。盘中只想用当日额佐证活跃度时，须显式标注"当日半日额、仅供参考"，门槛达标与否以近 20 日日均额为准。

### 4.1 K 线备用源（东财不可达时切换，实测顺序：东财 → 新浪 → 腾讯）

某些环境东财域名不可达（返回空）。**降级顺序**：东财（有成交额字段，首选）→ 新浪日线（字段最干净，推荐备用）→ 腾讯日线。

**新浪日线**（返回标准 `OHLC` 顺序、量单位为**股**，无成交额字段）：

```bash
# scale: 240=日线 5/15/30/60=分钟线 ; datalen: 取多少根
curl -s --max-time 12 'https://money.finance.sina.com.cn/quotes_service/api/json_v2.php/CN_MarketData.getKLineData?symbol=sh513310&scale=240&ma=no&datalen=70'
```

返回 JSON 数组，每根 `{"day","open","high","low","close","volume"}`。

> ⚠️ 与东财不同：新浪是**正常 OHLC 顺序**、`volume` 单位为**股**（东财为 O,C,H,L 且量为手）。**无成交额字段** → 日均成交额须**估算 = 均价 × 量**（均价可取 `(H+L+C)/3`），并在报告标注"成交额为估算值"。

**腾讯日线**（次级备用，前复权）：

```bash
curl -s --max-time 12 'https://web.ifzq.gtimg.cn/appstock/app/fqkline/get?param=sh513310,day,,,80,qfq'
```

返回 `data.<代码>.day[]`，每根 `[日期, 开, 收, 高, 低, 量]`（**O,C,H,L 顺序，同东财**；量为手），同样无成交额字段，需估算。

### 4.2 日线根数不足（新上市 / 停牌久 / 接口截断）

`lmt=60` / `datalen=70` **只是请求值，不是保证值**。新上市 ETF、长期停牌或接口截断时实际返回会少于请求根数，而三态需要 60 日线、ATR(14) 需要 15 根、近 20 日均振幅需要 21 根。

**检测（必须做，不许假定取满）**：解析后先数长度——东财 `data.klines[]` 的数组长度、新浪返回数组长度、腾讯 `data.<代码>.day[]` 长度；把**实际根数写进报告的「数据完整度」**。

| 实际可用日线根数 | 可算 | 不可算 | 处置 |
|---|---|---|---|
| ≥ 61 | 20/60 日线、20 日线斜率、ATR(14)、近 20 日均振幅、近 20 日日均额 | — | 正常，全口径可用 |
| 21 – 60 | 20 日线与其斜率（calc-methods §六）、ATR(14)、近 20 日均振幅、近 20 日日均额 | **60 日均线** | 三态按 20 日线斜率口径判（calc-methods §六）+ tie-break（framework §2.1）；「均线排列 20/60」一项标 `数据缺失`，报告注明"60 日线不可得，三态仅由 20 日线斜率与价格位置支撑，置信度下调" |
| 15 – 20 | ATR(14) | 20 日线斜率、近 20 日均振幅、近 20 日日均额 | **三态无法判定** → 按 SKILL 退出码 3；成交额/振幅门槛一并标 `数据缺失`，只出框架性报告 |
| < 15 | 几乎无 | ATR(14) 亦不可算 | 三态与 W/L 均不可得 → 退出码 3；若确需给差价口径，按 framework §4.4 的"退回静态表"情形①处理，**且必须额外确认近 20 日均振幅 ≥ 该档「所需最低振幅」——该确认本身也算不出时，结论只能是"不做"** |

> ⚠️ **严禁用不足样本硬算**：不得把 40 根当 60 根用（如"用现有最长均线代替 60 日线"）、不得把 12 根 TR 当 ATR(14)、不得用不足 20 个交易日的均振幅去比 1.5%/4% 门槛。样本不足是**降级 + 标注**事由，不是四舍五入事由。
> 📌 新上市 ETF（上市不足 3 个月）天然落在此节：其"近 20 日日均成交额"与振幅尚未定型，报告须显式提示"上市初期数据不稳定，门槛判定为暂定值"。
> 📌 换源不改变根数结论：东财取不到 60 根时换新浪/腾讯多半也取不到（是标的历史短，不是源的问题）；但仍应换源核对一次，确认是"标的没有"而非"接口截断"。

## 五、IOPV / 折溢价（诚实处理）

- **多数免费快照接口不直接提供场内 ETF 的 IOPV**。优先用行情终端/数据商接口的 IOPV 字段；无把握时**不要臆造**，按 calc-methods §三标注 `IOPV 失真/缺失`，折溢价一节写"数据缺失"。
- ⚠️ **严禁用"现价 vs 跟踪指数涨幅"倒推折溢价**：指数涨幅不等于净值，二者差异含成分停牌、汇率、费用与仓位偏离，倒推值不可信 → 该维度只能标 `数据缺失`。
- **折溢价口径按品种分两栏，先分类再套口径（不得混用）**：

| 品种 | 折溢价判定口径 | 取数要求 |
|---|---|---|
| **境内股票型 ETF**（无额度限制） | 沿用 calc-methods §三 的**绝对阈值表**（±0.3% / ±0.5%） | 需当日 IOPV；取不到 → 该维度标 `数据缺失` |
| **跨境 / QDII / 商品 ETF**（有额度或申赎限制） | **绝对阈值表不适用**（其常态溢价可达 5%+，会系统性误报）→ 一律走 §5.2 的**三级降级口径** | 按三级依次尝试，每级取数要求见 §5.2 |

> ⚠️ 不得把境内股票型 ETF 的 ±0.5% 阈值套到跨境/商品 ETF；分类不明时按"常态溢价品种"从严处理（走三级降级）。

### 5.1 ETF 份额 / 规模（info-checklist §D 要求，免费接口普遍不提供份额）

info-checklist §D 要求"份额变化（申购/赎回，反映资金进出）"，但 §三/§四/§六 的快照与 K 线接口**都不返回份额**。份额与规模是两件事，必须分开处理：

| 指标 | 含义 | 可得性 |
|---|---|---|
| **规模（亿元）** | 净值 × 份额，是**存量快照** | 相对易得（基金公司/交易所产品页、财经门户 ETF 页），常滞后 1 日或为上季度末值 |
| **份额（亿份）及其变化** | 剔除净值涨跌后的**真实申赎方向** | 免费渠道多为按日/按周披露，常需逐日抓取；**多数免费接口不提供** |

**降级链（依次尝试，取到即止）**：

1. **用户提供**（`news` / `position` 附带的份额或规模数字）→ 标注"用户提供 + 用户给的时间"。
2. **基金公司官网 / 交易所官网的 ETF 产品页与公告页**（份额变动公告、定期报告、每日净值与份额披露页）→ 用可用的抓取工具取正文，**必须记录披露日期**（份额几乎总是滞后，不得当实时值用）。
3. **联网检索**："{ETF 名称} 份额 变化"、"{ETF 名称} 规模 亿元"、"{代码} 最新份额"，命中财经门户 ETF 数据页后取值 + 记来源与时间。
4. 全不可得 → §D 的份额项标 `数据缺失`，改用**可得的替代佐证**并明确标注是替代：近 5 日成交额趋势（§四 日线成交额，放量/缩量）、折溢价方向（§五，若可得）。
5. 报告中 §D 结论须写成"份额数据缺失，资金面结论仅由成交额趋势支撑，强度按弱计"。

> ⚠️ **不得臆造份额数字，也不得由成交额/成交量反推份额**——成交是二级市场换手，与一级申赎无数量关系，反推没有任何依据。滞后份额可以用，但必须写明"截至 YYYY-MM-DD 披露值，非当日"。
> 📌 规模只用于门槛判定（是否迷你基、清盘风险，info-checklist §F），**份额变化才是资金面信号**；只取到规模时不得声称"资金流入/流出"。

### 5.2 跨境 / QDII ETF 的取数陷阱（对接 framework §8）

跨境标的的折溢价数据在 A 股盘中**结构性不可信**，这不是接口质量问题，取数时必须先做这一层判定：

| 陷阱 | 取数表现 | 处置 |
|---|---|---|
| **标的市场休市 / 时差未开盘** | IOPV 停在上一收盘或按估值模型给固定值，全天不动或跳变 | 折溢价率**不可信** → 标注 `IOPV 失真（标的市场休市/未开盘）`，**不据此判多空、不据此调整进出场价** |
| **额度限制导致常态高溢价** | 溢价长期 1%–5%+，绝对值超阈值但属常态 | **不可简单当利空**，绝对阈值表不适用 → 走下方**三级降级口径**（framework §8） |
| **1 年 IOPV / 折溢价历史取不到** | 免费接口普遍不提供历史 IOPV / 历史折溢价序列 | 不得用绝对阈值反推"高溢价 = 利空" → 按三级降级的 ② 或 ③ 处理，并提示用户补数据 |
| **盘中公告停止 / 限制申购** | 溢价急剧扩大后急速回落，快照价与 IOPV 背离骤变 | 检索"{ETF 名称} 暂停申购 / 限制大额申购 公告"（§二 降级链）；**公告日不做 T** |
| **汇率叠加** | 与 IOPV 无关，但影响标的收益归因 | 纳入 info-checklist §A 宏观维度，不混入折溢价结论 |

**跨境溢价判定的三级降级口径（与 framework §8 一致，依次尝试、命中即定）**：

| 级 | 前提数据 | 判定 | 取数 |
|---|---|---|---|
| ① | **有 IOPV 历史序列**（近 1 年） | 溢价率 > 自身近 1 年 **80% 分位** → **停做正向 T** | 行情终端/数据商；免费源基本不提供 |
| ② | **无 IOPV 历史，但有二级价日线** | `当日收盘价 / 近 20 日均价 − 1 > +3%`（且标的市场同期无对应涨幅）→ **视同高溢价，停做正向 T** | §四 日线即可算（近 20 根收盘均价）；**必须标注「代理指标，非真实折溢价分位」** |
| ③ | **二者皆无** | 标注「溢价分位不可得」，对跨境 ETF **一律保守停做正向 T** | 无需取数 |

> 📌 ② 只要能取到日线就能走通，是免费环境下的主路径；③ 是兜底——跨境高溢价回归可在标的市场平盘时单独造成 3%+ 跌幅，与 W/L 无关，**不确定时按不做处理**。
> ⚠️ ② 的代理指标**不得写成"折溢价率 = X%"**，只能写成"二级价对近 20 日均价偏离 +X%（代理指标）"。

**标的市场休市判定**：先按 §九 判 A 股是否交易日，再单独判标的市场（美股/港股/日股等）当日是否开市——联网检索"{市场} {年份} 休市安排 / market holidays"，取不到则按"IOPV 可信度未知"保守标注。多日视角（info-checklist §四）须把标的市场休市日单独列出。

## 八、通用注意事项（务必核对）

- **时段**：仅交易时段（09:30–11:30、13:00–15:00）返回实时价；盘前/盘后/周末拿到的是上一交易日快照 → 当日情况须标注"非实时快照"。**`date` 是否为交易日必须先按 §九 判定**，不得默认"给了日期就是交易日"。
- **最小变动价位与申报单位（所有价位类输出的硬约束，对接 framework §1 / calc-methods §七）**：
  - 📌 **数值出处唯一**：最小变动价位与申报单位的**具体数值一律取自主文档【附录 D 外部规则快照表】**（「ETF 最小变动价位」「ETF 申报单位」两行），本文件只引用、不复写。引用时必须同时写出附录 D 该行的**快照日期**；快照日期为空、或距分析日 **> 180 天** → 必须标注「规则快照可能过期，须复核」，且不得把该数值当已核实事实使用（约束 **ETA11**）。
  - ETF 最小变动价位（值见附录 D） → 支撑/阻力/区间上下沿/买点价/卖点价/止损价**必须落在该最小变动价位网格上**，严禁输出 `0.1234`、`5.0725` 这类不可下单价；取整后须复核 `W ≥ 4×2C`、`上沿 − 下沿 ≥ 2W` 仍成立（取整可能吃掉几个 tick 的余量）。
  - ETF 申报数量（值见附录 D，按其「申报单位」行的整数倍） → 单轮 T 仓数量按 `floor(金额 / 价 / 申报单位) × 申报单位` **向下取整到整手**，不得输出 1350 份这类无法申报的数量；由此产生的零股按 framework §5 的收盘清零/部分成交规则当日清掉，不留隔夜。
  - 数量向下取整后，实际单轮金额会小于计划额 → 须回头核对是否仍满足最小单笔金额（framework §1 / calc-methods §八），差得太多则按"单轮实际成交额不足"处理。
  - ⚠️ **可转债：最小变动价位与 ETF 相同、申报单位与 ETF 不同**（附录 D，快照 **2026-07-27**）：
    - **最小变动价位 = 0.001 元**，与 ETF 一致 → 价位网格判定可沿用同一逻辑。
    - **申报单位 = 10 张**（每张面值 100 元），ETF 是 **100 份** —— **两者差 10 倍，且计量单位不同（张 / 份），严禁互换**。取整须写成 `floor(金额 / 价 / 10) × 10`，不是 `× 100`。
    - 📌 **由此反转的一处结论**：整手门槛对可转债 ≈ `10 × P` ≈ 1,000–1,300 元，**远低于**性价比下限 `40/w`（约 3,400–8,900 元）→ 可转债的绑定约束是**性价比下限，不是整手**。误按 `100 × P` 会把整手门槛**高估 10 倍**，进而错判"资金不够做不了"（详见 calc-methods §8.3）。
  - 📌 **适用范围声明（范围声明，非新规则）**：本体系覆盖 **股票型 ETF、跨境 ETF、可转债**；**货币 ETF、债券 ETF** 等报价单位与申报单位可能不同的品种**不在覆盖范围内**——如需覆盖，须先自行核实其最小变动价位、申报单位与费用结构，**不得把附录 D 的 ETF 最小变动价位 / 申报单位及本体系参数表外推套用**。
- **编码**：新浪/腾讯为 GBK，必须 `iconv -f GBK -t UTF-8`，否则中文名乱码。
- **单位**：新浪量=股、东财K线与腾讯量=手（×100）；算金额/放量时单位统一，勿混用。
- **限频/失败**：公开接口可能限频或偶发超时 → 失败按退出码 1（可重试）；重试仍失败则该项标注数据缺失。
- **字段漂移**：以上下标基于实测，但接口随时可能调整，**解析前先打印一次原始返回核对**，不匹配则以实际为准，不硬套。
- **合规**：接口仅用于个人分析取数，遵守各站点使用条款，勿高频抓取。

## 九、交易日历与"是否交易日"判定（STEP 1 需要）

**没有免费、稳定、通用的"交易日历"接口可直接依赖。** 判定一律靠下面的降级链推断，并**把用到的判定依据写进报告**。

### 9.1 降级链（依次尝试，命中即定）

| # | 方式 | 做法 | 结论强度 |
|---|---|---|---|
| 1 | **周末自查（零依赖，先做）** | 算 `date` 是星期几：周六/周日 → **非交易日**，直接定案 | 确定 |
| 2 | **用户明示** | 用户在入参或对话中说明"今天休市/今天开市/按上一交易日看" | 确定（标"用户提供"） |
| 3 | **日线最近一根 K 线的日期反推** | 取日线（§四），看最后一根的日期 `d_last`：`d_last == date` → `date` 是交易日；`d_last < date` → `date` **可能**是非交易日，**也可能**是交易日的盘前（当日日线尚未生成） | 强（需配合 4 消歧） |
| 4 | **实时快照的日期/时间字段** | 新浪下标 30/31（§三）、腾讯对应字段（§六）：快照日期 == `date` 且时间落在交易时段 → 交易日且盘中；快照日期 < `date` 且当前时刻已过 09:35 → `date` 大概率**非交易日** | 强 |
| 5 | **交易所休市安排公告** | 按 §二 降级链检索"上海证券交易所 {年份} 休市安排"/"深圳证券交易所 全年休市"，或直取已知公告页 | 确定（若取到） |
| 6 | **全不可用** | → **不得猜**：按"以最近一根日线的日期为分析基准日"处理，并在报告标题与「数据完整度」显式标注：`无法判定 {date} 是否交易日，分析基准日按最近可得交易日 {d_last}` | 降级（须标注） |

> 📌 3 与 4 的消歧要点：盘前（09:30 前）取数时"日线缺当日一根"是**正常现象**，此时不能据此判非交易日；须结合当前时钟与快照时间字段。若当前时刻在 09:35–15:00 之间而快照日期仍是上一日 → 判 `date` 非交易日或标的停牌（见 9.3）。
> ⚠️ 判定为非交易日时，**不是报错**：按 SKILL 的时段视角处理成"最近交易日的收盘复盘 + 下一交易日预案"，并显式标注（对接 ETA5，不得把上一交易日快照当"当日实况"）。

### 9.2 三种"取不到当日数据"的情形必须分开写

| 情形 | 特征 | 处置 |
|---|---|---|
| **周末** | `date` 为周六/周日 | 无需取数即可定案；A 股周末一律休市，**即使遇调休上班日也不补开市**，不要因"那天上班"就当交易日 |
| **法定节假日休市** | 工作日但全市场无数据：日线无当日一根、快照日期为节前最后交易日、**同市场其他标的同样取不到** | 判全市场休市 → 同非交易日处理；结论来源标"交易所休市安排"或"多标的交叉验证" |
| **标的停牌** | **市场在交易**（对照标的如 510300/159919 有当日数据），但**本标的**现价 0 / 成交量 0 / 日线缺当日一根 | 判本标的停牌 → **当日不做 T（framework §5.1 铁律 5：涨跌停日、停牌日、复牌首日不做 T）**；理由：停牌客观不可成交且破坏收盘清零，**复牌首日量能失真使放量判定失效**（calc-methods §一）→ 复牌首日同样不做，并标注 `停牌/复牌，量能口径失效` |

> 📌 **交叉验证是区分"休市"与"停牌"的唯一低成本手段**：额外取一只高流动性宽基 ETF 的快照/日线作对照标的。对照标的有数据、本标的没有 → 停牌；两者都没有 → 休市或接口故障（再按 §八「限频/失败」重试一次，仍失败按退出码 1）。

### 9.3 停牌与涨跌停的检测口径

```
停牌（交易时段内）：现价 == 0  或  成交量 == 0  或  日线缺当日一根而对照标的有
涨停封死：卖一价/卖一量为 0（无卖盘）
跌停封死：买一价/买一量为 0（无买盘）
```

三者一律 → 当日不做 T（**framework §5.1 铁律 5：涨跌停日、停牌日、复牌首日不做 T**），且不得继续输出买卖价位（会给出不可成交的价）。若为可转债，还须叠加 framework §8 的临停规则（临停期间无法平仓，直接破坏收盘清零）——**临停阈值与涨跌幅限制的数值见主文档附录 D，引用须带该行快照日期**（ETA11），不在本文件复写。临停/停牌期间五档失真 → 价差、深度、滑点三项判定标"不可用"（§三）。

## 十、账户级参数（`cost` / `position` 入参与历史 state，非接口取数）

> 📌 章节编号 **§十 不变**（原标题「账户成本参数」，其他文件按 `data-sources §十` 交叉引用照旧有效）；本节现覆盖**两类**账户级参数：**成本参数**（下表，佣金率与最低佣金 `F`）与**权益类字段**（§10.1）。两类的共同点：**任何行情接口都取不到，只能来自用户或历史 state**。

**佣金率与单笔最低佣金无法从任何行情接口取得，只能来自用户。** 但它直接决定 framework §1 的成本硬门槛是否通过（判定算法见 calc-methods §八），所以缺省时必须显式标注假设，而不是静默按"无最低佣金"算完就当结论。

| 参数 | 来源 | 缺省处置 |
|---|---|---|
| 佣金率（单边） | 用户 `cost` 入参 / 口述 | 缺省按 **万0.5 单边（往返 2C = 万1）** 假设，标注"示例假设，需用户核实" |
| **单笔最低佣金 `F`** | 用户 `cost` 入参 / 口述（券商 App 费率页） | 缺省 → **不得默认 F = 0**；按"F 未知"处理，报告须写出两档结论：`F = 0 时成本达标` 与 `F = 5 元且单轮 < 10 万元时真实往返成本升至约 万5`，并提示用户补 `cost` |
| 是否两融/是否有其他费用 | 用户提供 | 缺省标"未提供，未纳入测算" |

> ⚠️ **不要联网"查"某券商的佣金**：费率是账户级协议价，检索到的公开值对该用户不成立，属于 ETA1 意义上的编造。只接受用户提供。
> 📌 缺省不影响流程继续（向后兼容）：仍按名义万1 出策略，但「成本硬门槛是否通过」一项必须标为 `待用户确认`，不得打勾。

### 10.1 账户权益类字段（`position` 入参 / 历史 state，非接口取数）

**`prev_close_equity`（昨收账户总资产）同样无法从任何行情接口取得**——它是账户级数据，只能来自历史 state 或用户提供。但它直接决定 framework §5.2 **回撤口径 A** 的单日档能否核查，所以缺失时必须按下表走三级取数链，而不是静默跳过。

| 字段 | 来源优先级（依次尝试，取到即止） | 皆无时的处置 |
|---|---|---|
| **`prev_close_equity`**（昨收账户总资产） | ① **历史 state 文件的 `account_equity`**（上一交易日收盘写入值）→ 采用，来源标"历史 state + 其日期"<br>② **用户在 `position` 入参中提供的「昨收账户总资产」**——**券商 App「昨日资产 / 参考市值」直接可见**，用户只需填一个数字；性质与 `cost` / `news` 入参相同（一手信息、有来源，不违反 ETA1）→ 采用，来源标"用户提供"<br>③ 皆无 | 写 `null` 并标「**口径 A 单日档不可核查**」→ 进入**冷启动档**（framework §5.2：名义 T 仓上限降一档 + 仅做 A 档信号，`cold_start.active = true`）；**不得按缺失字段数累计降档** |
| **`account_equity_week_high`**（周内账户总资产峰值） | **只能由历史 state 逐日续算**（需每日收盘序列取最大值）——用户**无法一次性提供** | 缺失 → 只标「口径 A 单周档不可核查」+ **要求用户人工确认**（"本周账户总资产是否已从周内最高点回撤超过 3%？"），**不自动触发、不额外降档** |

> ⚠️ **口径警告（必须是市值口径）**：`prev_close_equity` / `account_equity` / `account_equity_week_high` 三者一律为**市值口径** = 底仓按**收盘市价**计的市值 + 现金，等同券商 App 显示的「账户总资产」。**严禁用成本口径的 `total_capital`（持仓市值按成本估算 + 现金）代替**——两者只在"成本价恰等于市价"时数值相同，实盘中必然分叉，**跨口径相减得出的跌幅无意义**。三者必须同口径才可比。
> ⚠️ **不要联网"查"用户的账户权益**：这是账户级私有数据，检索不到也**不得估算**（例如按"标的涨跌幅 × 假设仓位"倒推），属于 ETA1 意义上的编造。**只接受用户提供或历史 state 续算**。
> 📌 采用 ② 时冷启动状态**解除口径 A 单日档部分**；若 `account_equity_week_high` 仍缺失，单周档仍不可核查，但**不再额外降档**（与冷启动同属一个事件）。
> ⚠️ 标"不可核查" ≠ 标"未触发"（ETA10）：不可核查时既不触发收缩动作，也**不得宣称"单日/单周未触发、风控安全"**；把 `null` 当 0 用属违规。
