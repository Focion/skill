# 结算数据与状态文件（Settlement）

本文件定义收盘后把实际操作结算成跨日可续用数据的口径，以及结算态状态文件的写入与归档规则。

结算只由实际数据驱动：成交台账、收盘账户总资产、盘后行情。策略参数（三态、`W`、`L`、生效上限、轮次上限、`t_cap` 推导链）**必须**原样保留计划态所载值，**严禁**在结算环节改写其中任何一项——事后改风控结论等于让当日的纪律判定失去被检验的对象。

本节定义的是**结算时的续算**，与分析环节盘前取数是两回事：分析环节读的是别人昨日写下的值，本节写的是给明日读的值。

## 一、逐轮盈亏（口径 B 的输入）

每一轮**必须**写出三项，缺任一项即视为未结算：

| 项 | 口径 |
|---|---|
| 毛额 | 正向 T：`(卖出价 − 买入价) × 股数`；反向 T：`(卖出价 − 买回价) × 股数` |
| 费用 | `报告所载 2C × 股数`；报告未载 `2C` → 本项标「须用户自行核实」 |
| 净额 | `毛额 − 费用`；费用不可得时净额标「不含费用」 |

- `realized_pnl_today` **必须**取 `RV4`；`RV4` 未答时取逐轮净额求和并标「由台账推算」
- `RV4` 与逐轮求和不一致时**必须**以 `RV4` 为准，并写出两者差额，**严禁**取平均或静默采信其一
- `realized_pnl_today` 写入 state 时**必须**换算为占总资金的比例并注明所用总资金取值，**严禁**把元数直接写进该字段

## 二、`realized_pnl_week` 续算（四步，缺一不可）

| 步 | 判据 | 结果 |
|---|---|---|
| ① | 在 `{outputDir}` 内查找同一 6 位代码、日期早于本次 `date` 的最近一个 `.state.json` | 得候选文件或未命中 |
| ② | 命中，该文件 `settled == true`，且其日期与本次 `date` 属同一自然周 | `realized_pnl_week` = 该文件的 `realized_pnl_week` + 本日 `realized_pnl_today` |
| ③ | 命中，该文件 `settled == true`，日期跨周 | `realized_pnl_week` = 本日 `realized_pnl_today` |
| ④ | 未命中，或命中文件 `settled != true` 而其 `realized_pnl_week` 为 `null` | `realized_pnl_week` = **`null`**，并标注「单周口径不可核查（缺已结算历史 state）」 |

- 「自然周」的界定**必须**取报告所载表述，报告未载**必须**标「周界定缺报告记载，须用户自行核实」
- ④ 情形下**严禁把 `null` 当 0** 处理后写出「单周未触发」——标「不可核查」不等于标「未触发」
- ② 情形下命中份与本次 `date` 之间**存在未结算交易日**时，续算出的值**不完整**（漏掉中间各日的盈亏，低估亏损属危险方向）→ **必须**照常写出该值并标「不完整（中间 ____ 个交易日未结算）」，**严禁**把它当作已核实值写入结论

## 三、口径 A 权益三字段

三者一律为**市值口径**（底仓按当日收盘市价计的市值 + 现金），等同券商 App 的「账户总资产」。**严禁**用成本口径的 `total_capital` 代替其中任何一项。

| 字段 | 取数 |
|---|---|
| `account_equity` | 取 `RV3`；`RV3` 未答 → 写 `null` 并标「口径 A 不可核查」 |
| `prev_close_equity` | 计划态已载非 `null` 值 → 原样保留；计划态为 `null` 且 §二 ① 命中的已结算 state **紧邻上一交易日** → **必须**补填为该文件的 `account_equity` 并标「结算时回填」；命中份不紧邻或皆无 → 保留 `null`，**严禁**用更早那一日的权益充当昨收权益 |
| `account_equity_week_high` | 按下方四步续算 |

**`account_equity_week_high` 续算四步**：

| 步 | 判据 | 结果 |
|---|---|---|
| ① | §二 ① 命中已结算 state，且同一自然周 | `max(该文件的 account_equity_week_high, 本日 account_equity)`；命中份与本次 `date` 之间有未结算交易日时**必须**加标「不完整（中间 ____ 个交易日未结算）」 |
| ② | 命中已结算 state，跨周 | 本日 `account_equity` |
| ③ | 未命中，但 `RV9` 提供了本周此前各交易日的收盘账户总资产 | 取 `RV9` 各值与本日 `account_equity` 的最大值，来源标「用户提供」 |
| ④ | 皆无 | **`null`**，标注「口径 A 单周档不可核查」 |

> ③ 与「用户无法一次性提供周内峰值」并不冲突：用户提供的是**每日收盘权益序列**，峰值由本 skill 取最大值构造。用户只报一个自称的峰值数时**必须**回读确认其为哪一日的收盘值，**严禁**直接采用无日期的峰值口述。

## 四、标的级计数

| 字段 | 结算口径 |
|---|---|
| `rounds_used_today` | `RV1` 台账的轮数；部分成交与纠错成交各计 1 轮 |
| `consecutive_losses` | 台账**末尾**连续「净额 < 0」的轮数；末轮为盈利时写 `0` |
| `open_rounds` | 替换为实际各轮留痕（时刻、方向、成交价、股数、平仓价、净额），**严禁**保留计划态的预期留痕 |
| `halted` / `limit_lock` | 按盘后核对节所标状态确认；盘后核对标「不可判」时保留计划态值并标「未经收盘核实」 |
| `total_shares` / `cost_basis` | `RV7` 提供时更新；未提供时保留计划态值并标「未随结算更新」 |
| `cash` / `total_capital` | 保留计划态值并标「未随结算更新」，**严禁**由 `account_equity` 反推这两项 |

## 五、`rolling_stats` 与轮次流水

计划态 state 的 `rolling_stats` 只有汇总值，无法据其算出滚动窗指标。结算态**必须**新增 `rounds_ledger` 字段承载最近 100 轮流水，`rolling_stats` 由它机械算出：

```json
"rounds_ledger": [
  {"date": "2026-08-04", "direction": "forward", "pnl_net": 12.4},
  {"date": "2026-08-05", "direction": "forward", "pnl_net": -18.0}
],
"rolling_stats": {"sample_n": 2, "p_100": 0.5, "r_100": 0.689},
"settled": true,
"settled_at": "2026-08-05T15:20:00+08:00"
```

| 字段 | 口径 |
|---|---|
| `rounds_ledger` | 取 §二 ① 命中文件的 `rounds_ledger` 追加本日各轮；长度超过 100 时**必须**丢弃最早的条目直到长度为 100 |
| `sample_n` | `rounds_ledger` 的长度 |
| `p_100` | `rounds_ledger` 中 `pnl_net > 0` 的条目数 ÷ `sample_n` |
| `r_100` | 盈利条目 `pnl_net` 均值 ÷ 亏损条目 `pnl_net` 绝对值均值；亏损条目数为 `0` 时写 `null` |
| `settled` | 恒为 `true`（本 skill 写入的 state 一律为结算态） |
| `settled_at` | 本次结算的落盘时刻 |

- `sample_n < 100` 时**必须**在文档中写出实际样本数并标「样本未满 100 轮，处置以报告所载为准」，**严禁**由本 skill 据其给出仓位或停做结论
- 本日新增轮数**必须**标为「样本增量」，**严禁**用本日胜负比表述为胜率

## 六、结算态 state 的写入与计划态归档

写入顺序固定为「先归档、后覆盖」，**严禁**颠倒：

| 步 | 动作 | 幂等保护 |
|---|---|---|
| ① | 读入 `statePath` 所指计划态 state | 读不到时**必须**照常写出结算态 state（计划态字段一律写 `null`）并标「无计划态 state，结算数据仅由台账与用户答复构成」，**严禁**因缺计划态就跳过结算落盘 |
| ② | 把计划态原样写入 `{outputDir}/etf-t0-{symbol}-{date}.plan.json` | 该文件已存在 → **必须**跳过归档并保留原文件；读入的 state 已 `settled == true` → **必须**跳过归档 |
| ③ | 把结算态覆盖写入 `{outputDir}/etf-t0-{symbol}-{date}.state.json` | — |

- 归档文件**严禁**使用 `.state.json` 后缀：分析环节按该后缀查找历史 state，两份同日期文件会使「最近一个」不唯一
- 覆盖写**必须**保留 §一至 §五 未点名的全部计划态字段，**严禁**只写结算字段而丢弃 `regime`、`params`、`risk_state`、`cost`、`tick_size` 等留痕

```markdown
<!-- ✅ 正确：结算字段与保留字段分列，缺失写 null 并标注 -->
| account_equity | 48,213.50 元 | 用户 RV3 提供 2026-08-05 |
| account_equity_week_high | null | 口径 A 单周档不可核查（未命中已结算 state，RV9 未提供）|
| risk_state.t_cap.effective | 0.05 | 原样保留计划态值，未改写 |

<!-- ❌ 错误：把 null 当 0，凭空得出「单周未触发」 -->
| realized_pnl_week | 0 | 没找到上一份 state，先当 0，本周应该没超 |

<!-- ❌ 错误：结算时改写了当日生效上限，当日纪律判定失去比对基准 -->
| risk_state.t_cap.effective | 0.10 | 实际只做了一轮，上限调回 0.10 |
```
