# ETF T+0 收盘复盘与沉淀

> [!IMPORTANT] 路径解析基准
> 文档内相对路径引用一律以本 skill 根目录（`SKILL.md` 所在目录）为基准解析。

## 参数

| 参数 | 必填 | 说明 |
|------|------|------|
| `mode` | 否 | 复盘粒度：`day`（默认，单日收盘复盘）/ `week` / `month`（聚合已落盘的单日复盘，出趋势视图） |
| `reportPath` | 是 | 分析报告文件路径（`etf-t0-{6位代码}-{date}.md`）。**缺失时不得报错退出，必须先向用户提问**；`mode` 非 `day` 时本项不适用 |
| `manualPath` | 否 | 同批产出的操作手册路径；缺省时对照仅按报告委托单清单进行 |
| `statePath` | 否 | 同批产出的计划态 `.state.json` 路径；缺省时结算数据仅由台账与用户答复构成 |
| `symbol` | 否 | 6 位数字代码；缺省从报告首部继承。`mode` 非 `day` 时**必须**提供（该模式不读报告，无可继承来源） |
| `date` | 否 | 复盘基准日（`YYYY-MM-DD`）；缺省为今日。补做前几日的复盘时**必须**显式传该交易日 |
| `tradeLog` | 否 | 问询项 `RV1` 实际成交台账（手册第七节记账卡原文或等效文本）；未提供时按 STEP 4 问询，**严禁自填** |
| `closeEquity` | 否 | 问询项 `RV3` 收盘账户总资产（元）；未提供时按 STEP 4 问询，**严禁自填** |
| `closeQuote` | 否 | 问询项 `RV8` 当日收盘的开/高/低/收/量/额六个原值；未提供时按 STEP 3 第 ② 级取数 |
| `outlookStage` | 否 | 次日前瞻档位：`auto`（默认，按 [next-day-outlook.md](references/next-day-outlook.md) §二 机械判定）/ `close`（收盘档）/ `preopen`（盘前档）；指定 `preopen` 也**严禁**为无读数的观察项填值 |
| `lessonsPath` | 否 | 长期沉淀文件路径，缺省为 `{outputDir}/etf-t0-lessons-{symbol}.md` |
| `outputDir` | 否 | 产物输出目录，默认当前工作目录 |

## 公共约束

> [强约束] 总纲：只登记已发生的事实，计划值只继承不重算，实际值只问不猜，每条差异与每条判定都写出读数，次日只给条件式观察与情景、一个具体参数都不写。

| # | 约束 | 违反后处理 |
|---|------|-----------|
| ETS1 | 每条实际成交记录与盘后行情读数必须标注来源与时间，**严禁编造**任何成交价、股数或收盘读数 | 删除无源数据，改标注为「数据缺失」后重出 |
| ETS2 | 计划值必须逐项继承报告与手册所载值，**严禁自行重算或改写** | 改回来源文件原值后重出 |
| ETS3 | 实际操作数据必须取自用户答复，**严禁**以计划值、估算值或上一日旧值代替未答项 | 停止生成，回到问询步骤 |
| ETS4 | 每条差异必须归入单一 `DV` 类别并写出该类必备证据，**严禁**只写结论不给读数 | 补齐类别与证据后重出 |
| ETS5 | 复盘文档必须只登记已发生的事实，次日内容**只允许**以「观察项 + 阈值 + 情景 + 定性操作倾向」形态出现，**严禁**给出次日的三态、`W`、`L`、买卖价位、委托单清单、轮次数字或金额 | 删除越界内容并改标「次日参数须由 `etf-t0-analysis` 重跑产出」后重出 |
| ETS6 | 纪律核查必须逐项写出「是 / 否 / 不适用」与证据，**严禁**留空或写成无读数的观察性描述 | 补出判定与证据后重出 |
| ETS7 | 样本类数字必须写出样本数并把新增部分标为样本增量，**严禁**用单日或周月窗口的胜负比表述为胜率 | 补标样本数与「样本增量」后重出 |
| ETS8 | 结算字段取不到时必须写 `null` 并标注「不可核查」，**严禁把 `null` 当 0 处理**后宣称未触发 | 改回 `null` + 显式标注后重出 |
| ETS9 | 盘后行情不可得时必须把受影响的核对项标「不可判」，**严禁**用手册计划价位冒充实际成交或收盘读数 | 改标「不可判」后重出 |
| ETS10 | 沉淀条目必须绑定本日台账或盘后读数中的具体数值，**严禁**输出无判据的泛化经验 | 删除无证据条目后重出 |
| ETS11 | 交易所规则派生的时点与申报单位必须取报告所载值并原样带其快照标注，**严禁**填入报告未载的规则数值 | 改回报告值或标注「须用户自行核实」后重出 |
| ETS12 | 复盘必须在复盘日收盘后执行，**严禁**在复盘日行情记录尚未取到时产出结算数据 | 停止生成，提示收盘后重跑或改传交易日 |
| ETS13 | 未按纪律执行的动作必须原样登记，**严禁**因该轮结果为盈利而漏记 | 补记该动作后重出 |
| ETS14 | 次日前瞻每个观察项必须写出读数 + 时间 + 来源，或标「未开盘·不可读」/「不可读」；**严禁**用昨夜读数冒充今夜，**严禁**为无读数的项判定情景落点 | 改标「不可读」并把落点改「未落点」后重出 |
| ETS15 | 盘面与信号复盘必须写出对标基准与各信号的实际读数并逐项判「验证 / 失效 / 不可判 / 不适用」，**严禁**只写标的自身涨跌或只写结论不给读数 | 补出读数与逐项判定后重出 |

## 核心流程

> [强约束] STEP 3~10 仅在 `mode=day` 时执行。`mode` 为 `week` / `month` 时**必须**改按 [period-review.md](references/period-review.md) 执行聚合流程、套用其 §四 模板写入周/月度复盘文档、回显其绝对路径与状态行，**严禁**在聚合模式下重跑单日问询、单日结算、次日前瞻或改动长期沉淀文件；该文件写入失败 → stderr + exitCode=1。

### STEP 1：参数校验

按标准校验顺序校验：
- **必填 + 格式**：`reportPath`（**缺失时不得报错退出，必须先向用户提问**；`mode` 非 `day` 时改校验 `symbol`）｜`symbol` 匹配 `^[0-9]{6}$`、`date` 为 `YYYY-MM-DD`、`closeEquity` 可解析为非负数值
- **枚举 + 文件**：`mode`（`day` / `week` / `month`，缺省 `day`）、`outlookStage`（`auto` / `close` / `preopen`，缺省 `auto`）｜`reportPath`、`manualPath`、`statePath` 均仅在提供时校验存在
- **透传 + 创建**：`tradeLog`、`closeQuote` 原样透传；`outputDir` 创建

任一校验失败 → stderr + exitCode=2

### STEP 2：读取规范原文与来源文件

用 `Read` 逐份读取下列十份规范原文，**严禁**凭记忆或凭摘要执行；同时读入 `{reportPath}`、`{manualPath}`、`{statePath}`、`{lessonsPath}`（提供或已存在时）：

- [intake.md](references/intake.md) 问询清单、逐字问法、答复校验与未答处置 ｜ [market-recheck.md](references/market-recheck.md) 收盘时机守卫、两级取数降级链、六项盘面核对
- [board-signal-review.md](references/board-signal-review.md) 三层对标基准、`BM1`–`BM4` 强弱与量能登记、`SG1`–`SG6` 信号有效性判据 ｜ [next-day-outlook.md](references/next-day-outlook.md) 三类 key 语义、双档判定、板块路由表、三情景与落点
- [reconcile.md](references/reconcile.md) 对照条目构造与 `DV1`–`DV7` 归因决策树 ｜ [discipline-audit.md](references/discipline-audit.md) `DA1`–`DA14` 核查项判据与计数行
- [settlement.md](references/settlement.md) 结算口径、`rounds_ledger` 与状态文件写入归档规则 ｜ [lessons.md](references/lessons.md) 沉淀条目必备项、去重与退场判据、长期文件三段结构与同步步骤
- [review-template.md](references/review-template.md) 复盘文档模板（九节 + `§二之二` / `§八之二`）｜ [period-review.md](references/period-review.md) `mode` 非 `day` 时的窗口界定、`PA1`–`PA9` 聚合项、`PT1`–`PT3` 趋势判定与输出模板

`mode=day` 时：用户答「没有分析报告」或所给路径无报告、报告缺 `W`/`L`/生效上限/委托单清单任一项、报告或手册基准日与复盘日不是同一交易日 → stderr + exitCode=3。`mode` 非 `day` 时：上述报告类校验一律**不适用**，窗口内一份单日复盘文档都读不到 → stderr + exitCode=3

**完成标准**：十份规范原文与全部来源文件均已读取；报告结论、`symbol`、`date` 已确定。

### STEP 3：收盘核对、盘后取数与盘面信号复盘

按 [market-recheck.md](references/market-recheck.md) §一 判已收盘、§二 走两级取数降级链（第 ② 级经 `Bash` 调公开接口）、§三 逐项填六个核对项、§四 标注缺失与失真；再按 [board-signal-review.md](references/board-signal-review.md) §一 定三层对标基准、§二 走三级取数降级链、§三 填 `BM1`–`BM4`、§四 逐项判 `SG1`–`SG6` 并填计数行与分母（ETS15）。复盘日未收盘、复盘日无行情记录（ETS12），或标的行情两级取数皆不可得致六项全标「不可判」 → stderr + exitCode=3；标的行情接口取数失败并重试一次仍失败 → stderr + exitCode=1；**对标基准与外盘取数失败一律按「不可读」处置，严禁因此中止复盘**——台账、差异归因、纪律核查与结算均不依赖它们。

**完成标准**：已收盘判据行号已写出；六个原值与 `M1`–`M6`、`BM1`–`BM4`、`SG1`–`SG6` 均有读数或缺失标注；信号计数行与分母已填。

### STEP 4：实际操作采集

按 [intake.md](references/intake.md) §一 先解析用户已粘贴的手册第七节记账卡，再**一次性列出**剩余待问项等用户答复；逐项过 §五 答复校验与 §四 口径二次确认。用户明示不需要复盘 → 不生成任何文件，打印状态行，exitCode=0；`RV1`/`RV2`/`RV5` 任一为 `未答` → 只出待补信息清单 → stderr + exitCode=3；`RV3`/`RV4` 为 `未答` → 按 §三「未答处置」列降级出复盘并在首部写出降级的节；`RV10` 缺「对应交易日」→ 按 §七 记该项 `未提供` 并走接口取数。

**完成标准**：阻塞必答三项均为「已校验的显式值」；全部答复已带「用户提供 + 时间」标注。

### STEP 5：继承参数抽取

从报告与手册逐项抄出 [review-template.md](references/review-template.md) 第一节表格的每一行（含来源位置），**严禁**改写数值或补算来源文件未载项。报告结论属「不适合做 T / 不适用本体系 / 当日不做 T / 停手」→ 对照节按 [reconcile.md](references/reconcile.md) §四 的对应行处置，结算与沉淀照常执行；报告已对规则派生值标注「快照可能过期，须复核」→ 原样抄入复盘文档（ETS11）。

**完成标准**：继承快照表无空行、无自算值；本日可用轮次与口径 B 当日档绝对额已确定。

### STEP 6：结算数据与状态文件落盘

按 [settlement.md](references/settlement.md) §一 算逐轮三项、§二 续算 `realized_pnl_week`、§三 结算口径 A 三字段、§四 结算标的级计数、§五 更新 `rounds_ledger` 与 `rolling_stats`、§六 先归档计划态再用 `Write` 覆盖写结算态。读不到 `statePath` → 按 §六 ① 照常写结算态并把计划态字段写 `null`，**严禁**跳过结算落盘；归档或覆盖写失败 → stderr + exitCode=1

**完成标准**：结算字段均有值或 `null` + 「不可核查」标注（`prev_close_equity` 已定值，`DA14` 得以在下一步判定）；归档与覆盖写结果已回填绝对路径。

### STEP 7：差异归因与纪律核查

按 [reconcile.md](references/reconcile.md) §一 构造对照条目、§二 决策树逐条归类并写出步号、§三 填齐该类必备证据，未产生成交的清单外动作按 §一 只登记指针；再按 [discipline-audit.md](references/discipline-audit.md) §一 四条通则、§二 逐项判定 `DA1`–`DA14`、§三 填计数行，并按 §四 把判为「否」的项转入 STEP 8。

**完成标准**：每个对照条目恰好归入一个类别且带步号；`DA1`–`DA14` 均有判定与证据，计数行已填。

### STEP 8：沉淀提炼与长期文件同步

按 [lessons.md](references/lessons.md) §二 扫全部候选来源（含 STEP 3 判为「失效」的 `SG` 编号）、§一 过五个必备项、§三 去重与退场回迁判据、§五 六步同步长期文件；长期文件写入失败 → stderr + exitCode=1

**完成标准**：新增、复现、移入高频、移入已改掉、回迁五个条目数与丢弃原因均已写出。

### STEP 9：次日前瞻

按 [next-day-outlook.md](references/next-day-outlook.md) §一 作用域上限、§二 判档位（第 0 行**先判**：追溯复盘时整节标「不适用（追溯复盘，次日已走完）」并止步；`outlookStage` 非 `auto` 时以入参为准，但**严禁**为此凭空填读数、**严禁**由它推翻第 0 行）、§三 用 STEP 3 已定的跟踪指数名称路由到板块与主指标、§四 走三级取数降级链、§五 写全三情景、§六 判落点。观察项取不到一律标「不可读」并把落点标「未落点」，**严禁**升级为退出码、**严禁**改用次指标顶替主指标、**严禁**搬用 `BM4` 的昨夜读数（ETS14）。

**完成标准**：档位与其命中判据行已写出；三情景全部写出，操作倾向均取自 §五 的封闭词表；落点已判出、已标「未落点」及其原因，或整节已标「不适用（追溯复盘）」。

### STEP 10：复盘文档写入与自查

套用 [review-template.md](references/review-template.md) 的速览卡、九节与 `§二之二` / `§八之二` 生成复盘文档，写入 `{outputDir}/etf-t0-review-{symbol}-{date}.md`，逐条勾选第九节自查表（覆盖 `ETS1`–`ETS15`）。向 stdout 打印一句话复盘摘要、全部产物绝对路径与状态行；复盘文档写入失败 → stderr + exitCode=1

**完成标准**：速览卡、九节与两个插入节齐全、自查表全部勾选、全部产物绝对路径已回显。

## 输出规范

### 产物文件

| 文件 | 条件 | 路径 |
|------|------|------|
| 复盘文档 | 阻塞必答项齐备时必产 | `{outputDir}/etf-t0-review-{symbol}-{date}.md` |
| 结算态状态文件 | 阻塞必答项齐备时必产 | `{outputDir}/etf-t0-{symbol}-{date}.state.json` |
| 计划态归档 | 首次覆盖结算态时 | `{outputDir}/etf-t0-{symbol}-{date}.plan.json` |

| 待补信息清单 | `RV1`/`RV2`/`RV5` 任一未答时 | `{outputDir}/etf-t0-review-{symbol}-{date}.todo.md` |
| 周 / 月度复盘文档 | `mode` 为 `week` / `month` 时必产 | `{outputDir}/etf-t0-review-{symbol}-{date}-{mode}.md` |

> [强约束] 文件名片段生成规则：`{symbol}` 字符白名单为 `^[0-9]{6}$`（长度恒为 6 个字符，纯数字无大小写），为空时回退为报告首部所载 6 位代码；`{date}` 白名单为 `^\d{4}-\d{2}-\d{2}$`，为空时回退为报告首部所载分析基准日；`{mode}` 白名单为 `week` / `month` 两个字面串之一（`day` 不参与拼名），且周/月度产物的 `{date}` **必须**取窗口**起始交易日**而非入参原值，否则同一窗口在窗口内每跑一次就多堆一份文件。**严禁**把用户传入的中文名或带市场前缀的写法拼入文件名；两处回退值均取不到即按输入异常处置。计划态归档**严禁**使用 `.state.json` 后缀，否则分析环节按该后缀查找历史 state 时「最近一个」不唯一。盘前档补跑时**必须**就地改写同一份复盘文档的 `§八之二`，**严禁**新建第二份复盘文档或改动文件名。落盘后必须回显全部产物绝对路径。

### 退出码

> 本 skill 由 Claude 在对话中直接执行、无外部进程返回退出码，每次结束时必须在输出末尾单独打印一行 `状态：{含义}（exitCode={N}）`。

| exitCode | 含义 | 触发场景 | 后续动作 |
|---------|------|---------|-----------|
| 0 | 完成 | 复盘文档与结算态状态文件写入成功（含次日前瞻节按「未落点」出）；或周/月度复盘文档写入成功；或用户明示不需要复盘 | 读取复盘 → 次日盘前补跑或重跑分析 |
| 1 | 执行失败（可重试） | 标的行情接口重试后仍失败；复盘文档、结算态状态文件、计划态归档、长期沉淀文件、待补信息清单或周/月度复盘文档写入失败 | 询问用户：重试 / 终止 |
| 2 | 输入异常（不可重试） | `reportPath`、`manualPath` 或 `statePath` 指向的文件不存在；`symbol`、`date`、`closeEquity` 格式非法，或 `mode`、`outlookStage` 取值不属枚举；`mode` 非 `day` 而 `symbol` 缺失；`{symbol}`、`{date}` 两处回退值均取不到 | 提示用户修正参数 |
| 3 | 需人工决策 | 复盘日尚未收盘；复盘日无行情记录（休市或停牌，须改传交易日）；用户无分析报告；报告缺 `W`、`L`、生效上限、委托单清单任一项；报告或手册基准日与复盘日非同一交易日；标的行情用户提供与接口两级取数皆不可得；`RV1`/`RV2`/`RV5` 未答；`mode` 非 `day` 而窗口内一份单日复盘文档都读不到 | 提示收盘后重跑或补答问询项 |

### stderr 格式（JSONL，单行）

```jsonl
{"message":"...","detail":"...","hint":"..."}
```

字段约束：`message` 必填（自由文本、简洁单行）；`detail` 可选（多行文本，保留原始错误信息）；`hint` 可选（给用户的修复提示）。

## 危险信号（Red Flags）

以下可观测信号表明执行出现偏差，出现任一项必须回退修正：

- RF-ETS1: 台账或盘面核对节出现无来源、无时间标注的成交价、股数或收盘读数
- RF-ETS2: 继承快照表中出现报告与手册均未载的数值，或同一参数在复盘文档与来源文件中不一致
- RF-ETS3: 实际值取自手册计划价位，或用「按经验」「大概」形态的来源填入了未答项
- RF-ETS4: 差异条目缺归类步号、缺该类必备证据，或同一对照条目被计入两个 `DV` 类别
- RF-ETS5: 复盘文档出现次日的三态判定、`W`/`L`、支撑阻力位、委托单清单、具体轮次数或金额，或次日前瞻节的操作倾向不属五个封闭词表值
- RF-ETS6: 核查表存在空白的「判定」或「证据」格，或判据缺载时写「否」而非「不适用」
- RF-ETS7: 出现「今日胜率 67%」「本周胜率 67%」这类由十几轮以下样本算出的胜率，或据单日/周月样本给出仓位结论
- RF-ETS8: `realized_pnl_week` 或 `account_equity_week_high` 在未命中已结算 state 时被填成 0，或结算节写出「单周未触发」却无已结算历史 state 支撑
- RF-ETS9: 盘后行情不可得时核对项仍填了具体读数，或用手册止盈价充当当日收盘价
- RF-ETS10: 沉淀条目的证据格不含任何数字与时刻，或出现「要有耐心」「控制情绪」形态的结论
- RF-ETS11: 复盘文档写出报告未载的集合竞价时点、申报单位或税费数值，或抄漏报告的快照标注
- RF-ETS12: 已收盘判定未写出判据行号，或所取行情记录的日期不等于复盘日却照常写出了结算字段（含追溯复盘时误用快照返回的最新交易日读数）
- RF-ETS13: `RV5` 报出的违纪动作未出现在核查表证据中，或盈利轮的超限动作被判为「是」
- RF-ETS14: 次日前瞻的观察项有读数而无「对应交易日 / 取数时刻」；主指标标「不可读」或处于收盘档却仍判出了 A/B/C 落点；同一指标在 `BM4` 与前瞻节的「对应交易日」相同
- RF-ETS15: `§二之二` 只写「弱于大盘」而无两个涨跌幅与差值；`SG1`–`SG6` 存在无判定或无判据读数的行；信号计数行缺分母；`BM3` 出现与 `M6` 不一致的倍数

## 反合理化（Anti-Rationalization）

| 借口 | 反驳 |
|------|------|
| "用户不记得成交价了，按手册的委托价填上，差不多" | 委托价是计划、成交价是事实。用计划值回填等于让复盘自证正确，差异归因全部归零，这份复盘唯一的作用就剩让人放心。 |
| "这轮虽然超了轮次上限，但是赚的，就不记了" | 核查只看动作。赚钱的违规是最危险的一类——它给违规发了正反馈，下次会加倍做。 |
| "今天 3 轮 2 胜，胜率 67%，可以加仓了" | 3 轮的胜率标准误接近 30%，那是噪声不是胜率。本日只是样本增量，仓位调整一律以报告所载滚动窗口口径为准。 |
| "顺手把明天的价位和轮次也写进前瞻，用户省一步" | 明天的三态、区间与 `W` 都要用明天的数据重算。前瞻节的作用是告诉用户"盯哪个指标、过哪条线算哪种情形"，一旦填进具体价位，它就从观察清单变成了一份过期计划，而它会被当成计划照做。 |
| "SOX 昨夜跌了 2%，就当今夜也这样，先把落点写成偏空" | 昨夜那根已经作用在今日盘面上（`BM4`），搬去当今夜读数等于用已生效的旧信息假装预测。外盘没收就只写阈值与三情景、落点留空——留空是可补的，写错的落点会被当成已判定结论照做。 |
| "台账这笔和第 1 行价格很接近，就算第 1 行执行了" | 价格接近不等于同一笔意图。按价格自行配对会把清单外动作洗成计划内执行，`DV4` 永远为 0。 |
| "本周 9 轮 6 胜，下周可以把上限提回去" | 周月样本 15–25 轮，标准误足以让排序完全反转。周月指标只是执行质量观察值，仓位一律以报告所载滚动窗口口径为准。 |
