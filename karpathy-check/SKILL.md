# Karpathy 准则检查

> [!IMPORTANT] 路径解析基准
> 文档内相对路径引用一律以本 skill 根目录（`SKILL.md` 所在目录）为基准解析。

按 `mode` 选定检查范围，逐条对照准则原文判定并输出表格式报告。判定条款来源为本目录下的 [guidelines.md](references/guidelines.md)（Agent 行为准则，约束 Agent 做事）与 [instruction.md](references/instruction.md)（指令书写准则，约束给 Agent 下指令），检查项清单为 [checklist.md](references/checklist.md)。

## 参数

| 参数 | 必填 | 说明 |
|------|------|------|
| `filePath` | 是 | 待检查的代码或指令/Prompt 文件路径 |
| `mode` | 否 | `agent` / `instruction` / `both`，缺省取 `both`；显式指定时按该值执行，**不得**再按文件类型推断 |
| `diffRef` | 否 | git 基线引用（如 `HEAD~1`、分支名）。提供时精准改动 / 孤儿代码类检查项按 diff 判定，缺省时该类标 `➖` |
| `sessionLog` | 否 | 会话/交互记录文件路径。提供时会话过程行为类检查项按记录判定，缺省时该类标 `➖` |

## 公共约束

| # | 约束 | 违反后处理 |
|---|------|-----------|
| KC1 | 每条判定必须先定位 checklist.md 中该项 `依据` 指向的准则章节原文条款，**严禁凭检查项名称或印象判断** | 读取准则原文后重新判定 |
| KC2 | 违规描述必须给出被检查文件的行号与原文摘录，**严禁笼统概括** | 补充行号与摘录后重新输出 |
| KC3 | 每条违规必须给出可直接落地的具体改法，**严禁仅写"需要修改""再优化一下"这类空话** | 补充具体改法后重新输出 |
| KC4 | 检查项无对应内容、或所需上下文（`diffRef` / `sessionLog`）未提供时必须标 `➖`，**严禁凭单文件快照推断会话过程行为** | 修正结果标记 |
| KC5 | `mode` 未覆盖的检查章节必须整节按不适用输出，**严禁跳过不输出** | 补充不适用章节后重新输出 |
| KC6 | `mode` 范围内每个检查项必须各占一行按编号升序输出，**严禁省略或合并** | 补齐缺失行后重新输出 |
| KC7 | 同一处问题必须只计入一个最贴合的检查项，**严禁重复计入多项** | 改判多余项并重新统计 |
| KC8 | 严重度必须取检查项的固定归档档位，**严禁按个案主观调整** | 按 checklist.md 的 `严重度` 列归档值更正 |

## 检查规则

检查项清单见 [checklist.md](references/checklist.md)，共两类：Agent 行为准则检查 `K1`–`K13` 13 项（对应 `mode=agent`，依据 [guidelines.md](references/guidelines.md)，作用对象为代码文件与 Agent 产出物）、指令书写准则检查 `I1`–`I5` 5 项（对应 `mode=instruction`，依据 [instruction.md](references/instruction.md)，作用对象为 Skill 定义文件、Prompt 文件与给 Agent 的指令文档）；`mode=both` 时两类全量判定。各项的依据锚点、严重度归档值与上下文依赖均以 checklist.md 为准。

## 严重度判据

严重度由 checklist.md 的 `严重度` 列固定归档，**严禁**按主观感受逐次调整；同一检查项在不同文件中的严重度必须一致。

| 档位 | 客观判据 |
|------|---------|
| 高 | 违规使 Agent 无法自主收敛（无任何机器可读验证信号），或使产出不可信（编造 API、在已知错误上继续修补） |
| 中 | 违规导致返工或维护成本上升，但不阻断执行（过度设计、无关改动、孤儿代码、跳过朴素版） |
| 低 | 违规仅影响整洁度或可读性，不改变程序行为（TODO 残留、调试日志、注释被删） |

## 核心流程

### STEP 1：参数校验

按标准校验顺序校验：
- **必填**：`filePath`
- **枚举**：`mode`（`agent` / `instruction` / `both`，缺省取 `both`）
- **文件**：`filePath`
- **条件**：若 `sessionLog` 非空，校验该文件存在

任一校验失败 → stderr + exitCode=2

### STEP 2：读取准则原文与被检查内容

- **检查项清单**：读取 [checklist.md](references/checklist.md) 全文，作为本次检查项编号、名称、依据锚点与严重度的唯一来源；文件不存在 → stderr + exitCode=2
- **准则原文**：`mode=agent` 读 [guidelines.md](references/guidelines.md) 全文，`mode=instruction` 读 [instruction.md](references/instruction.md) 全文，`mode=both` 两份均读全文；对应文件不存在 → stderr + exitCode=2。**严禁跳过**——未读取对应准则文档即开始判定 = 违反 KC1
- **被检查文件**：读取 `filePath` 全文并记录总行数
- **改动基线**：`diffRef` 非空时执行 `git diff {diffRef} -- {filePath}` 取改动行集合；无法解析为 git 引用 → stderr + exitCode=2
- **会话记录**：`sessionLog` 非空时读取其全文
- **检查范围**：按 `mode` 确定 checklist.md 中纳入本次判定的检查项类别

### STEP 3：逐条检查

对 checklist.md 中范围内的每个检查项，先定位其 `依据` 章节的原文条款，再对照被检查内容判定，逐项记录结果、严重度、位置（行号 + 原文摘录）、违规描述、修复建议。所需上下文缺省的检查项按 KC4 标 `➖`，**严禁**据单文件快照推断；同一处问题只归入最贴合的一个检查项（KC7），否则"违规 N 项"这个数字失去意义。

### STEP 4：输出报告

按输出规范生成报告，范围外的章节整节按不适用输出，并按下列判据给出退出码：

- 范围内存在违规项 → exitCode=1
- 范围内至少 1 项通过且无违规项 → exitCode=0
- 范围内全部检查项均为不适用 → stderr + exitCode=3

## 危险信号（Red Flags）

以下可观测信号表明执行出现偏差，出现任一项必须回退修正：

- RF-KC1a: 未读取 checklist.md 与 `mode` 对应准则文档全文即开始输出判定
- RF-KC1b: 判定理由复述的是 checklist.md 的检查项名称或可观测信号，而非 `依据` 章节的准则原文条款
- RF-KC2: 违规描述中不含行号或不含被检查文件的原文摘录
- RF-KC3: 修复建议为"建议优化""需要调整"这类无具体改法的表述
- RF-KC4: 未提供 `diffRef` / `sessionLog`，却把 diff 类或会话过程行为类检查项判为通过或违规
- RF-KC6: 报告中某检查项整行缺失，或多个检查项被合并为一行
- RF-KC7: 同一处代码或同一句指令被同时计入两个以上检查项

## 反合理化（Anti-Rationalization）

| 借口 | 反驳 |
|------|------|
| "checklist.md 的检查项名已经写得很清楚，不必再读准则原文" | 清单只给项名与锚点，判定条款在准则原文。凭清单判定即违反 KC1，结论不成立。 |
| "这个文件明显没问题，逐条走太浪费" | "明显没问题"不是判定结论。逐条产出行是统计口径的前提，缺行等于数字造假。 |
| "看不出具体行号，先给个总体结论" | 无行号无摘录的违规既不可验证也不可修复，等于没检出。 |
| "这项没法判定，写通过报告更好看" | 不可判定就是 `➖`。把不可判定写成通过是给用户假信号，比漏检更危险。 |
| "改法只说方向，具体让用户自己定" | 用户来找你就是因为定不了。给不出可落地改法说明你还没定位到问题。 |

## 输出规范

### 产物文件

| 文件 | 条件 | 路径 |
|------|------|------|
| 检查报告 | 必产 | 直接输出到 stdout |

### 退出码

| exitCode | 含义 | 触发场景 | 后续动作 |
|---------|------|---------|-----------|
| 0 | 检查完成，无违规 | 范围内至少 1 项判定为通过，且无违规项 | 读取报告 |
| 1 | 检查完成，存在违规（非可重试错误） | 范围内至少 1 项判定为违规 | 读取报告 → 决定是否修复 |
| 2 | 输入异常（不可重试） | `filePath` 缺失、`filePath` 文件不存在、`sessionLog` 文件不存在、`mode` 值非法、`diffRef` 无法解析为 git 引用、`references/checklist.md` 缺失、`mode` 对应的准则文档缺失 | 提示用户修正参数 |
| 3 | 需人工决策 | 范围内全部检查项均为不适用，检查范围与文件类型不匹配 | 提示用户改用其他 `mode` 重跑 |

### stderr 格式（JSONL，单行）

```jsonl
{"message":"...","detail":"...","hint":"..."}
```

字段约束：
- `message` 必填，自由文本，简洁单行
- `detail` 可选，多行文本（保留原始错误信息）
- `hint` 可选，给用户的修复提示

### 报告格式

```markdown
## 检查报告：{filePath}

### 一、Agent 行为准则检查

| # | 检查项 | 结果 | 严重度 | 位置 | 违规描述 | 修复建议 |
|---|--------|------|--------|------|---------|---------|
| K1 | 暴露假设与权衡 | ➖ | — | — | 未提供 sessionLog，无法判定 | — |
| K2 | 简洁优先 | ❌ | 中 | L42: `class ConfigFactory:`（共 3 处） | 用户只要求读取一个配置文件，此处引入工厂类 | 删除工厂类，直接返回解析后的 dict |

### 二、指令书写准则检查

| # | 检查项 | 结果 | 严重度 | 位置 | 违规描述 | 修复建议 |
|---|--------|------|--------|------|---------|---------|
| I1 | 声明式优于命令式 | ✅ | — | — | — | — |

### 统计

- 通过：X 项
- 违规：Y 项（高 A / 中 B / 低 C）
- 不适用：Z 项
```

格式约束：

- `结果` 列取 `✅`（通过）/ `❌`（违规）/ `➖`（不适用）之一，**严禁输出 `✅ / ❌ / ➖` 这类候选列举**
- `位置` 列格式为 `L{行号}: {原文摘录 ≤30 字}`；结果为 `✅` 或 `➖` 时，`严重度` 与 `位置` 两列均填 `—`
- `mode` 范围内每个检查项必产一行，按编号升序，不得省略或合并；范围外的检查章节整节输出一行 `本节不适用（mode={mode} 未覆盖）`
- 同一检查项存在多处违规时，`位置` 列只列最严重的前 3 处并追加 `（共 N 处）`
- 无任何违规时仍输出完整表格，并在统计后追加结论行 `结论：mode={mode} 范围内无违规`
