# 论证解剖与靶心还原

本文件为 `critical-thinking` 技能提供操作细节：把用户的零散表述还原为可攻击的靶心命题、澄清歧义、挖出隐含假设、点出被省略的信息。方法源自《学会提问》的批判性提问清单与《金字塔原理》的结构化重构。

---

## 一、论证还原五问

对用户给出的每一段表述，按顺序问出下列五项，缺哪一项就向用户补问哪一项：

| # | 问项 | 找什么 | 找不到时的处理 |
|---|------|--------|--------------|
| 1 | 论题是什么 | 这段话在回答哪个问题；属**描述性论题**（世界是什么样）还是**规定性论题**（应该怎么做） | 向用户补问「你这段话是在回答哪个问题」 |
| 2 | 结论是什么 | 要人接受的那个判断本身，不是论据、不是背景、不是现象罗列 | 用户只给了一堆现象 → 请其把主张压成一句话 |
| 3 | 理由是什么 | 支撑结论的陈述，逐条编号 `R1`、`R2`… | 只有结论没有理由 → 标为【裸结论】，列为首个靶点 |
| 4 | 隐含假设是什么 | 从理由跳到结论之间被省略的那一步 | 按第四节挖出 |
| 5 | 怎样才算错 | 什么事实一旦出现，就说明这个结论不成立 | 答不出 → 该命题不可证伪，按第二节改写 |

**两类论题的攻击路径不同**：描述性论题攻证据与因果；规定性论题除证据外还必须攻价值观假设（见 4.2）。

## 二、靶心命题格式

对抗必须有唯一靶心。把结论改写成下列可证伪句式之一，得到「靶心命题」，交用户确认后才开打：

- `在 {条件/范围} 下，{主体} 会 {可观测结果}，判据是 {指标 + 阈值 + 时间窗}`
- `{方案 A} 在 {指标} 上优于 {方案 B}，判据是 {比较方式}`
- `{结果} 的主要原因是 {原因}，判据是 {移除该原因后结果发生可观测变化}`

改写规则：

- 出现「很多」「大幅」「趋势向好」等无阈值词 → 请用户给出数值或可观测判据后再入靶
- 用户拒绝给判据 → 标为【不可证伪】，本轮改为攻击「这个说法为什么无法被任何事实推翻」，而不是攻它的真假
- 表述含 2 个及以上互不隶属的结论 → 请用户指定本次靶心，其余写入「未检验清单」

```markdown
<!-- ✅ 正确：条件、主体、可观测结果、判据四项齐全，能被具体事实推翻 -->
在 {单价不变} 的前提下，{渠道 A} 的获客成本会在 {6 个月} 内降到 {80 元} 以下，判据是 {月度获客成本报表}

<!-- ❌ 错误：无阈值、无时间窗、无判据，任何后续结果都能被说成「符合预期」 -->
渠道 A 的获客成本会大幅下降
```

## 三、歧义词澄清

关键词在结论与理由中含义不一致，是最省力的攻击点，也是双方最容易一起忽略的点。

操作：

1. 从靶心命题与各条理由中框出承载判断的关键词：抽象名词、评价性形容词、专业术语、比较级
2. 对每个关键词写出至少两种能成立的释义
3. 换用另一种释义重读该论证 —— 结论翻转或某条理由失效 → 记为【歧义漏洞】，要求用户先定义再继续

释义分歧无法消除时，把靶心命题拆成两条（各对应一种释义），分别检验。

## 四、隐含假设

### 4.1 描述性假设

关于「世界实际如何运转」的未言明信念。定位方法：把某条理由与结论并排，问「要让这条理由推得出这个结论，中间必须先成立什么」。

常见形态：

- **因果链假设**：A 与 B 同时出现 → 默认 A 导致 B
- **同质假设**：默认样本内的个体、不同时间段、不同市场之间可以类比
- **稳定假设**：默认过去成立的规律在未来的条件下继续成立
- **完备假设**：默认已列出的选项就是全部选项
- **度量假设**：默认所用指标能代表真正关心的目标
- **可控假设**：默认结果由自己的动作决定，忽略对手与环境的反应

### 4.2 价值观假设

在两个都好的价值之间，作者默认了哪个优先。用价值冲突对来定位：

`效率 / 公平`、`短期收益 / 长期存续`、`集体 / 个体`、`确定性 / 上限`、`速度 / 质量`、`自由 / 安全`、`创新 / 稳定`

写法固定为：`本结论默认在 {价值 A} 与 {价值 B} 冲突时优先 {价值 A}`。把这一句摆到用户面前 —— 用户不认同自己的这条排序时，结论当场失效。

### 4.3 承重假设标记

对每条假设问一次：「这条为假时，靶心命题还成立吗」。答「不成立」的即为**承重假设**，标 `★`，作为对抗的优先靶点。

## 五、省略信息清单

用户的表述里默认不会出现的东西，逐条对照追问：

| 类别 | 追问 |
|------|------|
| 反面证据 | 与你结论相反的案例有哪些，你找过吗 |
| 证据来源 | 这个数字出自哪里，谁做的，样本怎么选出来的 |
| 度量口径 | 指标怎么定义的，换个口径结论还一样吗 |
| 反事实 | 不做这件事会发生什么，拿什么当对照组 |
| 替代方案 | 除了这条路，还有哪些路能到同一个目标 |
| 二阶后果 | 这么做之后别人会怎么反应，反应之后又会怎样 |
| 利益相关 | 提出这个说法的人，说对了能拿到什么 |
| 失败样本 | 用同样方法失败的案例在哪，你看到的是不是只有活下来的 |
| 时间尺度 | 换成三年、十年的尺度看，结论还一样吗 |
| 定义边界 | 这个结论适用的范围到哪为止，出了范围会怎样 |

## 六、金字塔重构

对抗前把用户表述整理成金字塔，结构缺陷本身就是攻击点（结构面的出击方式见 [debate-protocol.md 第一节](references/debate-protocol.md#一攻击面矩阵)）：

- **纵向**：上层是下层的概括，下层是对上层「为什么 / 怎么做」的回答。上下层只是换词复述 = 结论未完成概括
- **横向**：同组理由属同一逻辑范畴，穷尽且互不重叠（MECE）。有重叠 = 同一条理由被重复计数；有遗漏 = 结论强于证据
- **顺序**：同组理由按时间顺序、结构顺序、程度顺序之一排列。三种都套不上 = 这个分组本身不成立
- **归纳组**要求同类项能被一句概括句统摄；**演绎组**要求「大前提 → 小前提 → 结论」三段齐全，缺一段即为断链

## 七、标注标签

全流程（还原 → 报告）统一使用下列四个标签，不得改写为其他措辞：

| 标签 | 含义 |
|------|------|
| 【事实】 | 有出处、可复现验证的陈述 |
| 【推断】 | 由事实推出、尚未被独立验证的判断 |
| 【价值判断】 | 关于「应该如何」的主张，无法用事实真假裁决 |
| 【信息缺口】 | 判定所需的事实本次对话内无法取得 |

标签作用：报告里三类混排时，读者会把【推断】当【事实】用，把【价值判断】当【事实】争。分开标注是让用户看清「哪些能靠查证解决、哪些只能靠取舍决定」的唯一手段。
