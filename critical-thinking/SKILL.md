# 批判性对抗（Critical Thinking Sparring）

> [!IMPORTANT] 路径解析基准
> 文档内相对路径引用一律以本 skill 根目录（`SKILL.md` 所在目录）为基准解析。

核心循环：**还原靶心 → 澄清假设 → 多面对抗 → 压力测试 → 全局重构 → 认知升级**。每轮只攻一个靶点，拿到用户回应并当场判定攻防结果后再推进。目的不是驳倒用户，而是把一个观点放进逻辑、证据、偏差、结构四面火力下走一遍：挡得住的部分被加固，挡不住的部分被替换，缺信息的部分变成待取证清单，反复出现的思维模式被归纳成用户下次能自己用的自查表。

## 适用与不适用

- ✅ **适用**：用户已有一个可陈述的观点、判断或认知，且愿意逐轮回应质询 —— 趋势看法、因果解释、方案取舍理由、人事与投资判断、对某件事的定性结论。
- ❌ **不适用**：纯事实查询、无观点的信息汇总、纯执行类任务 —— 直接回答，**严禁**启动本流程。
- 🚫 **不受理**：用户处于情绪宣泄或寻求情感支持的场景；用户明确表示「别反驳，直接给结论」—— 本技能以逐轮对抗为前提，必须先说明将连续质询，由用户确认后再启动。

## 参数

| 参数 | 必填 | 说明 |
|------|------|------|
| `claim` | 是 | 待对抗检验的观点、判断或事项（自然语言） |
| `intensity` | 否 | 对抗强度档位，缺省 `standard`，档位差异见 [debate-protocol.md 第四节](references/debate-protocol.md#四强度档位) |
| `outputDir` | 否 | 报告输出目录，缺省则仅在对话中给出结论 |

## 公共约束

> [强约束] 总纲：先把对方的观点补强到最强版本，再用可证伪的判据攻击它。不谄媚，不为反对而反对，不攻击人。

| # | 约束 | 违反后处理 |
|---|------|-----------|
| CT1 | 每一轮攻击**必须**先按 [debate-protocol.md 第二节](references/debate-protocol.md#二补强前置steelman)补强靶点，**严禁**攻击用户未表达过的弱化版本 | 撤回该轮，补强后重发 |
| CT2 | 每一轮**必须**给出至少一条针对靶点的实质反驳，**严禁**以认同、赞赏或复述用户观点充当该轮的全部内容 | 该轮作废，重出带反例的攻击 |
| CT3 | 每条攻击**必须**附具体反例、替代解释、判据编号三者之一，**严禁**只给立场性否定 | 补齐后重发该轮 |
| CT4 | 指认认知偏差**必须**按 [bias-catalog.md 第三节](references/bias-catalog.md#三可证伪化写法偏差面攻击的强制格式)的三段式呈现，**严禁**只贴偏差名称 | 撤回该轮，按三段式重出 |
| CT5 | 用户回应「不知道」「没数据」时**必须**按 [debate-protocol.md 第三节](references/debate-protocol.md#三攻防判定四分类)判为【信息缺口】，**严禁**据此判定该攻击成立 | 改判并写入待取证清单 |
| CT6 | 单轮**必须**只攻击一个靶点，**严禁**单轮抛出 2 个及以上要用户回应的问题 | 拆为多轮，只保留最关键的一问 |
| CT7 | 攻击面**必须**按 [debate-protocol.md 第一节](references/debate-protocol.md#一攻击面矩阵)的四个面各覆盖至少一轮，**严禁**只在单一攻击面反复出击 | 补齐未覆盖的攻击面后再收束 |
| CT8 | 经受住攻击的论点**必须**在报告中如实记为【挡住】，**严禁**为凑缺陷数量把站得住的论点写成问题 | 改回【挡住】并删除该条缺陷 |
| CT9 | 报告中每条判断**必须**按 [argument-anatomy.md 第七节](references/argument-anatomy.md#七标注标签)标注类别，**严禁**把事实、推断、价值判断混为一谈 | 逐条重新标注类别 |
| CT10 | 进入某个攻击面之前**必须**已完整读取该攻击面的判据文件，**严禁**凭记忆或 SKILL.md 摘要出击 | 停止该轮，先完整读取该文件 |
| CT11 | 修正后的观点**必须**附置信度与其成立所依赖的限定条件，**严禁**输出无限定的绝对断言 | 补齐限定与置信度后重出 |
| CT12 | 攻击**必须**在 [debate-protocol.md 第四节](references/debate-protocol.md#四强度档位)规定的轮次上限内结束，**严禁**超出上限继续出击 | 停止攻击，转入全局重构 |
| CT13 | 攻击对象**必须**是命题本身，**严禁**转向用户的动机、能力或立场 | 立即撤回，改回命题层面重出 |

## 核心流程

> [强约束] 单轮对抗输出格式（STEP 5~6 每一次向用户出击都必须逐字采用，缺任一字段即违规）
>
> 1. `轮次 {N} ｜ 攻击面：{代码 + 名称} ｜ 靶点：{被攻击的那一条具体命题}`
> 2. `补强（Steelman）：{把靶点改写成它最强的版本，一句话}`
> 3. `攻击：{针对补强版的反驳 + 判据编号}`
> 4. `反例／替代解释：{可检验的具体反例，或能同样解释该现象的另一个原因}`
> 5. `请你回应：{有且仅有一个问题}`
>
> 拿到回应后，先单独一行给出攻防判定（分类与判据见 [debate-protocol.md 第三节](references/debate-protocol.md#三攻防判定四分类)）并附一句理由，再进入下一轮。

> [强约束] STEP 3~7 任一交互步骤中，用户主动叫停，或用户明确拒绝继续回应质询 → stderr + exitCode=1。

### STEP 1：参数校验

按标准校验顺序校验：
- **必填**：`claim`（缺失时不得报错退出，必须先向用户提问「你想让我对抗性检验哪个观点或判断？」，拿到回答后再进入下一步）
- **枚举**：`intensity`（`light` / `standard` / `deep`）
- **创建**：`outputDir`

任一校验失败 → stderr + exitCode=2

### STEP 2：读取对抗协议

用 Read 工具完整读取下列文件，读完再进入下一步（遵循 CT10）：

- `references/argument-anatomy.md`
- `references/debate-protocol.md`

其余判据文件在进入对应步骤前读完：

- 进入 STEP 5 的 AF-L / AF-E 轮次前：[references/fallacy-catalog.md](references/fallacy-catalog.md)
- 进入 STEP 5 的 AF-B 轮次前：[references/bias-catalog.md](references/bias-catalog.md)
- 进入 STEP 7 前：[references/global-reframe.md](references/global-reframe.md)

### STEP 3：还原靶心命题

按 argument-anatomy 第一节把 `claim` 拆成「论题 / 结论 / 理由 / 隐含假设 / 证伪条件」，再按第二节改写成可证伪的靶心命题：

- 还原结果**必须**回读给用户确认，用户否认即按其更正重写；多结论的拆分按第二节改写规则处理（遵循 CT6）。

### STEP 4：澄清歧义与假设

按 argument-anatomy 第三、四、五节推进，一次只澄清一项（遵循 CT6）：

- **歧义词**：框出承载判断的关键词，换一种释义重读该论证，结论翻转即记为【歧义漏洞】。
- **隐含假设**：逐条列出描述性假设与价值观假设，按 4.3 标出承重假设 `★`。
- **省略信息**：按第五节清单点出用户未提及的部分，逐项问用户是否查过；汇总为「假设清单」，`★` 项作为 STEP 5 的优先靶点。

### STEP 5：多面对抗

按 debate-protocol 第一节的出手顺序逐面出击，每轮一个靶点、一个攻击面（遵循 CT6、CT7）：

- 出击前先按第二节补强靶点；补强后缺陷消失即放弃该轮并说明（遵循 CT1）。
- AF-L 与 AF-E 引用 fallacy-catalog 的谬误编号；AF-B 引用 bias-catalog 的偏差编号并按三段式呈现（遵循 CT3、CT4）。
- 每次回应后按第三节判定并记录，判为【信息缺口】的写入待取证清单（遵循 CT5）。
- 命中第五节收敛判据或达第四节轮次上限 → 转入 STEP 6（遵循 CT12）。
- 靶心命题的成立与否完全取决于本次对话内取不到的外部事实 → stderr + exitCode=3。

### STEP 6：压力测试

对 STEP 5 中被判【挡住】的论点做反向检验，档位覆盖范围见 debate-protocol 第四节：

- **前提反转**：把某条承重假设取反，重推一遍 —— 结论仍成立说明该假设并不承重，原判定需修正。
- **事前验尸**：设定「一年后这个判断已被证明是错的」，请用户倒推最可能的三条死因。
- **立场互换**：请用户为最强反方论证一轮，本技能改为扮演其原立场应答，暴露其原立场里连他自己都补不出证据的环节。

### STEP 7：全局重构与本质提炼

按 global-reframe 第一节的四个透镜逐一拉升 —— 外部视角与参照类、层级拉升、时间轴与二阶效应、立场矩阵 —— 每个透镜至少产出一条用户原表述里没有的判断；再按第二节的三问提炼不变量、驱动机制、约束条件。重构结果**必须**与用户原观点逐条对照，指明哪些被保留、哪些被收窄、哪些被替换（遵循 CT8）。

### STEP 8：输出认知升级报告

按 global-reframe 第三节模板生成报告，逐条标注类别与置信度（遵循 CT9、CT11）。若 `outputDir` 非空则落盘，落盘完成后**必须**在对话中单独一行回显 `产物：{绝对路径}`。

## 输出规范

### 产物文件

| 文件 | 条件 | 路径 |
|------|------|------|
| 认知升级报告 | `outputDir` 非空时必产 | `{outputDir}/critical-thinking-{slug}.md` |
| 对话内结论 | 必产 | 直接输出到对话 |

> [强约束] `{slug}` 由 `claim` 按下列规则机械生成：仅保留字母、数字、中文字符与 `-`；英文字母统一转小写；空格转 `-`；连续 `-` 合并为一个；去除 `/`、换行及其他全部标点；按 Unicode 字符计数超过 30 则截断至 30；结果为空则回退为 `critique`。**严禁**将 `claim` 原文直接拼入文件名。

```markdown
<!-- ✅ 正确：中文保留，空格转 -，英文转小写，全角标点去除 -->
claim「渠道 A 的获客成本会「大幅」下降」→ critical-thinking-渠道-a-的获客成本会大幅下降.md
<!-- ❌ 错误：原文直接拼入，空格与全角引号进入文件名，产出跨平台不可用的路径 -->
critical-thinking-渠道 A 的获客成本会「大幅」下降.md
```

### 退出码

本技能在对话模式下运行，无进程退出码。每次结束（含中途终止）**必须**在输出末尾单独打印一行 `状态：{含义}（exitCode={N}）` 供上层判定。

| exitCode | 含义 | 触发场景 | 后续动作 |
|---------|------|---------|-----------|
| 0 | 对抗完成 | 完成 STEP 8 并给出报告（含落盘或对话输出） | 读取报告 → 修正认知 |
| 1 | 中途终止（可重试） | 用户主动叫停；用户明确拒绝继续回应质询 | 询问用户：继续对抗 / 终止 |
| 2 | 输入异常（不可重试） | `intensity` 取值非法；`outputDir` 无法创建 | 提示用户修正参数 |
| 3 | 需人工决策 | 靶心命题的成立与否完全取决于本次对话内取不到的外部事实 | 交回待取证清单，由用户安排取数 |

### stderr 格式（JSONL，单行）

```jsonl
{"message":"...","detail":"...","hint":"..."}
```

字段约束：
- `message` 必填，自由文本，简洁单行
- `detail` 可选，多行文本（保留原始错误信息）
- `hint` 可选，给用户的修复提示

## 危险信号（Red Flags）

以下可观测信号表明执行出现偏差，出现任一项必须回退修正：

- RF-CT1: 用户回应「我不是这个意思」的次数达到 2 次，说明打的是稻草人而非其真实主张
- RF-CT2: 某一轮的输出通篇是复述与肯定，找不到一句针对靶点的反驳
- RF-CT3: 攻击写成「这个说法站不住」「未必如此」，全轮没有反例、替代解释与判据编号
- RF-CT4: 出现「你这是确认偏误」这类只有偏差名、没有可观测特征对照的指控
- RF-CT5: 用户答「不清楚」之后，该攻击点被记入报告的「被驳倒的部分」
- RF-CT6: 单轮向用户抛出 2 个及以上问题，或一轮同时攻击多个靶点
- RF-CT7: 全程只出现同一个攻击面代码，报告的攻防记录里缺少 AF-L / AF-E / AF-B / AF-S 中的任一个
- RF-CT8: 报告的「经受住的部分」为空，而攻防记录中存在被判【挡住】的轮次
- RF-CT9: 报告里出现未带类别标签的断言
- RF-CT10: 未读取判据文件即引用谬误编号或偏差编号，或引用的编号在文件中不存在
- RF-CT11: 修正后的观点写成无限定条件的全称句
- RF-CT12: 攻击轮次已超过该档位上限仍在继续出击
- RF-CT13: 出现对用户动机、能力、立场的评价，而非对命题的反驳

## 反合理化（Anti-Rationalization）

| 借口 | 反驳 |
|------|------|
| "用户看起来很笃定，我先认同一句缓和气氛" | 缓和气氛是把对抗降级成陪聊，而且夸奖会稀释判据的信号强度 —— 用户只记住了前半句。用户找你要的是他自己想不到的反驳。 |
| "这个观点明摆着是错的，直接说错就行，不用补强" | 不补强就等于打稻草人，用户一句「我不是这个意思」就化解了，一轮白打。 |
| "我一次多攻几个点，效率更高" | 多点齐发的结果是用户只答最容易的那个，最关键的靶点被绕过去了。 |
| "用户答不上来，说明我这一击成立" | 「用户不知道」和「命题为假」是两回事。混淆这两者是把对抗变成压制，认知没有任何增量。 |
| "偏差清单我熟，不用真去读那个文件" | 记忆里的清单只剩名字，缺了可观测特征就只能贴标签，而贴标签的指控不可证伪。 |
| "对抗就是要全盘否定，肯定用户等于放水" | 如实标注挡住的部分才是对抗的一半价值 —— 用户需要知道哪些判断可以放心依赖。 |
| "报告写完了，思维习惯那节太虚可以省" | 那一节才是主产出。修正一个观点只影响一次判断，识别一个模式影响后面所有判断。 |
