# 第一性原理分析（First Principles Thinking）

> [!IMPORTANT] 路径解析基准
> 文档内相对路径引用一律以本 skill 根目录（`SKILL.md` 所在目录）为基准解析。

进入「界定问题」步骤之前，**必须**先用 Read 工具读取 [references/inquiry-framework.md](references/inquiry-framework.md) 全文（追问技术、归约判据、量化模板、输出模板）；未读取即开始追问 = 违反 FP8。

核心循环：**界定问题 → 拆解假设 → 归约到第一性真理 → 量化计算 → 重构方案 → 给结论/行动项**。通过逐轮深度追问驱动，每轮只聚焦一个维度，拿到用户回答再推进。

## 适用与不适用

- ✅ **适用**：有明确决策点、且存在"行业惯例可能是错的"空间的问题 —— 成本结构颠覆、方案 A vs B 取舍、可行性上限判断、被长期默认前提卡住的议题。
- ❌ **不适用**：纯事实查询、纯执行类任务、无决策点的信息汇总 —— 直接回答，**严禁**启动本流程。
- 🚫 **不受理**：用户明确要求"快点给结论/别问我" —— 本技能以逐轮追问为前提，必须先说明需要多轮交互，由用户确认后再启动。

## 参数

| 参数 | 必填 | 说明 |
|------|------|------|
| `topic` | 是 | 待分析的问题、决策或议题（自然语言） |
| `outputDir` | 否 | 结论文档输出目录，缺省则仅在对话中给出结论 |

## 公共约束

> [强约束] 总纲：只从可验证的基本真理出发推导，不从类比、惯例、权威意见出发。

| # | 约束 | 违反后处理 |
|---|------|-----------|
| FP1 | 每轮推进**必须**先拿到用户的真实回答，**严禁**替用户臆测事实、编造数字或假定其立场；仅当已向用户明示"这是估算"、给出区间与假设并获其认可后，该估算值方可参与计算 | 停止推进，就地向用户提问获取该事实 |
| FP2 | 每个假设**必须**按 inquiry-framework 1.2 的五连问追问，直至答案落到 inquiry-framework 1.3 收敛判据，**严禁**在"行业惯例""大家都这么做"层面停止 | 对该假设追加一轮"为什么/谁规定的"追问 |
| FP3 | 结论**必须**建立在量化计算或可验证事实之上，**严禁**仅凭定性感觉下结论 | 补充量化步骤或标注为"待验证假设"后重出 |
| FP4 | 输出**必须**明确区分「已验证事实」与「待验证假设」，**严禁**将两者混为一谈 | 逐条重新标注来源与置信度 |
| FP5 | 单轮追问**必须**只提一个问题、只聚焦一个决策维度，**严禁**单轮抛出 2 个及以上问题 | 拆分为多轮，只保留当前最关键的一问 |
| FP6 | 行动项**必须**可执行、有明确主体与可检验标准，**严禁**输出空泛口号 | 补齐主体/动作/检验标准后重出 |
| FP7 | **必须**与「类比基线」做对比并量化差距，**严禁**只给第一性推导结果不给对照 | 补充类比基线及差距计算 |
| FP8 | 进入交互步骤前**必须**已读取 `references/inquiry-framework.md` 全文，追问句式、收敛判据、量化与输出模板一律以该文件为唯一来源，**严禁**凭 SKILL.md 摘要或记忆执行 | 立即停止追问，先完整读取该文件 |
| FP9 | 单个假设的追问**必须**在累计 5 轮内收敛，达上限仍未收敛则标为【待验证假设】并写入「量化缺口」后推进下一步，**严禁**无限追问或自行宣布收敛 | 标注为【待验证假设】后推进下一步 |

## 核心流程

> [强约束] 单轮追问输出格式（交互步骤每一次向用户提问都必须逐字采用，缺任一字段即违规）
>
> 1. `轮次 {N} ｜ 当前步骤：{步骤名} ｜ 本轮锁定：{要锁定的那一件事}`
> 2. `问题：{有且仅有一个问题}`
> 3. `为什么问：{该答案决定推导链的哪一步 + 不答会导致什么推不下去}`
> 4. `期望答案形态：{数值+单位 / 是非 / 枚举选项 / 具体事实来源}`
>
> 拿到回答后，先用一句话复述从回答中提取到的事实并标注【已验证事实】/【待验证假设】，再进入下一轮。

> [强约束] 任一交互步骤（STEP 3~7）中，用户主动叫停，或用户明确表示无法提供继续推导所必需的信息 → stderr + exitCode=1。

### STEP 1：参数校验

按标准校验顺序校验：
- **必填**：`topic`（缺失时不得报错退出，必须先向用户提问「你想用第一性原理分析什么问题/决策？」，拿到回答后再进入下一步）
- **创建**：若 `outputDir` 非空，目录不存在则创建

任一校验失败 → stderr + exitCode=2

### STEP 2：读取追问框架

用 Read 工具完整读取下列文件，读完再进入下一步（遵循 FP8）：

- `references/inquiry-framework.md`

### STEP 3：界定问题

围绕 `topic` 与用户澄清三件事，一次交互聚焦一项（遵循 FP5）：

- **决策/目标**：到底要做什么决策？期望产出什么？
- **成功判据**：什么结果算"成功"？用什么指标衡量？
- **硬约束**：预算、时间、物理边界、不可违反的前提有哪些？

用户回答后，用一句话复述锁定的问题定义并请其确认。

### STEP 4：拆解假设

按 inquiry-framework 1.1 的提问句式，引导用户列出对该问题的所有"想当然"并逐条打问号：

- 对每条假设统一标注：【已验证事实】/【惯例】/【待验证假设】（标签定义见 inquiry-framework 第二节，全流程沿用同一套标签）

产出一张假设清单，标出其中"看似铁律、实为惯例"的高价值拆解目标。

### STEP 5：归约到第一性真理

对 STEP 4 中的高价值假设，逐个持续追问（遵循 FP2、FP9）：

- 每轮只追一个假设，按 inquiry-framework 1.2 的「五连问」**完整**推进：第 4 问（最小单元与各自取值）是 STEP 6 量化的必需输入，第 5 问（是否存在其他路径）是 STEP 7 重构的必需输入，**严禁**省略其中任一问。
- 收敛判据见 inquiry-framework 1.3。未收敛 → 追加一轮，回到本步；同一假设累计 5 轮仍未收敛 → 按 FP9 标注后推进 STEP 6。
- 关键第一性真理的验证需用户之外的角色/系统提供数据、本次对话内无法闭环 → stderr + exitCode=3。

### STEP 6：量化计算

对归约得到的第一性真理配上数字，量化出问题所需的关键量（形态依问题而定：理论上/下限、期望值、可行性阈值、多个候选的对比值等；模板见 inquiry-framework 第三节）：

- 向用户索取或共同估算关键数值；缺数据时明示为估算并给出区间与假设，经用户认可后方可入算（遵循 FP1）。
- 计算第一性推导值与类比基线的对应值，量化两者差距 = 该决策的价值空间（遵循 FP7）。
- 关键量在本次对话内无法取数且无法合理估算 → **严禁**虚构数字，改为输出「量化缺口」清单（缺什么量、单位、可能的取数途径、缺失对结论置信度的影响），并把相关结论标为【待验证假设】。

### STEP 7：重构方案

抛开现有方案，从第一性真理与量化结果重新推导可行路径：

- 提出 1~3 条从底线出发的候选方案。
- 每条标注：所需前提、与类比基线的差距收益、主要风险。

### STEP 8：输出结论

按输出规范生成结论，包含：可参考结论、建议、策略、可执行行动项，并逐条标注【已验证事实】/【待验证假设】及置信度。若 `outputDir` 非空则落盘，落盘完成后**必须**在对话中单独一行回显 `产物：{绝对路径}`。

## 输出规范

### 产物文件

| 文件 | 条件 | 路径 |
|------|------|------|
| 第一性原理分析结论 | `outputDir` 非空时必产 | `{outputDir}/first-principles-{slug}.md` |
| 对话内结论 | 必产 | 直接输出到对话 |

> [强约束] `{slug}` 由 `topic` 按下列规则机械生成：仅保留字母、数字、中文字符与 `-`；英文字母统一转小写；空格转 `-`；连续 `-` 合并为一个；去除 `/`、换行及其他全部标点；按 Unicode 字符计数超过 30 则截断至 30；结果为空则回退为 `analysis`。**严禁**将 `topic` 原文直接拼入文件名。

### 退出码

本技能在对话模式下运行，无进程退出码。每次结束（含中途终止）**必须**在输出末尾单独打印一行 `状态：{含义}（exitCode={N}）` 供上层判定。

| exitCode | 含义 | 触发场景 | 后续动作 |
|---------|------|---------|-----------|
| 0 | 分析完成 | 完成 STEP 8 并给出结论（含落盘或对话输出） | 读取结论 → 决策 |
| 1 | 中途终止（可重试） | 用户主动叫停；用户表示暂时拿不到继续推导所必需的信息 | 询问用户：补充信息重试 / 终止 |
| 2 | 输入异常（不可重试） | `outputDir` 无法创建 | 提示用户修正参数 |
| 3 | 需人工决策 | 关键第一性真理的验证需用户之外的角色/系统提供数据、本次对话内无法闭环 | 列出待取数清单，交回用户安排取数 |

### stderr 格式（JSONL，单行）

```jsonl
{"message":"...","detail":"...","hint":"..."}
```

字段约束：
- `message` 必填，自由文本，简洁单行
- `detail` 可选，多行文本（保留原始错误信息）
- `hint` 可选，给用户的修复提示

## 危险信号（Red Flags）

以下可观测信号表明执行出现偏差，出现任一项必须回退修正：

- RF-FP1: 出现了用户从未提供的具体数字或立场，却被当作既定事实继续推理
- RF-FP2a: 某个假设的最终答案仍是"行业就是这么做的""通常都这样"，未落到可验证事实
- RF-FP2b: 未达 inquiry-framework 1.3 收敛判据的假设被写入「归约后的第一性真理」列
- RF-FP3: 结论中出现"应该会更好""大概率可行"等无量化支撑的断言
- RF-FP4: 事实与假设在结论里混排，读者无法区分哪些已验证
- RF-FP5: 单轮向用户抛出 2 个及以上问题，或一轮提问跨越多个决策维度
- RF-FP6: 行动项写成"提升效率""优化流程"等无主体、无检验标准的口号
- RF-FP7: 只给出第一性推导结果，全程未与现状/惯例/其他候选做对比
- RF-FP8: 未读取 `references/inquiry-framework.md` 即开始向用户追问，或追问句式与该文件不一致
- RF-FP9: 同一假设的追问已超过 5 轮仍在继续

## 反合理化（Anti-Rationalization）

| 借口 | 反驳 |
|------|------|
| "用户没说，但按常识应该是这个数，我先填上加快进度" | 填错一个基数会污染整条推导链。缺数据就问，宁可慢不可假。 |
| "这个假设明显是行业铁律，不用再追问了" | "明显"正是类比思维的伪装。火箭贵也曾是"铁律"，追问才发现只占 2%。 |
| "定性判断已经很清楚了，量化太麻烦可以省" | 没有数字的第一性原理只是换个说法的直觉。差距要能算出来才叫结论。 |
| "事实和假设读者自己能分清，不用逐条标" | 你标注的成本远低于对方据此误决策的成本。区分来源是硬要求。 |
| "一次多问几个问题能省轮次" | 发散提问会让用户答得潦草、互相干扰。聚焦单问的答案质量才撑得起推导。 |
| "追问框架我已经熟了，不用真去读那个文件" | 记忆里的版本永远是旧的、残缺的。收敛判据差一个字，整轮追问就白做。 |
| "用户点头说'对，就是这样'，可以判为已归约了" | 点头不是数据。收敛要落到数值或可复现验证步骤，否则只是把假设换了张标签。 |
