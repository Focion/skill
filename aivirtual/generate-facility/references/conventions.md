# 格式选型与写法约定

---

## 1. 格式选型规则

三种格式各有明确适用面，不是风格偏好。选错的代价是真实的：让 Agent 去改写一个带注释的 YAML，
它会丢注释；把高频追加的流水写成 JSON 数组，它每次都得整文件读写。

| 格式 | 用在 | 为什么 |
|---|---|---|
| **YAML** | `profile/**` 设计态 | 需要行内注释解释字段语义（这是空白模板的主要价值），需要人手改，结构嵌套深 |
| **JSON** | `state/live.json`、`state/usage-digest.json` | 机器整体覆写，无需注释，解析零歧义；说明性文字放 `_meta` / `_comment` 字段 |
| **JSONL** | `state/*.jsonl`、`memory/short-term.jsonl` | 仅追加的事件流：写入是 O(1) 单行 append，读取可只取尾部窗口，不必解析全文 |
| **Markdown** | `MODEL.md`、`memory/POLICY.md`、`memory/long-term/**`、`scenarios/**` | 内容是叙述与判断（剧本、经验、路由说明），表格与标题比嵌套字段更适合承载 |

判定顺序：

1. 需要**仅追加**且会持续增长 → JSONL
2. 由机器整体覆写、不需注释 → JSON
3. 需要注释、需要人手编辑的结构化配置 → YAML
4. 内容是叙述、判断、流程而非字段 → Markdown

不要混用：同一层不要一半 YAML 一半 JSON；不要把 Markdown 表格当结构化数据源（无法校验引用）。

## 2. 待补标记

```yaml
name: ""                    # @fill(human) 对外名称；从挂牌或公告获取
```

- `@fill(human)` — 需人工确认的事实（名称、地址、价格、法定容量）
- `@fill(agent)` — 需运行中观测才知道的（使用规律、高频问法、摩擦点）
- `@fill(generator)` — 生成时应由填充模式写入，若仍留空说明用户描述里没提

整块待补用 HTML 注释包住（Markdown 中）或 `# @fill-block` 起头（YAML 中）。
`scripts/validate.py` 统计 `@fill` 出现次数作为未补项指标。

**空 ≠ 错**：空是待补，引用不上才是错。填充时不要为了"看起来完整"而编造内容——
宁可留空并保留 `@fill`，也不要写一个后续会被当成事实使用的假值。

## 3. 来源与置信度

被推断出来、而非明确声明的值，需要标注来源，否则下游无法区分事实与猜测：

```yaml
- window: "08:00-09:30"
  occupancy_avg: "0.85"
  source: observed          # seed | declared | observed | inferred
  confidence: medium        # high | medium | low
  observed_at: "2026-09-03"
```

| source | 含义 |
|---|---|
| `seed` | 生成器按设施类型预置的行业默认值，未经确认 |
| `declared` | 人明确声明或有公告依据 |
| `observed` | 从 `state/*.jsonl` 统计出来 |
| `inferred` | 由其他字段推断，未经验证 |

只在**可能被误当作事实**的地方标注（观测规律、推断容量、长期记忆条目），不必给每个字段都加。

## 4. 命名与取值

| 项 | 约定 |
|---|---|
| id | `snake_case`，英文，全模型唯一，不含空格与中文 |
| 时间戳 | ISO-8601 带时区：`2026-09-03T14:30:00+08:00` |
| 时长 | `30min` / `2h` / `7d`，带单位 |
| 时刻 | `HH:MM`，24 小时制 |
| 日期区间 | `MM-DD` 表年度重复（季节），`YYYY-MM-DD` 表具体日期 |
| 金额 | 带单位与计费颗粒度：`"2 元/本/天"`，不要写裸数字 |
| 比例 | 阈值等机器比较用小数（`0.8`），对外表述用百分比字符串（`"80%"`） |
| 容量 | 纯数字 + 独立 `unit` 字段 |
| 空值 | 标量 `""`、列表 `[]`、显式无 `null`；不要用 `"无"` / `"N/A"` |
| 枚举 | 全小写英文；候选值写在同行注释里 |

## 5. 写入方式的含义

`manifest.yaml` 中每个文件都声明 `update_mode`，含义固定：

| 模式 | 含义 | 注意 |
|---|---|---|
| `rewrite` | 整体覆写 | 写前先读，保留未识别字段；`state/live.json` 还需递增 `revision` |
| `patch` | 局部修改 | 不动其他区块与注释 |
| `append` | 仅追加 | 历史行不可改写；需要更正时追加一条更正记录并引用原 `event_id` |

`state/live.json` 的 `revision` 是乐观锁：读时记下值，写时校验未变。不匹配说明有并发写入，
应重读后重试而非覆盖。这是多 Agent 共用一个设施模型时唯一的一致性保障点。

---

## 6. 隐私最小化

`state/*.jsonl` 与 `memory/**` 会长期留存，因此：

- 不写入身份证号、手机号、住址、生物特征等可直接识别个人的信息
- 需要跨条目关联时用 `session_id` 或不可逆哈希
- 涉及个人的负面记录只留在 `state/incidents.jsonl`，长期记忆只保留去标识化的模式结论
- 可披露范围在 `profile/protocol.yaml#disclosure` 中声明
