# 场景层的推导方法

场景层回答的是：**遇到具体情境时，这个设施的既定做法是什么。**
`profile/` 里的规则是通用的、静态的；场景剧本是把规则落到特定情境下的判断路径。
两者的区别在于：规则说"不得超时占用"，剧本说"发现超时占用、对方还在使用、后面有人排队时，先做什么后做什么、什么条件下让步"。

---

## 1. 不要逐类型硬编码场景

「场景信息基于不同的设施生成不同」——但如果为每种设施类型手写一份场景清单，
遇到没预设过的类型（自定义设施、虚拟资源）就退化成空白。

所以用**轴 × 类型特征**推导：10 个轴对任何设施都成立，各轴下的具体剧本由该设施的特征决定。

---

## 2. 十个场景轴

| 轴 | 关注 | 推导提问 |
|---|---|---|
| A1 常规服务 | 最高频的顺利路径 | 这个设施每天做最多的一件事是什么？ |
| A2 高峰满载 | 供不应求时的排序与劝导 | 什么资源最先不够？谁该让位？ |
| A3 资源短缺 | 关键资源见底或不可用 | 哪一项一旦缺了服务就停？替代是什么？ |
| A4 违规冲突 | 规则被打破、人与人起争执 | 最常被打破的是哪条规则？争执双方各有什么道理？ |
| A5 故障降级 | 设备或依赖失效但仍需运营 | 断了什么还能开？怎么降级？ |
| A6 应急疏散 | 危及人身安全 | 这里最可能出的人身风险是什么？ |
| A7 特殊时段 | 节假日、包场、改造、临时管控 | 有哪些时段规则完全不同？ |
| A8 跨设施协作 | 转介、联动、上下游 | 办不了时去哪儿？谁依赖我？ |
| A9 越界请求 | 超出本设施权限或能力的要求 | 最常被要求做但不该做的是什么？ |
| A10 长尾特例 | 无障碍、未成年人、外部访客、语言障碍 | 谁最容易被现有流程漏掉？ |

覆盖要求：**A1 / A2 / A4 / A6 / A9 五轴对任何设施都必须有剧本**——
每个设施都有主业、都会挤、都会有人违规、都可能出人身风险、都会被要求做份外事。
其余五轴按设施特征取用；`scenarios/INDEX.md` 会把未覆盖的轴显式列为「建议补充」，让缺口可见。

---

## 3. 按特征选轴

从设施的客观特征推出该重点写哪些轴，而不是凭类型名联想：

| 特征 | 必须补的轴 | 典型剧本 |
|---|---|---|
| 有借还行为 | A3 A4 | 逾期争议、损坏赔偿、丢失认定 |
| 有预约机制 | A2 A4 | 预约冲突、缺席释放、超时占用 |
| 涉及人身风险（水/电/化学/器械/高处） | A6（P0） | 事故急救、危险源处置、疏散 |
| 有食品药品 | A6 A3 | 安全投诉、效期与缺货、过敏忌口 |
| 依赖关键设备或外部系统 | A5 | 故障降级、转人工、退费 |
| 有稀缺固定位（车位/机位/座位/柜位） | A2 A4 | 满位排队、占而不用、抢占 |
| 有门禁或资格限制 | A4 A9 | 资格核验、未授权进入、代办请求 |
| 面向外部公众 | A10 | 无障碍、未成年人、语言障碍、首次到访 |
| 有排期或档期 | A7 | 换场窗口、装台拆台、闭馆布展 |
| 无人值守时段 | A5 A7 | 自助边界、异常无人处置 |
| 虚拟/配额型资源 | A2 A3 | 配额耗尽、长任务抢占、成本超支 |

---

## 4. 剧本的九节结构

`scenarios/_TEMPLATE.md` 是固定骨架。每节都有存在理由，删任何一节都会让剧本变得不可执行：

| 节 | 作用 | 写不好的典型 |
|---|---|---|
| 1 触发条件 | 何时适用 | 「当情况紧急时」——无法判定 |
| 2 判定信号 | 从什么可观测数据认定 | 没有引用具体字段，只有主观描述 |
| 3 处置流程 | 有序步骤 + 依据 + 写入哪个文件 | 只写动作，不写依据与留痕 |
| 4 决策规则 | 取舍标准；优先保住什么、可以牺牲什么 | 缺失——这是剧本最有价值的一节 |
| 5 对外表述要点 | 必须说明什么、不承诺什么、替代方案 | 写成固定话术，导致僵硬复述 |
| 6 升级与转介 | 什么条件交给谁、超时怎么办 | 只写「上报」，不写找谁、多久 |
| 7 记录要求 | 写哪些文件、写什么 | 缺失——事后无从复盘 |
| 8 复盘与沉淀 | 什么条件下整合进长期记忆 | 缺失——经验不累积 |
| 9 已知边界 | 明确不覆盖什么、改用哪个剧本 | 缺失——剧本被误用在不适用情形 |

第 4 节和第 9 节是区分"有用的剧本"和"规则的复述"的关键。
如果第 4 节写不出取舍，说明这个情境没有真正的两难，不值得单独立剧本——合并到 A1 即可。

---

## 5. 优先级

| 级 | 含义 |
|---|---|
| P0 | 涉及人身安全或不可逆损失，必须先写完整 |
| P1 | 高频且有明确损失，优先补 |
| P2 | 常见摩擦，可逐步补 |
| P3 | 低频或影响轻微 |

同时命中多个剧本时的取先顺序：`A6 > A5 > A4 > A3 > A2 > A9 > A7 > A8 > A10 > A1`，
并遵循 `profile/rules.yaml#conflict_resolution` 的裁决链。

---

## 6. 生成时的取舍

首次生成只铺**骨架**，不编造正文：

- 通用五轴（A1/A2/A4/A6/A9）+ 该类型 2–5 个特征剧本，共 8–10 个文件
- 每个剧本填好表头（id / 轴 / 优先级）和九节标题，正文留 `@fill`
- `INDEX.md` 登记全部剧本，并列出未覆盖的轴

填充模式下，若用户描述明确涉及某个情境（如"逾期每天 1 元"），
可在对应剧本里填入已知事实（第 2、3 节），但**不要替使用方编造第 4 节的取舍标准**——
那需要真实运营中的权衡，编出来的会成为错误的依据。
