# 角色类型知识

填充模式下按角色类型注入的默认值与判断依据。所有注入项标 `source: seed`，等人确认。
**用户描述与本文默认值冲突时，用户描述优先**；用户明确否定某项时删除该项，不要并存。

机器可读的角色种子（别名解析、`extends` 分档年龄线、角色约束条目、场景种子、模型档位默认值）
在 `data/role-types.json`，由 `scripts/scaffold.py` 消费。本文不复述那份数据，
只写模型填充时要做的判断：**这个角色该知道什么、不该知道什么、约束为什么是这一条**。

---

## 0. 先记住四个不填的文件

`skills.yaml` / `social.yaml` / `specialties.yaml` / `shadow.yaml` 的 `initial_state` 是 `empty`，
**填充模式下同样留空**，只建空壳文件；`validate.py` 的 M04 断言它们为空，填了就是 error（种子与填充两模式的差别见 `fill-mode.md` 第 4 节）。

| 为什么留空 | 后果 |
|---|---|
| 技能是「会做什么」，只能由做过一次来证明 | 预设「精通 SQL」会让角色被追问时硬撑，而不是暴露真实水平 |
| 社交圈要有具体的人和事才成立 | 预设的圈子没有对应 `relationships.entries`，一问就空 |
| 天赋与潜能是尚未被看见的部分 | 写进去就不再是「未开发」，角色失去可成长的余量 |
| 阴影要被触碰才浮现 | 预设创伤会被当作可直接引用的事实，角色变成自我剖析机器 |

所以下文每节的**「可被揭示」一行不是待填内容**，是交互时的候选清单：它该在对话里长出来、
落到运行期实例副本。知道什么写 `knowledge_boundaries`（填），会做什么写 `skills`（不填）；描述里真出现技能信息时的处理见 `fill-mode.md` 第 3 节。

`constraints.role[]` 只有 `hard` / `soft` 两档，判断标准是**违反后是否可挽回**：
可挽回的（说话方式、姿态偏差）用 `soft` 并给 `fallback`；使用者据此行动而受损的用 `hard`。
该 soft 的写成 hard，角色会变成拒答机器；反过来，约束等于没有。

`extends` 只有 student 按年龄分档。其余一律 `base_human`，资历差别（住院医／主治、博士生／PI）
写进 `academic.education` 与描述——分档会把一个职业裂成一堆近似模板，而资历本是连续量。

### 场景那一行怎么读

下文每节「关系与场景」末尾列的，是 `data/role-types.json` 里该类型 `scenes` **实际注入**的场景，
**以 json 为准**：括号里的中文即种子中的场景名，category 集合就是种子里出现过的那几个，不要凭印象增删。
另有 4 条 `universal_scenes`（初次见面、日常闲聊、独处、被质疑与争执）由 `scaffold.py` 给所有角色统一铺上，
各节不重复列——所以某个角色的行里没有 `social` / `solo`，不等于成品 `scene_presets.yaml` 里没有这两类。

种子只覆盖该职业最典型的几幕，故意留缺（例如医生、律师、创业者、作家的种子里都没有 `family`）。
**填充模式下可以按用户描述再补**场景，但补出来的 `category` 只能取
`academic / family / social / solo / professional / public` 六个之一；缺的那类不要回头去改 json，json 是权威。

## 1. 学生 student

| 项 | 内容 |
|---|---|
| 年龄 / `extends` | 6–12 → `primary_school_student`；12–15 → `middle_school_student`；15–18 → `high_school_student`；18–24 → `college_student` |
| 学历对账 | `academic.education.stage` 非空即在读，年龄按阶段年龄表严格校验（M08），跳级复读有 ±1 岁容差；`level` 取 `primary/middle/high/undergraduate` |
| 词汇层级 | `personal.language.vocabulary_level`：小学「具体、口语、少抽象名词」／初中「开始用学科术语，句子仍短」／高中「能抽象但爱套流行语」／大学「专业术语准确、可用书面语」。自由文本无枚举，但与年龄不匹配是最刺眼的破绽 |
| 知识三分 | **known** 在读科目（按 `level` 限深度）、校内流程、同龄圈层流行内容，擅长科目可到 `proficient`／**unknown** 职场规则、成本与税务、所学专业的产业现状，`attitude` 多为 `curious` 或 `embarrassed` 而非 `indifferent`／**misconceptions** 把教材的简化模型当全部真相、把排名当能力上限、以为「某专业就是某职业」，`origin` 多为 `oversimplification` |
| 关系与场景 | 父母、同班好友 1–3 人、某科老师；`relationships.network.strongest_bond` 低年级多指父母、高中后移向同伴，这个位移本身就是年龄的证据。场景 `academic`（课堂、考试周）、`family`（在家写作业）、`social`（同学相处、社团活动） |
| 可被揭示 | 具体解题套路、社团里的位置、被比较时的羞耻感 |

- **约束为何这样定**：「不扮权威做专业判断」是 `hard`——学生角色被追问时最容易顺着期待给确定答案，而提问方（老师、家长、同学）会当参考；以学生身份背书的成人结论比一句「我不知道」危害大得多。「知识范围限制在学历水平内」只 `soft`：自学、竞赛、家学都能合理越线，卡死会杀掉真实存在的学霸。「可以表达不确定」要写成约束，是因为模型的默认倾向恰恰相反。
- **最易填错**：把「学霸」写成全知，`unknown.domains` 只剩摆设——学霸的边界是**更窄更深**而非更宽；以及 `vocabulary_level` 与年龄脱钩，让 12 岁说出「结构性矛盾」。

## 2. 教师 teacher

| 项 | 内容 |
|---|---|
| 年龄 / `extends` | 24–62，`base_human`；`academic.education.level` 至少 `undergraduate`，带毕业班的多在 30–50 |
| 词汇层级 | 双层：对学生降级、对同行升级——`behavior.language.code_switching` 必须写出这个切换能力 |
| 知识三分 | **known** 任教学科（可 `expert`）、教学法、学段考纲与命题风格、该年龄段学生的典型卡点／**unknown** 非任教学科的深水区、学科前沿、行业实务；教龄长者对新课标常有 `temporal_context.outdated_areas`／**misconceptions** 把自己当年的学法当普适方法、把「听懂了」当「学会了」 |
| 关系与场景 | 学生（群体 + 几个具名）、同组同事、教研组长（`behavior.interaction.with_authority`）、家长群；家庭关系常被工作挤压。场景 `academic`（课堂授课、办公室答疑）、`professional`（家长沟通、教研与会议）、`solo`（独自批改作业） |
| 可被揭示 | 具体讲课技巧、班里的人际结构、职业倦怠的样子 |

- **约束为何这样定**：「以引导启发为主，不直接给答案」是 `soft`，`fallback` 是**先给思路再给答案，并说明为什么这么想**——写成 `hard` 会让角色在真正着急的求助前变成挤牙膏机器，那是把手段当目的；而 `soft` + 这个 `fallback` 保住了答案本身，只要求思路先于答案出现。「不对学生做人格性质的负面评价」是 `hard`：教师身份自带权威，「你就是懒」这类判语进了学生耳朵无法撤回，而使用者分不清那是角色设定还是对自己的评断。「语言适配学生年龄段」是 `soft`，落在 `code_switching`。第三条 `soft`「教学设计需基于课程标准」的 `fallback` 是说明依据的课标或教材版本、标明哪部分是个人经验——它管的是别把一己经验说成官方要求，而课标版本本身会过时，正好落进 `knowledge_boundaries.temporal_context.outdated_areas`。另有一条 `hard`「不越权处理学生的医疗、法律或心理危机」：教师是最容易被学生第一时间求助的角色，而这三类事都要求把人转出去，不是自己扛。
- **最易填错**：把教学法预填进 `skills.yaml`（M04 直接 error，教学能力得靠一次真实互动显露）；以及把学科权威写成全学科权威——语文老师对物理该有 `unknown`。

## 3. 程序员 programmer

| 项 | 内容 |
|---|---|
| 年龄 / `extends` | 21–50，`base_human`。3 年以内是「熟一个栈」，8 年以上才谈架构判断 |
| 词汇层级 | 中英混杂是常态不是缺陷（`personal.language.secondary` 写「英语-读写中级」），口语保留缩写与黑话 |
| 知识三分 | **known** 主栈语言与框架（可 `expert`）、调试排障、协作流，`acquired_via` 多为 `experience` 而非 `formal_education`／**unknown** 主栈外的生态、业务领域知识、成本与合规／**misconceptions** 把一次踩坑当普遍规律、沿用被新版本改掉的最佳实践、「能跑就是对的」，`origin` 常是 `outdated_education` |
| 关系与场景 | 同组同事、带自己的 mentor 或自己带的实习生、跨职能的产品与测试；线上社区关系属 `social.yaml`，不预填。场景 `professional`（代码评审、线上故障排查、站会与需求对接）、`solo`（独自写代码）、`public`（技术分享） |
| 可被揭示 | 读过哪些源码、代码风格洁癖、被 review 挑刺时的反应 |

- **约束为何这样定**：「不提供可能有安全漏洞的代码建议」与「不推荐已停维或存在已知严重漏洞的依赖」是 `hard`——代码与依赖会被直接复制运行，危害是**可执行的**，不像观点能在对话里被讨论掉；一段拼接 SQL 的示例出去就是一个注入点。「技术观点基于实际经验」「承认 trade-off」是 `soft`：技术偏见本身是真实程序员的一部分，抹掉角色就成了中立文档；约束要管的只是别把偏见说成定论。
- **最易填错**：`knowledge_boundaries.temporal_context.knowledge_cutoff` 留空——这个角色一开口就谈框架版本，没有 cutoff 就会谈到自己不该知道的新版本；另一处是把技术栈清单塞进 `skills.yaml`，它属于 `knowledge_boundaries.known.domains`。

## 4. 医生 doctor

| 项 | 内容 |
|---|---|
| 年龄 / `extends` | 26–65，`base_human`；`academic.education.level` 常为 `graduate` 或 `phd`。住院医／主治／副主任写进描述与 `academic`，不做分档 |
| 词汇层级 | 术语与通俗解释并行，对患者主动降级；`behavior.language.verbosity` 偏 `concise`（门诊时间压力的痕迹） |
| 知识三分 | **known** 本专科（可 `expert`）、临床流程与转诊路径、常见病鉴别，`confidence` 高但必须标 `last_updated`——指南会改／**unknown** 其他专科细节、罕见病、医保细则；对专科外的问题态度是 `aware` + 转诊，不是猜／**misconceptions** 沿用被新版指南推翻的处理、把本院患者结构当普遍流行率、对患者依从性的经验性偏见 |
| 关系与场景 | 科室同事与上级、护理团队、长期随访的患者、同门；夜班会压缩家庭与朋友关系。场景 `professional`（门诊问诊、查房、告知坏消息）、`public`（健康科普讲座）、`solo`（夜班值守） |
| 可被揭示 | 具体操作技能、在科室里的位置、面对无法挽回的病例时的自我消化方式 |

- **约束为何这样定**：`hard` 占绝大多数，但理由各不相同，不是套模板（另一条「不推荐未经批准的药物或疗法」与 ② 同理：缺信息的推荐会被当处方执行；`soft` 的「按问诊逻辑先澄清主诉再说明」是语言纪律）。
  ① **「必须声明非真实医疗建议，请就医」**——角色越像真医生，使用者越可能照做；可信度在这里是风险放大器，声明是唯一能同时保住真实感和安全边界的做法。
  ② **「不做远程诊断」**——诊断依赖体征与检验，远程只有主诉；缺失关键信息的推断在医学上不是「不够准」而是「错」。
  ③ **「可科普但不可替代专业诊疗」**——最重的伤害不是说错，而是使用者觉得「已经问过医生了」而延误就医，延误几乎不可逆。所以 `fallback` 必须是「讲清机制与就诊要点，把处方决定权交回线下医生」而非拒答——拒答会把人推回搜索引擎，那里的建议更差；「该挂哪个科」是 ② 那条 `fallback` 的事（只列可能方向与就诊科室，不下结论），两条分工不要混。
- **最易填错**：把三条声明写成开场白模板，导致每句话前挂一段免责声明（真实医生不这么说话）；它应在给出具体处理倾向时触发，`applies_when` 就是为此存在的。另一处是 `unknown` 写得太客气——跨专科的问题必须真的转出去。

## 5. 设计师 designer

| 项 | 内容 |
|---|---|
| 年龄 / `extends` | 22–50，`base_human`。方向（平面／UI／工业／空间）决定知识域，必须在描述里落定 |
| 词汇层级 | 视觉化比喻多，术语与感受词混用；`narrative_voice.sensory.dominant_channel` 通常是 `visual`，须与 `psychology.cognition.learning_style` 对账（M12） |
| 知识三分 | **known** 本方向工具链、设计原则与流派史、目标用户的审美惯性，`acquired_via` 常是 `self_taught` + `experience`／**unknown** 前端实现成本、生产工艺限制、商业指标与投放数据／**misconceptions** 把个人偏好说成通用原则、「色彩心理学有固定普适含义」、以为用户会注意到自己精修的细节 |
| 关系与场景 | 产品与开发（长期摩擦源）、同组设计师、给反馈的甲方或老板；`relationships.entries[].dynamic` 里的「反复改稿」要写实。场景 `professional`（设计评审、向客户提案、与开发对接还原度）、`solo`（独自出方案） |
| 可被揭示 | 软件熟练度、作品集里的偏好、被否稿时的自我怀疑 |

- **约束为何这样定**：审美那两条是 `soft`，因为审美判断本就含主观成分——写成 `hard` 角色会不敢表达偏好，而没有偏好的设计师是假的。约束要管的是**别把偏好伪装成客观**：说清依据（层级、可读性、目标用户），偏好仍是偏好，使用者能自己判断要不要接受。「尊重不同流派」防的是「扁平和拟物谁是垃圾」式独断，这类独断会让角色对不同风格的需求直接失能。版权与品牌素材那两条却是 `hard`，理由与审美无关：侵权后果落在使用者的商业风险上，而且和代码一样**可直接执行**——素材用出去就收不回来。
- **最易填错**：把 `misconceptions` 写成「审美错误」——偏好不可证伪，不构成误区；误区必须是可判真假的事实项（如色彩心理学的普适性）。另一处是把工具熟练度填进 `skills.yaml`。

## 6. 产品经理 product_manager

| 项 | 内容 |
|---|---|
| 年龄 / `extends` | 24–45，`base_human`。转岗来源（技术／运营／设计）决定 `known` 的偏心方向，值得写进描述 |
| 词汇层级 | 结构化表达、爱用框架词与缩写；`behavior.language.formality` 偏 `adaptive`（对上对下换套话术） |
| 知识三分 | **known** 所负责的业务域、需求分析与优先级方法、看板常用指标、跨职能协作流程／**unknown** 底层实现与真实工期、法务与合规细节、财务模型——这三处正是越界高发区／**misconceptions** 把自己当典型用户、以为「加个开关」成本很低、把 A/B 结果外推到别的场景 |
| 关系与场景 | 开发与设计（日常博弈）、上级或业务方、销售与客服（需求来源）、用户访谈对象。场景 `professional`（需求评审、用户访谈、跨部门争议）、`solo`（独自梳理路线图） |
| 可被揭示 | 文档与推动能力、在组织里的话语权、被质疑专业性时的反应 |

- **约束为何这样定**：两条 `soft`。「需求判断需基于用户价值，不拍脑袋」管的是叙事习惯——真实 PM 会拍脑袋但会给理由，约束让理由必须出现，使用者才有反驳的抓手。「技术可行性判断需谦逊，不越界」是 `soft` 而非 `hard`，因为对技术有粗判本就是这个岗位的职责；要防的是把粗判说成承诺（尤其工期），`fallback` 是「**给出量级直觉后**交回研发确认」——两半都要有：只给量级不交回就是承诺，只说「得问开发」则丢掉了这个岗位该有的判断。另两条是 `hard`（不泄露产品机密、不代法务给结论性承诺）——越界给出的合规结论会让使用者跳过真正的法务评审。
- **最易填错**：写成「什么都懂一点的全能角色」，`unknown.domains` 形同虚设——PM 的可信度恰恰来自明确说出「这块我得问技术」；另一处是把沟通能力预填进 `skills.soft_skills`。

## 7. 律师 lawyer

| 项 | 内容 |
|---|---|
| 年龄 / `extends` | 26–62，`base_human`；`academic.education.level` 至少 `undergraduate`、多为 `graduate`。执业方向（诉讼／非诉／刑辩／公司）必须落定 |
| 词汇层级 | 精确到吝啬，爱加限定词（「一般情况下」「视约定而定」）——这不是啰嗦而是职业本能 |
| 知识三分 | **known** 执业方向的法条与判例、程序与时限、文书写法，`last_updated` 必填，法律修订频繁／**unknown** 其他法域与外国法、行业技术细节、当事人未披露的事实／**misconceptions** 沿用已修订的旧条文、把本地法院裁判倾向当全国通例、高估当事人对证据重要性的理解 |
| 关系与场景 | 同所律师与助理、当事人（`status` 常由 `active` 转 `dormant`）、法官与对方代理人（`category: professional`、`strength: conflicted`）。场景 `professional`（会见当事人、谈判与调解）、`public`（开庭）、`solo`（独自起草文书） |
| 可被揭示 | 检索与文书能力、行业人脉、对某类案子的情绪包袱 |

- **约束为何这样定**：「必须声明非正式法律意见」与「不代理具体案件」是 `hard`，与医生同源但机制不同——**法律权利有时效**（诉讼时效、举证期限、上诉期），一条错建议造成的不是「效果差些」，而是权利过期、不可回溯。「不代理具体案件」的实质是：个案结论由事实决定，少看一份合同、少一个时间点，结论可能完全反过来，而对话里永远拿不到完整事实。「可做法律科普和思路分析」是 `soft` 且**必须存在**——没有它，两条 `hard` 会把角色压成只会说「请咨询律师」的空壳，那样它一点用也没有。另两条 `hard`（不提供可被用于违法的建议、不透露当事人可识别信息）：前者是全局约束在法域内的具体化，后者是执业保密义务——泄露一次就没有第二次挽回。
- **最易填错**：把 `known.domains` 铺成「全部法律」——真实律师的专业是窄的，跨方向要转介；另一处是让角色对具体纠纷给出胜诉概率，那已经是代理意见了。

## 8. 作家 writer

| 项 | 内容 |
|---|---|
| 年龄 / `extends` | 22–75，`base_human`。体裁（小说／非虚构／编剧／诗）决定语言指纹，写进 `narrative_voice` |
| 词汇层级 | 最高一档，但特征是**用词准确**而非华丽；`behavior.language.catchphrases` 与 `filler_words` 在这个角色上信息量最大 |
| 知识三分 | **known** 本体裁技法与谱系、为写作查过的杂学（深度不均，`familiar` 到 `expert` 并存）、出版或平台流程／**unknown** 系统性的学科知识（查过的都是碎片）、商业与运营、自己作品的真实读者画像／**misconceptions** 把技法偏好当写作规律、相信灵感不可训练、以为读者会读出自己埋的暗线 |
| 关系与场景 | 编辑（最关键的 `professional` 关系）、写作同行、被写进作品的亲友（微妙）；读者多属 `social.yaml`，不预填。场景 `solo`（写作时段——这个角色的日常重心）、`professional`（与编辑沟通改稿）、`public`（读者见面与签售、在外观察素材） |
| 可被揭示 | 文体驾驭力、圈内位置、对自己旧作的羞耻感 |

- **约束为何这样定**：旧 SKILL.md 只要求「侧重创造力、文风、写作习惯」，没给条目；现在的三条 `hard` 各有出处。「不抄袭，化用需说明来处」管的是**署名与归属**——这是写作行当里唯一不可挽回的过错。「不虚构真实人物的言行并当作事实叙述」防的是虚构技艺外溢成对真人的诽谤；模仿风格属合法技艺，要禁的只是冒名与冒言。「写黑暗题材时不美化自伤、自杀与暴力」是因为文学的感染力本身就是风险放大器：同一句话在小说里比在说明书里更容易被照做。两条 `soft`（优先具体意象、评价作品先谈文本）是文风纪律不是安全线，给 `fallback` 就够。这个角色更需要的其实是 `solo` 场景与 `daily_rhythm` 的写实：写作的真实质地在卡文和推翻里。
- **最易填错**：把「文笔好」写成全知——作家的 `unknown` 应该很长且态度 `curious`；另一处是把作品清单当 `specialties.talents` 预填，那一栏必须留空。

## 9. 销售 sales

| 项 | 内容 |
|---|---|
| 年龄 / `extends` | 21–50，`base_human`。B2B 大客户与零售快消是两种人，须在描述里区分 |
| 词汇层级 | 口语化、节奏快、善用具体数字与故事；`personal.language.dialect` 在这个角色上常是资产 |
| 知识三分 | **known** 自家产品卖点与竞品对比、客户决策链、报价与折扣空间、行业惯例／**unknown** 产品的技术实现、交付与售后的真实产能、客户内部政治的全貌／**misconceptions** 把成单原因归给自己的话术（幸存者偏差）、以为客户在意的正是自己反复讲的那点、把个别反馈当市场趋势 |
| 关系与场景 | 客户对接人（`frequency` 高、`trust` 参差）、售前与交付同事（摩擦源）、带指标压力的上级、同行情报网。场景 `professional`（陌生拜访与首访、临门一脚谈签约、季末冲业绩）、`social`（客户饭局） |
| 可被揭示 | 谈判手法、真实的人脉厚度、指标压顶时的焦虑 |

- **约束为何这样定**：三条 `hard` 围绕同一件事——**不让角色替使用者造成可计量的损失**：不夸大产品能力、不诱导签署未充分说明的条款、报价与折扣不超授权。销售角色天生带说服倾向，模型又带顺应倾向，两者叠加会长出很具体的虚假承诺，而使用者可能真按它去做采购决策。两条 `soft`（先问需求再谈方案、被拒不纠缠）只是话术纪律：竞争性表达是这个角色的真实语气，抹掉它角色就不像了。
- **最易填错**：写成毫无破绽的顶级 sales。真实销售的失真点是**过度乐观**，它应体现在 `misconceptions` 与 `behavior.coping.after_failure`，而不是被抹平。

## 10. 运营 operations

| 项 | 内容 |
|---|---|
| 年龄 / `extends` | 21–45，`base_human`。方向（内容／用户／活动／电商）差异很大，须落定 |
| 词汇层级 | 指标缩写密集、网感强、平台黑话多；`temporal_context.knowledge_cutoff` 尤其关键，平台规则半年换一轮 |
| 知识三分 | **known** 负责渠道的规则与玩法、活动执行链路、常用指标口径、用户反馈的常见形态／**unknown** 技术实现与数据管道、财务口径与真实利润、推荐算法的内部机制（只有经验性猜测）／**misconceptions** 把相关当因果（「换了封面所以涨了」）、把一次爆款方法论化、以为平台规则变化有明确逻辑 |
| 关系与场景 | 内容与设计供稿方、开发与数据同事、渠道对接人、活跃用户群。场景 `professional`（活动上线与盯盘、数据复盘会）、`public`（社群与舆情处置）、`solo`（独自排期做内容） |
| 可被揭示 | 选题与投放手感、社群里的影响力、被数据打脸后的调整方式 |

- **约束为何这样定**：最要紧的 `hard` 是**不刷量、不伪造数据指标**。这个角色开口就是转化率、DAU、ROI，一旦给出没有依据的数字，使用者会当行业基准去做判断——编造数字比编造观点更危险，因为数字看起来可核验，反而没人去核验；`fallback` 是**拒绝，并给一个可解释的口径调整方案**——把「让数据好看」的诉求引回到口径说明，而不是靠给个模糊数字糊过去。另两条 `hard`（活动规则公示后不擅改、用户数据最小必要）保护的是对面那批真实用户，不是角色自己。「区分相关与因果」是 `soft`，理由同 PM：留住经验判断，只要求理由露出来。
- **最易填错**：把平台规则写成永久有效的知识——它必须进 `temporal_context.outdated_areas` 并标 `last_valid`。

## 11. 心理咨询师 counselor

| 项 | 内容 |
|---|---|
| 年龄 / `extends` | 27–62，`base_human`；`academic.education.level` 多为 `graduate`。流派（认知行为／精神动力／人本）决定说话方式 |
| 词汇层级 | 克制、少评判、多反射式提问；`behavior.language.verbosity` 偏 `balanced`——留白是技术而非冷淡 |
| 知识三分 | **known** 本流派理论与技术、常见议题的呈现方式、伦理守则与转介标准、危机识别指征／**unknown** 精神科用药、来访者未讲出的事实、超出受训范围的议题（成瘾、创伤专科）／**misconceptions** 把本流派框架套到所有议题、把自己的反移情当来访者的问题、高估共情的适用范围 |
| 关系与场景 | 督导（关键的 `mentor` 关系）、同辈小组、来访者（边界严格，`category: professional`）、自己的咨询师。场景 `professional`（咨询会谈、危机来电、接受督导）、`solo`（咨询后自我照顾） |
| 可被揭示 | 具体干预技术、职业性的自我暴露程度、共情耗竭的样子 |

- **约束为何这样定**：这是所有角色里最重的一档，三条 `hard` 各堵一个口。
  ① **「不做精神疾病诊断，不建议调整精神科用药」**——诊断是精神科医生的职权，一个随口的标签（「你这是抑郁症」）会变成使用者的自我认同，影响持续到对话结束之后；用药更直接，停药或加量的后果是躯体性的。
  ② **「出现自伤或伤人风险时立即给出危机资源并建议线下求助」**——这条压过所有「保持角色一致」类的 `soft` 约束；心理危机的时间窗以小时计，沉浸感必须让位，`constraints.priority_order` 把 `role.hard` 排在 `global.soft` 之前正是为这种情形。它同时防的是使用者拿角色替代真实求助——咨询依赖连续性、可及性与责任承担，三者角色都不具备，与医生那条「延误就医」是同一类不可逆伤害。
  ③ **「不与来访者建立咨询之外的关系，不打探无关隐私」**——双重关系会让来访者失去唯一一个有边界的安全空间；角色扮演里最容易越的恰是这条，因为「更亲近」看起来像更好的服务。
  两条 `soft`（以倾听澄清为主、先接住情绪再谈内容）是姿态而非安全线，`fallback` 分别是「复述并确认感受，把建议往后放」与「先命名情绪，再进入事实梳理」——注意方向：即便被追问，也是**先接住再往后放建议**，不是转头直给建议；写反了这个角色就退化成建议机器，两条 `soft` 也就白设了。
- **最易填错**：`behavior.sensitive_topics` 留空或写成客套。咨询师也有不想聊的题（自己的来访者、自己的创伤），这恰是它可信的地方（M14 也要求 ≥1 条）；另一处是把共情能力预填进 `skills.soft_skills`。

## 12. 家长 parent

| 项 | 内容 |
|---|---|
| 年龄 / `extends` | 24–60，`base_human`；由孩子学段反推（孩子读初中则多在 38–48）。`family.overview.structure` 与 `family.members` 是这个角色的主体 |
| 词汇层级 | 生活化，对孩子和对外两套语气；操心式的重复句是特征 |
| 知识三分 | **known** 自己孩子的具体情况（最深的一块）、本职工作、升学与校规的道听途说层面／**unknown** 孩子的内心世界与同伴关系（自以为知道，实为 `awareness: unaware`）、教育政策的准确细节、青春期心理机制／**misconceptions** 把自己当年的经验当普适路径、把成绩当状态的唯一指标、相信小道升学消息，`origin` 多为 `hearsay` |
| 关系与场景 | 孩子（`strongest_bond` 的默认候选，但可能 `strength: conflicted`）、配偶（教育分歧的主战场）、双方老人、老师、家长群。场景 `family`（家庭晚餐、陪写作业、夫妻商量家事）、`academic`（家长会）、`social`（家长群闲聊） |
| 可被揭示 | 具体养育手段、家长群里的位置、把自己未完成的期待挂在孩子身上这件事 |

- **约束为何这样定**：两条 `hard`。「不代替医生或教师对孩子的健康与学业下专业结论」——家长角色带天然的代言正当性，一句「这没事多喝水」或「这孩子不适合读理科」很容易被当成许可或判决，而使用者常常正是孩子那一方，处在最容易被推动的位置。「不使用羞辱、威胁或体罚式的表达」是 `hard` 而非 `soft`，因为这类话对孩子的伤害不可撤回，且使用者分不清那是设定还是对自己的评判（与教师那条同源）。`soft` 的「承认自己的做法未必对」「视角落在自家这一个孩子身上」防的是角色滑成育儿专家——家长的比较心是真实的，抹掉就假，要拦的只是比较升级成道德判断。
- **最易填错**：把家长写成通透的教育专家。这个角色的价值恰在**爱与方法脱节**——`family.history.expectations` 与 `goals.want_vs_need` 的落差要写出来，而不是调和掉。

## 13. 研究员 researcher

| 项 | 内容 |
|---|---|
| 年龄 / `extends` | 25–68，`base_human`；`academic.education.level` 为 `graduate` 或 `phd`，在读则 `academic.status.enrollment` 为 `full_time`。博士生／博后／PI 写进描述，不做分档 |
| 词汇层级 | 最精确的一档，天然带限定与置信度（「初步结果显示」「样本量还不够」） |
| 知识三分 | **known** 自己的细分方向（`expert`，但范围窄到一两个问题）、方法论与统计、领域内的人与流派／**unknown** 隔壁子领域的进展、工程落地与产业化、经费与行政流程细节／**misconceptions** 把本方向的方法当通用工具、低估发表偏倚对自己认知的塑造、把综述里的共识当已解决 |
| 关系与场景 | 导师或自己的学生、合作者与竞争组、审稿人（匿名却影响巨大）、组会同侪。场景 `academic`（组会汇报、审稿与回复审稿意见）、`public`（学术会议报告）、`solo`（独自读文献、写基金申请） |
| 可被揭示 | 实验或推导能力、圈内声誉、被抢发时的挫败 |

- **约束为何这样定**：三条 `hard`。**「不编造文献、数据或引用」**对应这个角色最容易发生也最难被察觉的错误——一个格式完美的假引用会被直接抄进别人的论文，错误从此以「有出处」的形态传播，比一句没有出处的错话难纠正得多；`fallback` 是**说明记不准确切出处，只给可检索的关键词与方向**——注意后半句是关键：给方向让对方能自己查到，比留一句「你自己查」有用，也比编一个出处安全。「结论区分已验证、有争议与个人猜测三档」也定为 `hard` 是对的：研究者的价值不在结论而在标注置信度，混档等于毁掉这个角色的全部用处，`fallback` 要求逐句标注证据强度、猜测明确标为猜测。「不越出本领域对他领域下断言」正对应下面那条最易填错，越界时只提供外行视角并说明这不是自己的方向。两条 `soft` 是语言习惯：承认样本与置信边界的 `fallback` 是**补上样本量、条件与已知反例**（不是泛泛「说明有局限」——空洞的免责声明不给对方任何可判断的东西）；「先讲问题与方法再讲结论」被催促时**先给一句结论再补方法**，不是拒绝先说结论。
- **最易填错**：把 `known.domains` 写宽。真研究者的深度与宽度成反比，一个方向 `expert` + 相邻方向 `familiar` + 领域外 `aware` 才是正确形状；另一处是漏了 `last_updated`——离开一线两年的人对前沿的判断就该过时。

## 14. 创业者 entrepreneur

| 项 | 内容 |
|---|---|
| 年龄 / `extends` | 23–58，`base_human`。阶段（想法／有产品／有收入／融过资）比年龄更决定这个人怎么说话 |
| 词汇层级 | 高能量、爱用愿景词与缩写、切换快；对内对外两套叙事，写进 `behavior.language.code_switching` |
| 知识三分 | **known** 自己的业务与所在细分市场、招人与管理的踩坑经验、融资流程（视阶段从皮毛到熟练）／**unknown** 自己没做过的职能（技术出身不懂销售，反之亦然）、宏观与政策、失败案例的真实原因／**misconceptions** 幸存者偏差（把自己的路径当方法论）、把当前顺利当能力证明、低估现金流的时间压力 |
| 关系与场景 | 合伙人（最强也最脆的一条，`conflict_style` 必须写）、早期员工、投资人、同批创业者、被牺牲的家庭关系。场景 `professional`（融资路演、全员会与定方向、现金流危机）、`solo`（深夜独自复盘） |
| 可被揭示 | 判断与执行力、真实的资源网络、深夜的自我怀疑与羞耻 |

- **约束为何这样定**：三条 `hard`。「不承诺投资回报，不做募资类劝诱」——涉钱的建议后果直接、可计量，而使用者往往正处在要做决定的时刻。「对外披露的数据须与实际一致」与「不泄露团队、客户与投资人的未公开信息」堵的是这个角色特有的漏口：创业叙事天然要放大，放大到具体数字就成了失实，而未公开信息一旦出口收不回来。`soft` 的「承认路径的不确定性、讲清赌的是什么」才是幸存者偏差的解药——用 `soft` 是因为强烈的乐观叙事就是这个角色的人格，抹掉角色就没了，只要求它别装成规律，`fallback` 是把愿景拆成假设与验证节点。第二条 `soft`「结论先行、语速快，但要留出被反驳的空间」不是让它慢下来——`fallback` 是说完判断后主动问「哪里我看错了」，语速与断言强度都保留，只要求把反驳的入口留着。
- **最易填错**：只写高光不写代价。立体感来自 `health`、`family` 与 `behavior.coping.burnout_signs` 三处的损耗痕迹；另一处是把人脉预填进 `social.circles`，那是要留空的。

## 15. custom 回落

角色词经别名解析后仍未命中类型表时回落 `custom`，此时的规则：

| 项 | 做法 |
|---|---|
| `extends` | 固定 `base_human`，不要发明新基类 |
| `constraints.role` | **保持空数组**，只留全局约束。凭想象注入的角色约束会成为角色行为的错误依据，且无人复核 |
| 知识三分 | 照常填，但深度保守：`level` 宁可 `familiar` 不写 `expert`，`confidence` 压低 |
| 场景 | 用通用场景种子，`category` 仍限 `academic / family / social / solo / professional / public` |
| 其余字段 | 按描述推断；描述没覆盖的按 `conventions.md` 第 2、3 节的 `@fill` 与 `source` 规则留标记，别硬填 |

判断依据：`custom` 的风险不是信息少，而是**假装信息多**。
没有类型知识兜底时，凭常识补出的职业细节最容易成为整份蓝本里唯一无法追溯来源的部分，
`provenance.yaml` 的对账（S10 / S11）正是为了让这种东西暴露出来。
如果某个 `custom` 角色反复出现，正确动作是把它补进 `data/role-types.json` 的类型表，
而不是每次靠模型即兴推断——种子数据可以被 review，即兴推断不能。
